  T4.1: split ExecuteRayTracingSmokeTest: extract the clean route (lines ~1188-4814

        (PathTraceCleanFrame.cpp); ExecuteDebugViewFrame keeps the monolith
        dispatch. Entry picks one route; no shared 6,000-line body.
  T4.2: collapse requestedDebugMode gates in SceneBuild to two policies
        (production policy = current cleanRtxdiDiSceneBuildRluEmissives behavior;
        debug policy = what the keep-list needs).
  T4.3: prune cvars again (bring-up proofs from D3, dead diagnostics); goal is to
        cut PathTraceCVars.cpp roughly in half.
  T4.4 (RESTIR HYGIENE - key for Enhanced ReSTIR PT upgrades): split the clean-lane
        debug views out of the production shader binaries via compile-time
        permutations. Today the DI initial/temporal wrappers #include the 2,561-line
        sentinel and the view is a RUNTIME uint switch (sentinel:2489-2553 is a
        25-way else-if chain); the production view-16 binary statically carries all
        25 views, temporal_output.hlsli (1,362 LOC viewer), diagnostics.hlsli (616),
        rr_debug.hlsli (318) and the audit/GUI counter plumbing. Because raygen
        occupancy is the measured GI bound, dead branches cost real registers.
        Mechanism (matches existing #define-entry + material-features .cmake
        pattern):
          - compile each clean DI/GI/spatial raygen twice: production permutation
            with CLEAN_DI_VIEW_STATIC=16 (view is a literal; DXC dead-strips other
            branches; debug hlsli includes #if'd out) and a debug permutation that
            keeps the runtime switch unchanged;
          - C++ selects the shader table by view: 16 -> production, else -> debug;
          - temporal-audit readback + GUI snapshot stay debug-permutation-only;
          - resampling math stays in cleanroom_common (view-free) - that is the
            surface where paper upgrades (shift mappings, MIS changes) land.
        Do this AFTER Phase 2/3 so the shader CMake is already minimal.
  T4.5 (optional, last): mechanical rename of the SmokeTest/m_smoke* naming to
        PathTraceFrame naming - huge diff, do only when the tree is otherwise quiet.

Ordering rationale: files that nothing compiles go first (free); mode-56 C++ next
because every branch is explicitly keyed on debugMode==56/restirPTCombinedMode and
is after the production early-return (mechanical, low risk); the monolith strip
only after its wrappers are gone; the structural split last, when the code that
would have to move is already minimal.

Estimated removal: ~35-40k LOC of HLSL (monolith regions, verifier, debug hlsli,
PT lane, dead bridges) plus several thousand lines of C++ and ~150+ cvars.

5. 2026-07-21 VIABILITY REVIEW AND RECENT-FEATURE GUARDRAILS
----------------------------------------------------------------------------------
Verdict: the overall cleanup direction is viable after the corrections above.
The original Phase 1 and wholesale pipeline-removal wording was not viable.

Live-contract corrections proven by the include/call graph:
  - remix_restir_gi/pathtrace_clean_restir_gi.rt.hlsl directly includes
    restir_gi_temporal_reuse.rt.hlsl.
  - that temporal file reaches RAB_GITemporalValidationBridge, which reaches
    RAB_GradientBridge and RAB_TemporalOutputBridge.
  - pathtrace_restir_combined_resolve includes
    pathtrace_restir_local_debug_reservoirs, which reaches the remix_rtxdi
    temporal/spatial reuse files. Those files are legacy, but not dead-on-disk.
  - the clean route calls InitRayTracingSmokeRestirPipeline for live shader kinds;
    remove legacy cases, not the shared function.
  - PathTraceReGIR state is created and consumed before the clean-route early
    return. Keep the module; separate optional debug presentation later.

Last-24-hour feature audit (nine commits, all liquid-pool work):
  - production ownership lives in the retained primary-surface producer,
    cleanroom_rtxdi DI adapters/producers/spatial shader, clean ReSTIR GI shader,
    material-feature ABI/parameters, draw-surface capture, and liquid modifier.
  - PathTraceSmokeReadback contains new clean liquid-pool probe selection and
    reporting. When deleting view-68/69 mode-56 readback, preserve the liquid
    globals, status-buffer readback, probe scan, and printout.
  - PathTraceCVars contains the new default r_pathTracingLiquidPoolMode=3 plus
    liquid debug/page controls. CVar pruning must preserve all three.
  - pathtrace_restir_combined_resolve received routed-rigid liquid support in
    commit b7c30aae. Deleting the defunct mode-56 lane intentionally deletes
    that legacy copy; it must not be mistaken for the production implementation.
  - no cleanup slice may delete or rename shared liquid material ABI fields,
    LiquidPoolInfo constant transport, primary-surface liquid status buffers, or
    the clean DI/GI modifier include chain without a separate feature audit.

Working rule for every deletion slice:
  1. enumerate direct and transitive includers/callers;
  2. distinguish production clean-route use from legacy mode-56 use;
  3. list any symbol/file changed during the preceding 24 hours;
  4. delete only the proven legacy surface;
  5. force affected Vulkan blobs, build, verify mtimes, deploy, runtime-check;
  6. checkpoint the meaningful slice without staging unrelated worktree files.
