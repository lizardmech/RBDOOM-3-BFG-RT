UPT-22: decisive temporal bottleneck ladder
============================================

Status
------

Implemented and Vulkan-build verified on 2026-08-10. Runtime timings are the
acceptance result. This is a destructive profiling view of T0 output, not a
renderer mode and not an estimator experiment.

Purpose
-------

Aggregate Nsight stalls and route counters could show that indirect temporal
was expensive but could not assign its milliseconds among receiver/history
traffic, the first indirect replay, reciprocal cross evaluation, merge work and
final visibility. OpenPBR isolation also changed continuation directions and
therefore could not isolate these dependency chains.

The new cvar selects five separately compiled cumulative T0 shaders:

    r_pathTracingUnifiedPtTemporalBottleneckProbe 0..5

    0   normal production temporal
    1   receiver reprojection, surface search and history load
    2   stage 1 plus history-to-current indirect replay
    3   stage 2 plus previous-best/duplication and reciprocal cross evaluation
    4   stage 3 plus temporal reservoir merge
    5   stage 4 plus final winner visibility

Every nonzero stage writes one digest dword per valid pixel so the compiler
cannot remove computed values. It then republishes the untouched D0 reservoir,
including stage 5. Consequently every probe stage consumes the same previous-
frame D0 event population instead of changing later work by feeding a partial
temporal result back into history. The digest buffer is count-bounded, fully
written by active pixels and never cleared.

Admission gate
--------------

The host clamps the cvar to 0..5 and admits a nonzero stage only with:

    r_pathTracingUnifiedPtFamily 0
    r_pathTracingUnifiedPtBackend 0
    r_pathTracingUnifiedPtCompactReceiver 2
    r_pathTracingUnifiedPtCompactGeometry 1
    r_pathTracingUnifiedPtCompactLights 1
    r_pathTracingUnifiedPtLambertDiagnostic 1
    r_pathTracingUnifiedPtTemporal 1
    r_pathTracingUnifiedPtTemporalIndirect 1
    r_pathTracingUnifiedPtDuplication 1
    r_pathTracingUnifiedPtTemporalEarlyReconnect 0
    r_pathTracingUnifiedPtTemporalRouteDiagnostics 0
    r_pathTracingUnifiedPtSplitInitial 0
    r_pathTracingUnifiedPtDiagnostics 0
    r_pathTracingUnifiedPtShaderProof 6

The temporal pipeline log must print shading=lambert-diagnostic and
bottleneckProbe=N. A missing or zero label means the requested stage was gated
off and the timing is invalid. CompactLights is subordinate to CompactGeometry;
the D0 pipeline must report geometry=compact48 lights=compact64 before any probe
can engage.

SPIR-V proof
------------

The built blobs demonstrate cumulative closure rather than a runtime branch or
dead-code-eliminated experiment:

    stage   bytes     static RayQuery initialization sites   digest binding
      1      71,684                  0                             31
      2     309,912                  1                             31
      3     616,736                  2                             31
      4     639,216                  2                             31
      5     712,112                  4                             31

Stage 2 adds the first replay query. Stage 3 adds the reciprocal replay site.
Stage 4 adds no traversal. Stage 5 adds the two possible final-visibility sites.
The compile-time unreachable-code warnings after each terminal probe return are
expected; normal variants compile with the probe macro explicitly equal to zero.

Capture procedure
-----------------

Use one fixed heavy Doom-level camera, fixed resolution and otherwise identical
cvars. Disable unrelated diagnostics. The preferred measurement route does not
require Nsight:

    r_pathTracingUnifiedPtTemporalGpuTiming 1

The host waits for 16 valid-history warm-up dispatches, records 64 Vulkan
timestamp-query samples around the compute dispatch only, then prints median,
mean, minimum, p90 and maximum milliseconds. It automatically discards the old
batch and rearms when the effective probe mode changes. The timing cvar is off
by default and does not allocate, submit or poll queries while disabled.

For each stage 0 through 5, require the `timing armed probe=N` line, leave the
camera fixed, and wait for the corresponding `temporal GPU timing probe=N`
result before selecting the next stage. The 16-frame warm-up removes the
history-invalid mode-switch frame and PSO/cache startup from the 64-sample
batch. Do not compare image quality: probe stages deliberately show D0-only
output.

Nsight remains useful for instruction/dependency attribution, but its marker
time and capture overhead are no longer required for this ladder. If it is used
as a cross-check, compare its dispatch action rather than barriers surrounding
the marker.

Let the measured temporal times be T1..T5. Attribute work by subtraction:

    receiver/history shell        = T1
    history indirect replay       = T2 - T1
    reciprocal/cross evaluation   = T3 - T2
    merge/duplication remainder    = T4 - T3
    final winner visibility       = T5 - T4

Also record production mode 0 as P. P versus T5 is not an instruction delta:
it measures how much production temporal feedback changes the next frame's
event population compared with the controlled D0-only population. A large
P-T5 difference is itself proof that temporal feedback/route population, rather
than one isolated shader block, owns the instability.

Decision rule
-------------

The largest positive adjacent delta owns the next implementation task. If
T2-T1 dominates, compact/queue the first replay or reduce its traversal work.
If T3-T2 dominates, remove or restructure reciprocal replay/pairwise work. If
T5-T4 dominates, compact winner visibility. If T1 dominates, the bottleneck is
full-screen receiver/history memory and reprojection before any RayQuery. If no
single delta dominates but P is much larger than T5, investigate temporal event
feedback and route amplification rather than shader arithmetic.

First measured result and stage-3 refinement
---------------------------------------------

At 2560x1440, 64-sample dispatch-only medians measured:

    P       13.501 ms
    T1       1.293 ms
    T2       2.261 ms
    T3       8.749 ms
    T4       9.092 ms
    T5      11.546 ms

The resulting costs are 1.293 ms receiver/history, 0.968 ms first replay,
6.488 ms reciprocal/cross evaluation, 0.343 ms merge, 2.454 ms final
visibility and 1.955 ms production-feedback difference. Means reproduce the
same partition. The reciprocal/cross stage therefore owns 56 percent of the
controlled T5 shader and 48 percent of production P; temporal merge is closed
as the next optimization target.

Modes 6 through 11 split that dominant stage without changing modes 1 through
5:

    6   T2 plus previous-best/duplication bookkeeping and BASIC selection
    7   T6 plus current-candidate target at the current receiver
    8   T7 plus direct-light target at the history receiver
    10  T8 plus reciprocal identity, continuation and trace-request construction
    11  T10 plus reciprocal RayQuery and committed-hit facts
    9   T11 plus full geometry-surface decode
    3   T9 plus global post-hit endpoint/light/material/PDF target evaluation

Stage 10 folds every resolved identity, continuation and request field into the
observable digest before the second query. Stage 11 folds every committed-hit
fact into the digest before vertex/index/material loads. Stage 9 folds the
complete decoded hit surface into the digest. None admits a synthetic sample to
the reservoir; every probe republishes untouched D0. Run modes 2, 6, 7 and 8
when reproducing the full stage-3 partition, then run 8, 10, 11, 9 and 3 for the
focused T9 split. Attribute:

    bookkeeping/duplication       = T6 - T2
    current-receiver target       = T7 - T6
    direct cross-receiver target  = T8 - T7
    reciprocal request setup      = T10 - T8
    reciprocal RayQuery           = T11 - T10
    reciprocal surface decode     = T9 - T11
    reciprocal post-hit target    = T3 - T9

Static SPIR-V inspection proves the intended closure:

    mode   bytes     RayQuery initialize/proceed sites   OpLoad count
      2    309,912                  1 / 1                    418
      6    339,132                  1 / 1                    422
      7    393,824                  1 / 1                    506
      8    446,320                  1 / 1                    589
     10    478,256                  1 / 1                    604
     11    502,424                  2 / 2                    664
      9    542,564                  2 / 2                    721
      3    616,736                  2 / 2                    883

Thus mode 10 contains no reciprocal query, mode 11 introduces exactly that
query without surface decode, mode 9 adds decoded geometry without another
ray, and mode 3 adds the remaining post-hit work.

Build and deployment
--------------------

`cmake --build --preset win64-pt-dev-release` from `neo/` passes. The eleven
diagnostic Vulkan SPIR-V artifacts and matching executable are the only required deploy
outputs for this diagnostic. No DX12 shader is compiled.

After the stage-3 refinement, only the four new probe 6--9 blobs and the rebuilt
executable require deployment; the original probes and normal UPT-07 artifacts
remain byte-identical.

After the T9 refinement, only new probes 10 and 11 plus the rebuilt executable
require deployment. Probes 1--9 and normal UPT-07 artifacts remain
byte-identical.
