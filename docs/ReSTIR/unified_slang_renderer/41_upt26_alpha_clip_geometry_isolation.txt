UPT-26: Alpha-clip geometry isolation diagnostic
================================================

Purpose
-------

This is a destructive profiling control for ruling alpha-clipped geometry out
of the remaining UPT D0/T0 cost. It is not an alternate rendering mode and it
must remain default-off.

Control
-------

    r_pathTracingUnifiedPtRemoveAlphaClipSurfaces 0  normal production scene
    r_pathTracingUnifiedPtRemoveAlphaClipSurfaces 1  omit alpha-clip surfaces

The enabled mode removes a whole surface when its material has an authored
alpha-test stage or MC_PERFORATED coverage. It does not turn the material
opaque and does not merely accept/reject an any-hit candidate differently.
The surface is excluded before ray-tracing geometry publication, so its
triangles are absent from the BLAS/TLAS and cannot incur traversal, material,
texture, or alpha-test work.

Coverage and invalidation
-------------------------

The same predicate gates:

    visible static and dynamic draw-surface capture;
    full and portal-selected static scene-universe geometry;
    the draw-surface mirror and skinned capture signature;
    entity-feed rigid candidates;
    portal-resident off-screen rigid candidates;
    the static portal-bucket universe.

Changing the effective value clears static, static-bucket, rigid, dynamic,
skinned and instance-universe caches once. It does not add a per-frame clear.
The console prints the policy transition and periodically reports the number
of visible/static surfaces removed. Missing grates, foliage, lamp masks and
other obvious holes are expected proof that the diagnostic engaged.

Test protocol
-------------

Run the same fixed camera twice after normal PSO warm-up, without Nsight first:

    r_pathTracingUnifiedPtRemoveAlphaClipSurfaces 0
    r_pathTracingUnifiedPtTemporalGpuTiming 0
    r_pathTracingUnifiedPtTemporalGpuTiming 1

then:

    r_pathTracingUnifiedPtRemoveAlphaClipSurfaces 1
    r_pathTracingUnifiedPtTemporalGpuTiming 0
    r_pathTracingUnifiedPtTemporalGpuTiming 1

Wait for the one-time rebuild and temporal-history warm-up after each toggle.
Compare D0 and T0 separately. Restore the cvar to 0 after testing.

Interpretation
--------------

A negligible timing change rules out executed alpha-clip geometry and texture
work as the large remaining cost in that view. It does not measure the static
instruction footprint of alpha support still linked into the shader; a later
shader specialization would be required only if that narrower code-footprint
question becomes material.

Runtime findings and capture caveat, 2026-08-10
------------------------------------------------

The first field pass measured a scene-dependent 3--10 ms improvement when
alpha-clip surfaces were removed. The effect appeared only when indirect modes
were enabled. Characters and monsters were approximately mid-range examples;
their materials contain tiled death/dissolve alpha-test stages, so this
authored-stage diagnostic removes the whole character even while that stage is
inactive. The result is therefore a broad upper bound, not the cost of active
alpha clipping alone.

The strongest case was a floor grate covering substantial screen area but
containing only about 30 visible polygons. Removing it recovered about 10 ms
from indirect work. Polygon count is not the useful predictor: indirect rays
can repeatedly execute candidate material lookup, triangle/UV replay, bindless
coverage sampling and continued traversal across the grate's rejected texels.
Screen coverage, transparent candidate depth and indirect RayQuery count are
the relevant capture variables.

Direct is not a control measurement for this cost. The current direct
visibility route calls Upt04TraceVisibilityRayQuery with alphaClipTraversal
disabled, and direct temporal visibility likewise commits programmable
triangles without evaluating their alpha mask. Indirect continuation,
indirect visibility and temporal replay execute the full alpha-clip evaluator.
Consequently, a grate can have negligible direct timing impact while adding
many milliseconds to indirect. Direct shadows through cutouts remain a later
correctness/performance issue.

For performance captures, leave
r_pathTracingUnifiedPtRemoveAlphaClipSurfaces at 0 unless deliberately
measuring the destructive upper bound. Record whether the camera is
alpha-light or alpha-heavy, especially large grates and character crowds, and
do not compare captures with materially different alpha screen coverage as if
they represented the same workload.

Deferred work
-------------

Opacity micromaps remain the likely production solution for genuine cutouts,
but are deferred behind more consistently expensive work. Runtime-conditional
character dissolve stages also need live opacity classification: shading can
clear their inactive alpha flag while BLAS classification still conservatively
treats the material as permanently programmable.

Before implementing OMM, use a three-step indirect-only probe if attribution
is needed: commit alpha candidates as solid without texture evaluation; force
their geometry hardware-opaque; then remove the geometry. Those deltas isolate
alpha decode/texture work, programmable-candidate overhead and ordinary
geometry cost respectively.

Build proof, 2026-08-10
-----------------------

The prescribed win64-pt-dev-release build passed. ShaderMake reported all
SPIR-V shaders up to date, so no DX12 or Vulkan shader was rebuilt. Deployment
therefore requires only the release executable.
