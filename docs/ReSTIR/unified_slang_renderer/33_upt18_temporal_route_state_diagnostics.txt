UPT-18 Temporal Route-State Diagnostics
=======================================

Status
------

Implemented and build-verified on Vulkan, 2026-08-10. Runtime evidence is
pending. The diagnostic is isolated from production temporal SPIR-V and
defaults off.

Observed trigger
----------------

The UPT-17 static reconnection A/B was about 6 ms slower. More importantly,
with reconnection disabled, captures of the same view differed by as much as
7 ms in indirect temporal after changing analytic-light intensity and moving
through the level. The improvement was delayed and did not repeat as a stable
response to intensity. This invalidates the reconnection timing comparison
until the temporal workload is classified.

Verified mechanism
------------------

Baseline unified temporal has data-dependent work:

1. A replayable indirect history sample executes Upt07ReplayIndirectSample.
2. Under BASIC normalization, when the fresh sample is predicted to win, a
   fresh indirect sample can execute a second replay at the previous receiver
   to obtain currentTargetAtHistory.
3. Direct history takes the cheaper arithmetic shift.
4. Selected event and age are retained in the reservoir. Default maximum age
   is 32; packed age 63 is explicitly the no-expiry stress case.

Identical camera and cvars therefore do not imply identical temporal work
unless reservoir event populations are also equivalent. Motion can replace
that population and alter the number of one- and two-replay lanes.

Analytic intensity is not part of Upt06BuildContentGeneration. Live payload
changes instead use stable identity replay. Analytic payload compatibility
includes color and intensity, so a scale change can make previous-to-current
remaps fail for the changed frame. That can prune light-backed histories and
then allow them to repopulate. It explains a transient timing change; it does
not prove that lower light energy makes equivalent shader work cheaper.

Diagnostic specialization
-------------------------

    r_pathTracingUnifiedPtTemporalRouteDiagnostics 0|1

The enabled form selects separate _route_diag Vulkan blobs for natural or
compact lights and duplication on or off. Binding 30 and aggregate atomics
exist only in those blobs. Normal unified blobs retain 30 bindings and four
static RayQuery sites. Diagnostic blobs retain the same four sites and expose
31 bindings. Early reconnection must be off; if both cvars are requested, the
reconnect specialization remains authoritative.

One-frame-delayed output reports current/history event mix, history replay and
reciprocal replay attempts and results, BASIC choice, merge winner and event,
history age buckets, unsupported/missing history, and visibility fallback.

Focused runtime protocol
------------------------

Use the same view and accepted UPT cvars for every sample.

1. Keep r_pathTracingUnifiedPtTemporalEarlyReconnect 0.
2. In the slow state, enable route diagnostics, collect one complete
   "PathTraceUnifiedPt: temporal route" line, then disable diagnostics before
   an Nsight timing capture.
3. After the unexplained fast transition, repeat the one-line diagnostic and
   disable it before timing.
4. As a controlled reset, toggle temporal off for one rendered frame and back
   on. ExecuteInitial invalidates both page metadata records on this mode
   transition without a full-buffer clear. Compare the first stable timing and
   route line with the slow and fast states.
5. Optionally set maximum age to 1 and perform the same temporal off/on reset.
   This bounds persistence and tests whether variance follows aged indirect
   history.

If temporal time tracks history and reciprocal replay attempts, the next work
is workload shaping or replay compaction. If route counts remain equivalent
while pass time differs by milliseconds, compare GPU clocks, shader hash,
resolution, TLAS instance count and traversal metrics instead.

Do not time the diagnostic blob itself. Its atomics only classify production
work.

Runtime finding: fresh endpoint visibility proof
------------------------------------------------

temptests.txt isolated two independent results in the same mc_underground
view. Reducing maximum history age from 32 to 1 reduced the inferred indirect
RayQuery population from about 3.57 million to 2.00 million per frame. Restoring
age 32 and selecting exact single-tap reprojection left it at about 3.57
million, so the nine-tap receiver search was not the source of the accumulated
endpoint workload.

The age-1 run also exposed a D0/T0 contract mismatch. Fresh D0 continuation-hit
endpoints did not persist VisibilityKnown|VisibilityPassed even though their
closest-hit continuation query is the complete current-frame visibility proof.
When BASIC selected one of those current endpoints, T0 classified it as a
missing-proof indirect winner, failed closed, and republished the raw D0
reservoir. visibilityFallback consequently tracked merge-current selections:
about 424k at age 32 and 877k at age 1.

Upt04PrepareIndirectHitTrials now marks the continuation-hit endpoint known and
passed before reservoir streaming. Secondary NEE retains its separate explicit
visibility query and proof path. No history sample is trusted by this change;
Upt07ReplayIndirectSample must still reconstruct history in the current TLAS.
The static-specialization verifier owns a source contract preventing removal of
the fresh-endpoint proof.

Runtime recheck
---------------

Repeat the age-1 reset test first. Current endpoint selections should no longer
inflate visibilityFallback, while history/reciprocal replay counts should remain
within stochastic variance. Time only the production blob with route diagnostics
disabled. Do not promote age 1 from this experiment; it remains a diagnostic for
history-workload accumulation.

Wall/orb route comparison, 2026-08-10
-------------------------------------

wall.txt and orbs.txt disprove retained temporal population as the cause of
the approximately twofold view-dependent cost in the small PBR-orb test map.
Both 2560x1440 captures execute essentially the same work count:

    D0 continuation rays             3,515,211 wall   3,510,917 orbs
    D0 visibility rays               7,194,668 wall   7,046,825 orbs
    T0 history replay attempts         about 457k       about 455k
    T0 reciprocal replay attempts      about 154k       about 149k

The topology of committed continuation hits changes instead. Rigid hits rise
from 14,882 to 463,694. Secondary missing-fallback material evaluations rise
from 8,026 to 266,620; material rejection rises from 602 to 95,336; PDF/ray
rejection rises from 117 to 23,066; and secondary visibility occlusion rises
from 7,220 to 217,649. The timing change therefore follows rigid geometry and
its candidate/material path, not temporal age, history search, light selection
or a larger ray population. See document 34 for the downstream TLAS-opacity
gap exposed by this comparison.

Split-continuation Nsight result, 2026-08-10
--------------------------------------------

orbssplitcontinue.txt proves that the strict continuation split was admitted:
compact32 receiver, compact48 geometry, compact64 lights and
continuation=split-hit32. The two latest matched captures are:

    RBDoom3BFG_2026_08_10_12_19_26.ngfx-gputrace   orb view
    RBDoom3BFG_2026_08_10_12_19_33.ngfx-gputrace   wall view

Nsight reports:

                                      wall       orbs       delta
    frame                             14.92 ms   18.46 ms   +3.54 ms
    C0 continuation trace             0.28 ms    0.80 ms   +0.52 ms
    D0 continuation shade             6.64 ms    6.92 ms   +0.28 ms
    T0 temporal indirect enabled      4.79 ms    8.23 ms   +3.44 ms

C0 therefore proves a real 2.86x geometry-dependent traversal change, but the
isolated primary-continuation cost explains only a small part of the total
marker swing. D0 shading remains within four percent. T0 owns about 81 percent
of the C0+D0+T0 marker delta.

The selected wall T0 profile reports 14.2 active threads/warp, 44.5 percent
coherence, 23.1 percent compute warp occupancy, 54.62 percent RTCORE input
dependency and 35.53 percent global-load input dependency. The matched orb T0
keeps the same static instruction footprint and similar warp behavior; it does
not expose a new candidate-count or arithmetic loop. The cost is the existing
indirect replay RayQuery work becoming more expensive for the visible rigid
geometry.

Source audit matches the profile. Upt07ReplayIndirectSample executes one
continuation query. T0 invokes it once for history-to-current replay and may
invoke it again for the current-at-history reciprocal target, then executes
one winner-only visibility query. The compiled contract remains bounded to
four indirect replay RayQuery sites. Document 35 owns the next bounded step:
compact only pixels that require those replay routes instead of making the
full-screen temporal kernel carry their divergent traversal state.
