PART 1 - ROOT CAUSE
===================

The single-sentence version
---------------------------

The plan treats "unified DI/GI" as a random draw between a direct technique and
an indirect technique. The paper treats it as tracing both and letting
resampling choose. Candidates are cheap; rays are what cost. UPT-04 conflated
"one candidate" with "bounded ray count" and therefore deleted the mechanism
that makes unification work.

What the paper actually specifies (Section 6.1, page 13:10)
-----------------------------------------------------------

Quoted:

    "Lin et al. [2022] start by initially sampling a path tree by emanating NEE
    rays from BSDF-sampled vertices [x2, ..., xk] where k is limited by the
    maximum allowed bounces. Initial resampling selects and stores a single
    path in the reservoir, i.e. xbar = [x0, x1, x2, ..., xk] with a single
    NEE/BSDF ray connecting to a light at xk (see Section 2.3) with k <= 3
    originally. Direct light can be handled by simply tracing another NEE ray
    from x1 when generating the path tree, and giving the (unified) initial
    resampling a chance to select a shorter direct lighting path (k = 2) from
    the tree. The selected path is thus sampled from the full path space."

Therefore:

    the NEE ray at x1 is traced IN ADDITION TO the BSDF continuation,
        not instead of it;
    the tree yields several candidate paths per pixel, so initial M > 1;
    selection among them is RIS weighted by the target function p-hat,
        not a uniform pre-draw over techniques;
    every candidate is a complete path in the full path space, carrying
        whatever direct and indirect radiance that path gathered.

What UPT-04 implements instead
------------------------------

    neo/shaders/slang_upt04/upt04_initial_shared.slang:85-95
        familyPdf = 1/familyCount, familyOrdinal from one white hash,
        then chooseDirect ? PrepareDirectTrial : PrepareIndirectTrial.
        A blind uniform draw between techniques before anything is evaluated.

    neo/shaders/slang_upt04/upt04_transport_initial_bounded.slang:30-48
        Upt04AdmitDirectVisibility and Upt04AdmitIndirectContinuation share
        the precondition stage == kUpt04TransportInitial &&
        continuationRays == 0 && visibilityRays == 0. Whichever fires first
        advances the stage and permanently locks the other out. XOR is
        enforced structurally, not by policy.

    12_upt04_initial_sampler_admission.txt
        "This admits one logical candidate and therefore M = 1"
        "There is no branch where both a direct-family visibility ray and an
        indirect continuation execute for the same receiver."
        Stop condition: "a receiver can emit more than one continuation or one
        visibility ray" - this forbids the second visibility ray that the
        correct design requires.

    03_unified_reservoir_contract.txt:161-178
        "'Unified' means the selected sample and normalization belong to one
        proposal mixture ... The direct/global mixture probabilities must sum
        to one over enabled families."
        This is where the drift starts. README decision 3 is correct - it is a
        statement about the reservoir ABI (one record type, not two). Doc 03
        reinterpreted it as one technique draw, and doc 12 implemented that.

Consequence of M = 1
--------------------

With a single candidate, RIS degenerates algebraically:

    W = (1 / p-hat(x)) * (p-hat(x) / p(x)) = 1 / p(x)

The target function cancels exactly. The final estimate is f(x)/p(x), i.e.
plain importance sampling. Any target function - correct, wrong, or constant -
produces an identical image. UPT-04 therefore cannot exercise p-hat at all, and
the paper's own conclusion is that "overall quality is bounded by the
effectiveness of initial sampling."


PART 2 - PAPER REFERENCE
========================

Notation used throughout
------------------------

    xbar        a path [x0, x1, ..., xk]; x0 = sensor, x1 = primary hit
    k           path length (number of vertices after x0)
    F(xbar)     path contribution: BSDF, geometry, sensor and emitter terms
    p-hat       target function (scalar; usually luminance of F, see 6.3)
    p           source PDF the candidate was actually drawn from
    W           unbiased contribution weight (UCW), E[W | Y] = 1 / p(Y)
    c           confidence weight (originally "effective sample count", M)
    m_i         resampling MIS weight
    T           shift mapping, y = T(x)
    |dT/dx|     Jacobian determinant of the shift
    ubar        primary sample space (PSS) coordinates, a random number vector
    tau         technique index, tau in {1, 2}: 1 = NEE, 2 = BSDF continuation

2.1 RIS (paper Section 2.1, page 13:2) - VERIFIED
--------------------------------------------------

Draw M i.i.d. candidates x_i ~ p. Compute resampling weights:

    w_i = (1/M) * p-hat(x_i) / p(x_i)

Select Y from {x_i} with probability proportional to w_i. As M -> infinity, Y's
distribution converges to p-bar = p-hat / integral(p-hat).

The unbiased contribution weight of the selection is:

    W_Y = (1 / p-hat(Y)) * sum_{i=1..M} w_i

and F(Y) * W_Y unbiasedly estimates integral(F). W_Y estimates 1/p(Y).

Talbot et al. construct p-hat by dropping the visibility term. The paper follows
this for NEE (see 6.1 below): visibility is excluded from the target function
and tested only for the selected light.

2.2 GRIS resampling weight (paper Equation 1, page 13:3) - CHECK-PDF
---------------------------------------------------------------------

Candidates may come from different domains and are mapped into the target
domain by bijective shift mappings T_i. With y_i = T_i(x_i):

    w_i = m_i(y_i) * p-hat(y_i) * W_i * |dT_i/dx_i|

and the output is sampled proportionally to w_i. Here W_i are unbiased
contribution weights from prior RIS/GRIS passes, and m_i are resampling MIS
weights that normalize coverage of the target domain.

Unbiasedness requires including a canonical sample that fully covers the
support of p-hat among the GRIS inputs. In temporal/spatial reuse the current
pixel's own reservoir is that canonical sample.

2.3 Reservoir (paper Section 2.2, page 13:3) - VERIFIED
--------------------------------------------------------

A reservoir is the tuple (Y, W_Y, c):

    Y     the selected sample
    W_Y   its unbiased contribution weight
    c     confidence weight, used to weight domains/techniques in resampling
          MIS

Initial sampling initialises the reservoir with c = 1 via weighted reservoir
sampling (Chao 1982 streaming form). Temporal reuse gives:

    c_new = min(c_cap, c_temporal) + 1

with the paper's default c_cap = 20. Spatial reuse sums the confidence weights
of all accepted neighbours. Paper defaults for spatial: 3 random neighbours in
a 30-pixel radius.

Note for our codec: "confidence weight" is the field UPT-02/03 call effective M.
It is not a count of rays and not a count of candidates evaluated; it is the
resampling MIS bookkeeping term.

2.4 Path space, lobes and the technique index (supplemental Section 1)
-----------------------------------------------------------------------

ReSTIR PT evaluates a single BSDF lobe per vertex, so paths carry a lobe
sequence and the integrand is split across lobe combinations. NEE at each vertex
is performed with all lobes enabled. The NEE sample at the final vertex xk is
encoded by lobe index 0.

A technique index tau in {1, 2} is attached to each path to record whether the
final vertex was reached by NEE (tau = 1) or by a BSDF-sampled continuation
(tau = 2). This is mandatory, not optional bookkeeping: without it the same
geometric path can be produced by two techniques and MIS cannot be applied.

MIS weight between techniques (supplemental Section 1) - CHECK-PDF:

    m_1(xbar) = c_1(xbar) / (c_1(xbar) + c_2(xbar))
    m_2(xbar) = c_2(xbar) / (c_1(xbar) + c_2(xbar))

where c_1 and c_2 are the NEE and BSDF light-sampling strategy PDFs for the same
path. This is a balance heuristic over the two techniques.

PSS parameterisation: the path tracer maps a random sequence ubar into a path
via xbar = W_{k,tau}(ubar), and the integrand becomes

    f(ubar) = m_tau(xbar) * F(xbar) / p(xbar)

integrated over the unit hypercube. For paths produced directly by the path
tracer the PSS source PDF is p(ubar) = 1.

2.5 Hybrid shift and reconnection (paper Section 2.3, page 13:3-13:4)
----------------------------------------------------------------------

Not required for D0, but the reservoir ABI must be able to carry it, so record
it here.

Reconnection is postponed until a vertex pair satisfies two criteria; until then
the shifted path is retraced by replaying the same random numbers. ReSTIR PT
precomputes a reconnection vertex on the base path by finding the first pair
(x_{j-1}, x_j) satisfying:

    roughness:  min(alpha_{j-1}, alpha_j) >= alpha_min
                (alpha from the path's sampled lobes, lobe-specific)
    distance:   || x_j - x_{j-1} || >= d_min
                (avoids geometric singularities)

This predetermines the replayed path length. Shift invertibility is checked when
connecting from y_{j-1} to x_j.

Jacobian (paper Equation 2, supplemental Equation 4) - CHECK-PDF:

The hybrid-shift PSS Jacobian is a ratio of directional sampling PDFs and
single-sided geometry terms at the reconnection vertex:

    |dubar_from / dubar_to|
        = [ p_{j-1}^to(omega_{j-1}^to) * G(y_{j-1} -> x_j) * p_j^to(omega_j) ]
        / [ p_{j-1}^from(omega_{j-1}^from) * G(x_{j-1} -> x_j) * p_j^from(omega_j) ]

with the single-sided geometry term G(x -> y) = cos(theta) / ||x - y||^2, theta
being the angle between the connecting direction and the normal at the origin
vertex.

Two facts matter for our ABI:

    the Jacobian is purely the result of reconnection;
    random replay is an identity shift in PSS and therefore has Jacobian 1.

Confirm exact index placement against the PDF before implementing; the extracted
text lost superscripts.

2.6 Unified DI+GI initial sampling (paper Section 6.1) - the core change
-------------------------------------------------------------------------

Algorithm:

    1. From the primary hit x1, trace an NEE ray. This produces a candidate
       path of length k = 2 with tau = 1.
    2. BSDF-sample at x1 and trace a continuation ray to x2.
       - miss: environment path, k = 2, tau = 2
       - emissive hit: endpoint-emission path, k = 2, tau = 2
       - opaque hit: continue
    3. From x2, trace an NEE ray. Candidate path k = 3, tau = 1.
    4. Repeat 2-3 up to k_max (paper uses k <= 3, i.e. NEE at x1, x2 and x3).
    5. Stream every candidate through ONE reservoir with RIS. The reservoir
       initialises with c = 1 regardless of how many candidates were streamed.
    6. Store the single selected path.

Quality mechanism, quoted:

    "Somewhat surprisingly, it also improves quality as direct lighting now
    benefits from ReSTIR PT's built-in shift mapping (especially on glossy
    highlights)."

Supplemental Figure 4 attributes the gain specifically to "hybrid shift and
pairwise MIS". Both are reuse machinery. The quality benefit of unification is
therefore NOT observable in a no-reuse renderer - see Part 4.

Many-light NEE, quoted:

    "For scenes with many lights, we optionally apply RIS when generating NEE
    samples at x1. As in ReSTIR DI, visibility is excluded from the target
    function and tested only for the selected light. We reuse the presampled
    light-tile scheme from Wyman and Panteleev [2021] to improve cache
    coherence: each frame precomputes 128 tiles with 1024 lights, from which
    each 8 x 8 screen tile draws a light tile to generate candidates per
    bounce."

This matters for Doom 3 map light counts and matters more once emissive
surfaces become mesh lights.

2.7 MIS and UCW under RIS-based NEE (supplemental Section 5) - CHECK-PDF
--------------------------------------------------------------------------

When NEE uses RIS with M > 1 light candidates, two things change.

MIS weight becomes the multi-sample form, using the light sampling source PDF
p_1 and assuming RIS approximates fully evaluating all M lights:

    m_1(xbar) = c_1(xbar) / (c_1(xbar) + c_2(xbar))

(as in 2.4, but c_1 now derived from the light-sampling source PDF rather than
an exactly known NEE PDF).

PSS treatment: the RIS process is treated as a black box. The PSS definition
still assumes a single NEE sample with a known PDF, so the integrand is
unchanged at m_1(xbar) * F(xbar) / p_1(xbar). The effect of RIS is folded into
the UCW instead. For the selected NEE sample:

    W = W_RIS * p_1(tau(ubar))

where tau(ubar) are the hypothetical random numbers that would have produced the
same light sample under the original single-sample NEE procedure, W_RIS is the
path-space UCW from the RIS process (area measure, as in ReSTIR DI), and
p_1(tau(ubar)) is also the Jacobian converting between parameterisations.

Sanity check stated in the paper: original single-sample NEE has
W(ubar) = 1 / p_1(tau(ubar)), which cancels the Jacobian to yield 1.

Getting this wrong produces a plausible image with wrong energy. Implement the
sanity check as a test: with RIS candidate count 1, the unified path must
produce bit-identical output to plain single-sample NEE.

UPT indirect implementation note, 2026-08-08
---------------------------------------------

Only the following conclusions are requirements for the first unified
one-continuation implementation:

    * For M NEE RIS trials, the NEE side of the balance heuristic uses the
      multi-sample source density. UPT's typed trial schedule may express this
      as M times the normalized per-draw mixture density because each domain
      PDF already includes its trial fraction. Preserve the analytic/emissive
      stratification rather than replacing it with homogeneous random draws.

    * Keep the bare physical NEE source density separate from UPT's existing
      proposal-parity source PDF. The latter may contain the technique MIS
      transform and is not automatically the p_1 used by the paper's
      W_PSS = W_RIS * p_1 conversion.

    * Forward light sampling and reverse emissive-hit evaluation must describe
      the same density. For emissives this includes the current power-CDF
      identity probability, typed-domain trial fraction, triangle-region
      density, and area/solid-angle conversion. The present reverse uniform
      1/lightCount approximation is not sufficient.

    * The emissive reverse hash must use the host builder's logical power-of-two
      capacity, not StructuredBuffer.GetDimensions(). The physical dimension
      remains only an OOB guard. Unified/indirect execution must remain
      fail-closed when the host marks the lookup inexact.

    * Continuation and secondary visibility rays use the accepted Doom direct
      ray-offset, t-range, and selected-emissive self-ignore conventions. Do
      not invent a second offset policy in the indirect module.

    * The initial slice remains opaque, one continuation, one shared reservoir,
      and within the existing D0 ray/work ceiling. Environment misses remain an
      explicit zero-contribution unavailable domain. Transmission/glass,
      environment reconnection, multiple bounces, and indirect temporal or
      spatial reuse remain later work.

    * New diagnostics must expand the counter layout and shift the existing
      probe bases/readback offsets coherently. In the implemented layout words
      0 through 106 are counters, words 107 through 122 are the initial
      reservoir probe, the D0 probe begins at word 123, and the C0 continuation
      probe begins at word 139. Distinguish continuation
      miss/hit, geometry/material rejection, endpoint emission, reverse lookup
      miss versus zero reverse PDF, secondary-light rejection, secondary
      visibility/self-hit, and final selected event family.

The following are deliberately test-resolved gates rather than frozen design
claims:

    * Derive or experimentally validate the exact UCW conversion through UPT's
      proposal-parity target/source transform. Candidate count one, previous-
      best off, must be output-bit-identical to plain NEE; do not require an
      unproven intermediate scalar to equal one.

    * Compare NEE-only, BSDF-endpoint-only, and combined modes by converged mean
      energy, not sample equality. Use these modes to expose wrong reverse PDFs
      or double counting.

    * Establish the no-history estimator with D0 previous-best disabled first.
      Re-enable previous-best only after the base estimator is correct, then
      validate its mass/count and duplicate-rejection interaction empirically.

    * Do not widen the compact reservoir for a lobe-index sequence until replay
      reconstruction has been audited. A stored/reconstructible lobe sequence
      is a hard gate before indirect temporal/spatial shifting, not necessarily
      before the no-reuse one-continuation slice.

Initial one-continuation implementation checkpoint, 2026-08-08
---------------------------------------------------------------

The first no-reuse unified D0/R0 slice is implemented. This is a build-verified
checkpoint, not runtime image or energy acceptance.

    * The host reverse-emissive table is 20 bytes per entry and publishes the
      exact current conditional identity probability derived from the current
      power CDF. Its hash mask uses the logical power-of-two capacity; physical
      GetDimensions is only a stride/OOB guard. Buffer reuse now also requires
      an exact structured stride, preventing a live 16-byte allocation from
      being reused for the widened table. ABI version 8 fails closed when the
      lookup is missing, stale, inexact, malformed, or zero-density.

    * Forward and reverse emissive densities use the same typed-domain trial
      fraction, current identity probability, replayed triangle-region density,
      and area-to-solid-angle conversion. Multi-sample direct/secondary NEE MIS
      uses the generalized sum n_j p_j, not the density of one CDF draw.

    * Endpoint and secondary-NEE candidates enter the outer path-tree stream as
      complete PSS estimators. The sampled continuation throughput already
      contains 1 / p_bsdf; therefore the outer proposal value is one while the
      physical p_bsdf (and p_nee for secondary NEE) remains available for MIS
      and diagnostics. This prevents applying the primary inverse BSDF density
      twice.

    * The path-tree reservoir mass is additive across available event families
      and publishes confidence c = 1. It is not divided by the number of event
      families. Direct-only retains its accepted effective M = 1 behavior.

    * Continuation and secondary visibility use the accepted Doom ray offset,
      finite t range, material/lobe mask, and emissive self-ignore convention.
      The implementation adds no extra dispatch, reservoir page, per-frame
      clear, or ray beyond the existing bounded one-continuation plus selected
      secondary-visibility ceiling. RayQuery remains the default backend.

    * Diagnostics are expanded from 69 to 107 counters. They identify
      continuation miss/hit, geometry failure, endpoint emission zero/positive,
      reverse lookup failure/zero/positive, secondary selection/material/PDF-
      ray failure, endpoint/secondary positive candidates, visibility pass,
      occlusion/self-hit, final indirect selection, secondary material
      interpretation, and per-route continuation hit/decode results. Probe
      bases moved to words 107, 123, and 139 coherently in shader and host
      readback.

Verification passed with cmake --build --preset win64-pt-dev-release from
neo/. Vulkan Slang reflection, backend closure, geometry/material closure,
compact32, proposal-parity, direct/indirect/unified specialization,
repeatability, and UPT-07/08/09 checks all passed. No DX12 shader compilation

Runtime acceptance must start with D0 previous-best, temporal, and spatial all
disabled. Compare direct-only and unified first; use indirect-only plus the new

First runtime correction, 2026-08-08
------------------------------------

The first unified image produced basic indirect lighting but visibly recreated
the recently fixed disappearing-emissive and phantom-emissive symptoms. Direct
D0 still used the accepted exact current power-CDF publication. The new
secondary-NEE path did not: it called Upt04SelectUniformLocalLight over the
complete emissive manager range. That bypass diluted currently sampleable
emitters and could select portal-ineligible records deliberately absent from
the current weighted publication.

The correction keeps one secondary proposal but draws its type according to
the accepted D0 typed trial schedule and draws an emissive identity from the
same logical-count current power CDF. It adds no candidate, ray, dispatch,
history dependency, or fallback admission. The selector lives in a minimal
shared module so direct and indirect cannot diverge on logical CDF count or
identity validation.

Indirect-only now legitimately exposes CDF binding 25 and exactly 25
descriptors, up from 24. Its trace ceiling remains two sites and it exposes no
previous/history binding. The focused UPT-04 artifact target and the complete
win64-pt-dev-release preset both pass. Twenty-three rebuilt Vulkan UPT-04 blobs
were deployed; the executable was unchanged. Runtime retest is pending, so this
is a verified source/build correction rather than visual acceptance.

Second runtime finding: secondary NEE required inner RIS
--------------------------------------------------------

The post-CDF-correction capture gi.txt was recorded in indirect-only family 2
at 2560 x 1440 with previous-best, temporal, spatial, and duplication disabled.
It proved that the remaining visual disappearance was not primarily reverse
remapping or replay:

    valid receivers                                  3,686,400
    continuation geometry hits                       3,530,606
    endpoint-emission positive samples                   7,913
    reverse lookup failure / positive PDF             1,911 / 6,002
    secondary selection/material/PDF-ray rejection  2,074,722 / 396,523 /
                                                     1,015,645
    secondary visibility attempts / passed             4,846 / 390
    canonical empty reservoirs                       3,678,098

The one-draw secondary sampler interpreted D0's 32 analytic plus configured
emissive trial counts as a random domain mixture. With one configured emissive
trial, only about one draw in 33 attempted the emissive domain; after material
and visibility rejection only 390 secondary samples survived the full frame.
This explains why a small set of dominant/easy emitters appeared stable while
most sources appeared ignored. Changing uniform versus power-CDF identity could
not materially change that candidate-rate defect.

The secondary vertex now evaluates the same fixed, bounded D0 typed candidate
schedule through an inner RIS. Each proposal uses its bare light-selection
times solid-angle source PDF; the winner uses weightSum / candidateCount and is
converted through winner target into one complete PSS estimator before entering
the outer path-tree reservoir. Invalid and zero-target trials remain in the
fixed denominator but are never selectable. Visibility is traced only for the
winner.

Random keys now keep path vertex 1 and candidate ordinal in separate fields.
The implementation adds no buffer, page, clear, dispatch, ABI field, or trace
site. Candidate evaluation is bounded by the existing 48-proposal D0 per-vertex
ceiling, but runtime cost must be measured because the secondary vertex now
evaluates the schedule rather than one proposal. Focused UPT-04 closure and the
full win64-pt-dev-release build passed; 23 rebuilt Vulkan blobs were deployed.
Runtime visual/energy/performance acceptance is pending.

Third runtime finding: secondary-hit normal orientation
--------------------------------------------------------

The indirect-only gi2.txt retest showed no visible change, but its counters
prove that the bounded inner RIS is executing and that proposal scarcity is no
longer the dominant failure:

    valid receivers                                  3,685,241
    continuation miss / geometry hit                 1,002 / 3,479,829
    endpoint-emission zero / positive                3,445,148 / 16,864
    reverse lookup failure / positive PDF            2,317 / 14,547
    secondary selection/material/PDF-ray rejection  0 / 138,615 / 3,217,063
    secondary visibility attempts / passed          106,334 / 8,189
    canonical empty reservoirs                       3,661,420

Relative to gi.txt, secondary visibility attempts rose from 4,846 to 106,334
and passes rose from 390 to 8,189. The unchanged image therefore cannot be
attributed to the inner loop not running. The dominant rejection moved to the
PDF/ray bucket at 3,217,063 secondary hits.

A direct comparison with the accepted legacy secondary-hit surface adapter
found a concrete downstream mismatch. Legacy orients the geometric normal to
the incoming ray, orients the shading normal to the same visible hemisphere,
and then constrains the shading normal. Upt04BuildGeometryHitSurface decoded
the RayQuery/TraceRay frontFace value but did not use it: both normals retained
raw mesh-winding orientation. On back-side committed triangles this can zero
the OpenPBR NdotV/NdotL terms and make the visibility builder reject the light
at its horizon test before any shadow ray is emitted.

The decoder now flips the geometric normal when frontFace is false and flips
the interpolated shading normal when it opposes that oriented geometric normal.
It then applies the legacy minimum 0.02 geometric-normal dot constraint.
This changes only traced-hit receiver construction; emissive light replay and
the accepted direct D0 light universe remain unchanged. It adds no proposal,
ray, descriptor, ABI field, resource, clear, or dispatch. The focused UPT-04
artifact target and full win64-pt-dev-release build pass. The final
shared-module rebuild produced and deployed exactly 33 UPT-04, four UPT-07,
and two UPT-09 Vulkan blobs; the executable remained unchanged. Runtime visual
and counter acceptance is pending.

Fourth runtime finding: secondary diffuse material contract
-----------------------------------------------------------

The normal-orientation build remained visually broken. The user's mirror
experiment provided a stronger localization signal: geometry reached by the
continuation ray showed false-color/placeholder-looking texture data, and
emitters missing from indirect illumination corresponded to those corrupted
secondary receivers. The screenshots are:

    E:/prog/rbdoom-3-BFG-prebuilt/base/screenshots/
        rbdoom-3-bfg-20260808-235808-001.png
        rbdoom-3-bfg-20260809-000031-003.png

The geometry route audit found the same static, dynamic, rigid, and skinned
material-index sources used by legacy. The first proven divergence was instead
inside Upt04EvaluateSecondaryDirectProbe:

1. PathTraceMaterialUniverse initializes debugAlbedo from
   SmokeMaterialIdToDebugColor when no authored fallback is available.
2. UPT initialized baseColor from that debug/fallback value and multiplied the
   sampled diffuse texture by it for every textured hit.
3. UPT sampled RT_SMOKE_MATERIAL_DIFFUSE_YCOCG textures as raw RGB and did not
   mirror r_pathTracingTextureDecode.
4. UPT multiplied every surface by vertexColor, while legacy does this only
   for GUI-screen translucent surfaces.

This is sufficient to explain the mirror image without invoking a failed TLAS
identity: the correct texture can be addressed yet appear material-ID tinted
and raw-YCoCg false-colored. The same multiplication can drive selected color
channels or the scalar secondary target toward zero, explaining why a stable
subset of emitters appeared to illuminate secondary receivers while others did
not.

The secondary MaterialSet now uses legacy-shaped diffuse evaluation:

    forced debug or missing diffuse texture -> saturated debugAlbedo fallback;
    valid diffuse texture -> sampled texel, not debugAlbedo times texel;
    flagged YCoCg texture -> exact legacy decode when the existing decode cvar
        is enabled;
    GUI-screen translucent -> legacy vertex-color modulation/fallback only;
    invalid descriptor index -> reject, never substitute density.

The existing r_pathTracingTextureDecode cvar is carried through a new material
policy bit into the otherwise unchanged 208-byte UPT control word. The
specialization/history hash already includes materialPolicyFlags, so changing
the cvar cannot reuse a reservoir written under the other interpretation. No
ray, descriptor, reservoir field, buffer, clear, or dispatch was added.

The diagnostic-only entry adds a secondary material census distinguishing
valid/invalid material index, forced-debug fallback, missing-texture fallback,
ordinary textured input, YCoCg textured input, and descriptor OOB. This first
material-census version used words 0 through 93 with probe bases 94 and 110;
the later continuation-geometry diagnostic below supersedes that layout.
Production shaders contain none of these atomics.

The focused UPT-04 runtime-artifact target and full win64-pt-dev-release preset
pass. The rebuilt executable and exactly 23 affected production Vulkan UPT
blobs were deployed, followed by the final rebuilt diagnostic blob. Runtime
acceptance must first show correct mirror texture colors and then restored
family-2/family-0 indirect acquisition with reuse disabled.

Fifth runtime finding: secondary geometry localization
------------------------------------------------------

Runtime confirmed that the secondary diffuse correction fixes reflected

probe at 139. C0 records receiver material/surface, continuation validity, ray

An attempted scene-residency widening registered UPT indirect as a route-1

2.8 Russian roulette (paper Section 6.2.4, supplemental Section 6) - VERIFIED
------------------------------------------------------------------------------

This directly contradicts our 07_three_bounce_and_russian_roulette_readiness.txt
and doc 03. The paper does NOT replay roulette decisions.

Quoted problem statement:

    "Usually, the primary sample space (PSS) is extended with random numbers for
    Russian roulette, which can create caveats for shift mapping: naively
    replaying the random numbers to perform Russian roulette tests in hybrid
    shift can increase shift failure, as a survived path can sometimes be
    shifted to a killed path, invalidating the sample."

Their solution: decouple the PSS definition from the actual sampling process.
Paths are defined in the original PSS WITHOUT roulette dimensions. Roulette only
alters the initial sample's PDF:

    p(ubar) = product_{i=1..k-1} q_i(ubar)

where q_i are the survival probabilities at each bounce. RR is applied at initial
sampling only and removed from random replay entirely, so roulette failures
during shift mapping are eliminated.

Cost effect, from Table 1: applying RR moved total frame time from 25.02 ms to
16.52 ms, with initial sampling dropping 12.56 -> 5.21 ms. It is the single
largest optimisation in the paper.

PART 4 - CONSEQUENCES FOR THE GO/NO-GO
======================================

The performance argument does not transfer to greenfield
---------------------------------------------------------

The paper's unification is net faster only because it deletes an existing
separate ReSTIR DI pass. UPT is being built from scratch and has no such pass to
delete. In our architecture we buy the +24 percent on initial sampling and
collect none of the -4.24 ms offset.

In greenfield, unification is a quality and memory decision, not a speed one.
The memory win does transfer (2 x 64 bytes per pixel, 265 MB at 1080p). The
speed win does not. Do not set a UPT-05 performance expectation that assumes it.

The quality benefit is not visible before reuse
------------------------------------------------

The gain is attributed to hybrid shift and pairwise MIS. Neither exists in the
baseline, and both sit behind the UPT-05 stop condition. At M small and no
reuse, a correct unified renderer and a split DI/GI renderer produce nearly
identical images.

Therefore UPT-05 is a plumbing gate - is it correct, is the ABI sound, is the
cost within budget - and not a design gate. The unified-versus-split verdict
requires at least a temporal pass with a working shift mapping.

Decide deliberately between:

    A. accept UPT-05 as plumbing-only and move the design go/no-go to after
       UPT-07 temporal reuse;
    B. pull a minimal temporal pass with reconnection shift into the spike
       specifically to expose the reuse benefit, accepting that this violates
       the current stop condition.

What does not need to change
-----------------------------

    the 64-byte reservoir stride - matches the paper exactly;
    doc 03's stored fields: path length, reconnection vertex length, replay
        key, path PDF, partial Jacobian, confidence weight - all genuine
        ReSTIR PT and all needed;
    the three-state candidate model (INVALID / VALID_ZERO / VALID_POSITIVE);
    the material/ReSTIR separation and the composition-root design;
    the random dimension ledger structure;
    README decision 3.

The damage is confined to initial sampling, the ray ledger, and the roulette
replay contract. The ABI survives.


PART 5 - UNRELATED LIVE BLOCKERS (carry forward)
================================================

These are host-side and independent of everything above. They are why UPT-04 has
never executed.

B1. Duplicate Vulkan binding 0 in the set-0 layout

    PathTraceUnifiedPt.cpp zeroes all four VulkanBindingOffsets including
    setConstantBufferOffset(0), then adds both RayTracingAccelStruct(0) and
    PushConstants(0, 128). NVRHI maps PushConstants through
    bindingOffsets.constantBuffer, so both become Vulkan binding 0 in the same
    VkDescriptorSetLayout. That violates
    VUID-VkDescriptorSetLayoutCreateInfo-binding-00279 and corrupts the
    acceleration-structure descriptor, which is why every RayQuery dies while
    UAV writes and SRV reads survive.

    Fix: drop .setConstantBufferOffset(0) and leave the 256 default. No shader
    change, no reflection change.

    NVRHI's own validation layer cannot see this - it tracks duplicates per
    D3D register class, where SRV 0 and CB 0 are distinct.

B2. No Vulkan validation layer in any gate

    r_useValidationLayers defaults to 1 (NVRHI only). 2 loads
    VK_LAYER_KHRONOS_validation. B1 would have been reported at layout
    creation on the first launch. Add a first-launch validation-layer run to
    the UPT gate list.

B3. Scalar block layout mismatch between harness and game

    Shaders compile with -fvk-use-scalar-layout
    (neo/cmake/PathTracingSlang.cmake:108). The UPT-00 and UPT-03 harnesses
    require and enable vulkan12.scalarBlockLayout. The game device never
    enables it (neo/sys/DeviceManager_VK.cpp:1044-1055) and does not request
    VK_EXT_scalar_block_layout.

    Currently latent only because spirv-val runs without
    --scalar-block-layout and is therefore enforcing the stricter std430
    rules, which every present struct happens to satisfy.

    Fix one way or the other and record it in doc 08's frozen-command table.
    Do not "fix" it by adding --scalar-block-layout to the validator; that
    converts a build error into runtime UB on the game device.

B4. Observability

    05_tasks_and_validation.txt requires debug-only counters in UPT-04 scope;
    02_gpu_work_ledger.txt R3 makes them optional; doc 12 shipped none. The
    entire staged bring-up therefore had one observable - did the machine
    survive. Add the fixed counter block and a readback before resuming the
    stage ladder.
