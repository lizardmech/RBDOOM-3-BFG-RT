UPT-45 S45.1: native PSR compact-contract audit
================================================

Result
------

The native Slang PSR can replace the rejected clean-DI adapter without a
176-byte companion receiver. The accepted UPT compact streams already contain
the complete post-replacement shading/history contract. One fact required
only while resolving the front pane needs narrow native ownership:

    front-pane transmission/reflection composition payload.

That fact does not justify importing the clean feature registry or a wide
primary record.

Current compact receiver
------------------------

`Upt04PackedPrimarySurfaceRecord32` is exactly 32 bytes:

    geometry.x     full-precision camera hit distance
    geometry.y     oct16 geometric normal
    geometry.z     oct16 shading normal
    geometry.w     oct16 surface-to-camera direction
    material.x     RGB10 base color
    material.y     RGB10 specular F0
    material.z     shared-exponent RGB emission
    material.w     fp16 roughness plus version/valid header

`Upt04PrimaryHistorySidecar` is exactly 32 bytes:

    metadata.x     sidecar version plus surface class
    metadata.y     validity/object-motion/previous-position flags
    metadata.z     stable material ID
    metadata.w     material flags
    previous.xyz   previous world position
    previous.w     alpha cutoff

Together they publish every fact currently reconstructed by D0/T0/S0:

    current position, normals and view direction;
    evaluated base color, F0, roughness and emission;
    stable material identity and coverage class;
    previous position and motion validity;
    alpha-reuse boundary.

The 176-byte `Upt04PrimarySurfaceRecord` constructed in Slang is a logical
evaluation value, not required source storage. A native PSR must pack the
replacement directly into compact32 and the sidecar.

Facts deliberately absent from compact history
-----------------------------------------------

The compact streams do not retain:

    current dense material-table index;
    source instance ID;
    source primitive ID.

Those are not D0/T0/S0 history facts. They were present only because the old
clean producer consumed its 176-byte record.

Front material classification
-----------------------------

Eligibility is available without a material-table access from the stable
material flags and translucent surface class in the sidecar. Stable material
IDs are 32-bit FNV hashes, so they are intentionally sparse and cannot index a
dense GPU array. The native baseline classifies the front receiver from the
sidecar and derives its tint/transport inputs from the already packed receiver
values. It performs no front-material identity translation.

The committed back hit obtains its current dense material index directly from
the geometry route. That is the index needed for back-surface material
evaluation and does not require a search.

Forbidden alternatives:

    linear scan of the material table;
    GPU hash/probe lookup;
    binary search over sorted material IDs;
    a sparse array indexed by the 32-bit stable material hash;
    full-screen 16-byte identity companion solely to retain a dense index;
    assuming stable material ID equals the current dense index.

Source-pane exclusion should use a forward ray-origin offset. If an explicit
same-pane check proves necessary, source instance/primitive may be retained in
a producer-local scalar token; it must not become persistent receiver history.

Narrow hit resolver
-------------------

The existing general UPT decoder is intentionally too broad for PSR:

    Upt04SmokeVertex                 112 bytes
    Upt04ResolvedTriangle            356 bytes logical payload
    Upt04GeometryHitSurface          124 bytes logical payload

It expands three complete vertices and retains tangent, bitangent, two color
channels, two UV sets and secondary-shading state. Importing it wholesale would
defeat the register/occupancy goal.

The native PSR resolver must word-address the existing vertex buffers and load
only:

    position.xyz;
    normal.xyz;
    primary texcoord.xy;
    route material index and stable material ID;
    triangle class/flags;
    current and previous transform/position only when required.

The traversal live value is limited to compact hit facts:

    instance ID, canonical primitive ID, barycentrics, hit distance, face bit.

Triangle attributes are reconstructed only after the selected committed hit.
Material identity, texture sampling, previous-position reconstruction and
compact output packing happen after RayQuery so they do not extend its live
range.

Material evaluation boundary
----------------------------

The 112-byte source material and 96-byte feature-parameter records remain
authoritative storage but must be word-addressed. The clear-window producer
loads only:

    glass eligibility/capability words;
    params0 and params1 for transmittance, thickness, IOR, strength,
        reflection boost and transmission floor;
    diffuse/specular texture indices and material flags for the accepted hit;
    debug fallback colors needed when a texture is absent.

It must not construct the full OpenPBR closure or import the general secondary
material evaluator. Normal mapping, tangent reconstruction, emission and
additional texture roles require independent measured admission.

Composition token
-----------------

Replacing the receiver discards the front pane by design, but late appearance
composition still needs its transport weight. The old accepted sidecar proves
that one RGBA value is sufficient:

    rgb    transmission or reflection-owned throughput
    a      empty/pending/reflection-owned/resolved marker plus reflection energy

The native first implementation therefore owns one full-frame RGBA16F token:

    8 bytes / pixel
    overwritten for every pixel by the PSR classify/producer dispatch
    no clear
    read once by native post-R0 composition
    no temporal history

It is not a primary-surface stream and cannot be read by D0/T0/S0. Any proposal
to widen it or add history requires a new ledger entry.

RR and previous-position publication
------------------------------------

The replacement compact sidecar must publish the accepted hit's stable
material ID, class/flags, alpha cutoff and previous position. Previous position
comes from the existing route-specific sources:

    static/current-stable geometry    current position when history is stable;
    dynamic geometry                  previous dynamic vertex source when valid;
    rigid geometry                    previous object transform;
    skinned geometry                  previous skinned position buffer.

If a route cannot prove its previous position, it clears the motion-valid bits
and publishes current position as a non-reprojectable fallback. It must not
invent motion. RR guide texture writes are derived from the same accepted
replacement, after compact publication, and are statically absent when RR is
not requested.

Native descriptor closure
-------------------------

The producer may bind only:

    TLAS;
    compact32 receiver UAV;
    current sidecar UAV;
    narrow word views of material, feature and parameter tables;
    current geometry route/index/position/normal/UV data;
    route-specific previous position/transform data;
    bindless textures plus the existing material sampler;
    RGBA16F composition token UAV;
    optional RR guide UAVs in an RR-specific specialization;
    one small push-constant block.

The composer may bind only R0, the composition token and its output UAV. It
does not bind TLAS, geometry, material, light, reservoir or history resources.

Build and profile gates
-----------------------

The build verifier must fail if reflection/disassembly shows:

    a clean-DI reservoir or ReGIR binding;
    the 176-byte primary record;
    a light record/distribution/remap binding;
    more than the declared producer RayQuery count;
    the general `Upt04ResolvedTriangle` or `Upt04GeometryHitSurface` decoder;
    an unbounded search loop;
    unexpected material/geometry word loads.

Runtime promotion remains blocked until Nsight records registers/thread,
maximum live-register site, occupancy, No Instructions and Long Scoreboard for
no-glass, sparse-glass and full-view-glass cases. These figures must be kept in
this document with the final artifact hash.

S45.2/S45.3 implementation checkpoint, 2026-08-13
--------------------------------------------------

The first native Vulkan implementation now follows the split visible in the
RTXDI Full Sample capture:

    P0 -> UPT.PSR NativeClearWindow -> D0/T0/S0/R0
       -> UPT.Glass NativeCompose Last -> optional RR/presentation

The final Glass marker is therefore composition, not the receiver replacement
itself. The early producer overwrites compact32 plus its current sidecar before
any UPT estimator consumes them. The late compute pass binds only R0, the
RGBA16F token and the existing frame output UAV.

The producer is implemented in `neo/shaders/slang_upt45` and has one statically
declared RayQuery. It uses direct word loads for route, vertex and material
data, builds only `Upt45NarrowHit`/`Upt45NarrowSurface`, and does not import the
general UPT triangle/surface decoder. It binds no light universe, reservoir,
ReGIR, clean-DI state or 176-byte primary record. The token is the only new
full-resolution allocation: RGBA16F, 8 bytes/pixel, overwritten by every
dispatched pixel, no clear and no history. Composition reuses the existing
frame output instead of allocating a second private image.

The rejected adapter's UPT-side wide-record mode and clean material-feature
state were removed. The existing u97/u98 aliases remain owned solely by the
legacy clean-DI glass implementation; UPT neither binds nor imports them. This
keeps legacy behavior intact and the native UPT descriptor closure independently
auditable.

S45.4 behind-glass geometry guides and skinned route correction, 2026-08-13
----------------------------------------------------------------------------

Initial runtime validation proved the native PSR/compose split and exposed two
producer-contract defects. First, compact receiver replacement alone was not
enough for DLSS-RR: P0's guide textures still described the clear pane. Second,
the narrow resolver derived the first skinned shader-instance ID as
`2 + rigidInstanceCount`, although the established skinned route header owns
the actual ID. A non-contiguous route range could therefore select a wrong
skinned route and material.

The producer now reads the first skinned instance ID from route record zero,
then validates the selected record's own `shaderInstanceId` before loading its
triangle/material data. It does not broaden the route or add a search.

For every accepted replacement, and only while DLSS-RR is effective, the same
narrow post-RayQuery surface now publishes:

    albedo and specular/F0 guides from the replacement material;
    normal and roughness from the replacement surface;
    hardware-depth encoding and world position from the replacement hit;
    PT and RR motion from replacement current/previous positions;
    an invalid motion reason when prior camera/object position is unavailable.

Thus ordinary clear glass is invisible to RR geometry. The pane no longer
owns normal, depth, position, or motion for objects behind it. No distortion is
performed in this baseline; a later distortion lane may offset the viewed
guide lookup deliberately, but may not restore pane geometry to these guides.
The RR UAV writes are gated by the existing effective RR state. D0/T0/S0
receiver publication remains unconditional for accepted PSR hits.

The Vulkan verifier still proves one RayQuery and now admits producer bindings
0,3..34. The rebuilt producer is 57696 bytes with SHA256
299FF7474DBEA75C50F382A1D77BCE2AD436EDEE6D64393E289D1877F667F9CB.
The unchanged composer remains 2364 bytes with SHA256
89CDCA18E9BDC0350FB460E7EF09E7C8FA1C3EE58E0A1955799D7666F3150AC7.
The full Vulkan release build passes. Runtime acceptance must specifically
exercise animated skinned surfaces through clear glass with RR normal, depth,
motion, and final output views.

S45.5 neutral clear glass and bounded stacked-pane continuation, 2026-08-13
----------------------------------------------------------------------------

Runtime confirmed the RR geometry correction, but also proved that UPT45 had
invented two appearance behaviors absent from the accepted legacy baseline:
it multiplied the result by the pane's packed diffuse color and added a small
overlay. This made authored diffuse maps look like glass tint/opacity. Both are
removed. The clear-glass composition token is now exactly `(1,1,1,1)` and the
host overlay is zero. Pane material data is used only for eligibility; normal
maps remain reserved for the later distortion lane.

The original native traversal also committed the first hit behind the source
pane. When that hit was another clear pane, it became the replacement receiver
and therefore rendered solid. The single existing RayQuery now classifies each
non-opaque candidate from narrow route-owned material/class words and declines
to commit portal-window/object-glass candidates. Hardware traversal continues
until it finds the first non-glass receiver. This adds no ray and preserves the
one-RayQuery verifier ceiling. It is transmission visibility/receiver
selection, not GI transport; indirect lighting through the resulting receiver
remains owned by the ordinary unified D0/T0/S0/R0 estimator.

The rebuilt producer is 61864 bytes with SHA256
4C5F1D38CFD049AD0B953AB8A387502C16DC57A1F5E37B29CB9F4F9878F3EA18.
The full Vulkan release build and descriptor/RayQuery verifier pass. Runtime
acceptance must cover one pane, two or more overlapping panes, textured pane
materials, and an opaque/skinned receiver behind the stack.

S45.6 authoritative glass-feature admission, 2026-08-13
--------------------------------------------------------

Runtime showed two coupled failures after stacked traversal landed: some panes
still remained on the old stochastic translucent lane, while a pane behind an
accepted front pane could become the replacement receiver and project its
diffuse texture over dynamic geometry. The cause was the same narrow admission
mistake in two places. UPT45 recognized only portal/object fallback bits and
triangle subtype. The accepted legacy path first loads the authored
`PathTraceMaterialFeatureRecord` and requires the complete glass transmission
contract:

    materialKind == TRANSLUCENT_GLASS
    PATH_TRANSMISSION set
    DEBUG_FAIL_CLOSED clear
    SPECULAR_TRANSMISSION set
    TRANSMISSION_PRODUCER set

P0 already has the dense material index and authoritative feature buffer. It
now validates that contract once and publishes a cold sidecar eligibility bit.
The compact32 hot record is unchanged. The native producer admits a front pane
only from that bit, avoiding stable-ID search and avoiding the incomplete
fallback-only test.

RayQuery candidates already resolve a dense material index from their geometry
route. Binding 35 exposes the existing 32-byte feature records as two narrow
uint4 loads. Feature-supported panes are declined inside the same traversal;
the first non-glass receiver is committed and shaded from its own material.
Fallback subtype/flag checks remain only as a fail-safe for invalid feature
records. No extra ray, full-record load, material search, buffer clear or new
allocation was added. The producer push ABI remains 224 bytes by replacing two
unused appearance floats with feature count/reserved words.

Verified Vulkan artifacts after the full release build:

    upt45_clear_window_psr.bin
        bytes 63204
        SHA256 05148B1FEFF5763E73C45169A11B53ED0AEF7B00FFE0926524B2EAF84E0BF091

The reflected descriptor closure is now 0,3..35 and binding 35 is exactly
`gUpt45MaterialFeatureWords`. The SPIR-V verifier still proves one RayQuery.
Runtime acceptance must recheck the previously missing panes, a dynamic and a
skinned receiver behind one and multiple panes, and confirm that no pane
diffuse texture reaches the replacement receiver.

S45.7 reject the secondary mini renderer; integrate PSR into P0, 2026-08-13
----------------------------------------------------------------------------

Runtime disproved the S45.1 premise that a deliberately narrow secondary
surface evaluator could publish a complete receiver. Surface selection became
correct after S45.6, but the selected receiver still lost canonical behavior:

    alpha-tested candidates were committed without primary alpha evaluation;
    indirect-ready material surfaces were incomplete;
    skinned characters used a parallel route/attribute reconstruction;
    normal maps, dynamic stages, emission and primary modifier handling were
        either partial or absent.

This was the same architectural failure mode as the old clean-DI transmission
producer, even though UPT45 used one bounded RayQuery rather than the rejected
unbounded any-hit traversal. It built a second geometry/material renderer
behind glass. The geometry-modernization decision history accepted bounded
traversal for safety, not duplicated shading as a canonical producer contract.

The native compute producer, narrow geometry decoder, manual material
evaluator, full-screen RGBA16F token and no-op late composer are therefore
rejected and removed from the build. UPT clear-window PSR now executes inside
the lean P0 any-hit shader, after canonical route and material-index resolution
and before existing alpha/decal processing:

    eligible clear pane -> set one payload bit -> IgnoreHit -> continue P0
    final committed hit -> ordinary closest-hit -> ordinary BuildSurface
    final receiver -> ordinary compact32/sidecar/RR guide publication

The payload bit records only that a clear pane was crossed. It is copied across
the existing filter-decal receiver retrace and becomes the cold sidecar glass
ownership bit; it does not alter the final receiver's material identity. Stacked
panes naturally repeat the same any-hit decision in one primary traversal.

This makes alpha cards, rigid/skinned routes, dynamic materials, normal maps,
emission, modifiers, compact packing, motion and RR guides exactly the same
code path with and without glass. It also removes one full-screen RayQuery
dispatch, one full-screen compose dispatch and the 8-byte/pixel token.

S45.8 restore legacy optics without restoring the secondary renderer, 2026-08-13
-------------------------------------------------------------------------------

S45.7 correctly made canonical lean P0 the sole owner of the receiver behind
glass, but intentionally removed the legacy optical result. UPT therefore had
correct opaque, alpha-tested, rigid, skinned, emissive and indirect surfaces
behind a pane while losing its normal-map distortion, transmission attenuation
and bounded reflection.

The reference audit confirms that these concerns belong after opaque surface
resolution. RTXDI Full Sample's Glass pass retraces transparent layers and
composes throughput, overlay and a bounded secondary reflection over an
already-lit image. Remix similarly carries a compact GbufferPSRData pane event
into separate reflection/transmission work. Neither design replaces the opaque
receiver with a partial material renderer.

UPT now uses the same ownership split with existing proven components:

    P0-behind mode 1
        feature-supported panes call IgnoreHit;
        canonical compact32 receiver/history and RR guides remain authoritative.

    P0-pane mode 2
        a second canonical primary trace deterministically accepts the first
        feature-supported pane into the legacy wide scratch record;
        no stochastic glass-coverage test and no RR-guide publication occurs.

    optics-only transmission producer
        reads the pane record, evaluates the accepted normal-map distortion,
        transmission attenuation and one bounded reflection;
        publishes only the existing optical sidecars and returns before the
        legacy behind-glass receiver trace/rebuild/publication block.

    R0 then legacy glass compose
        applies the sidecars over the completed UPT result before DLSS-RR;
        it cannot alter compact32, temporal or spatial reservoirs.

This deliberately spends one extra canonical visibility trace for enabled
glass rather than reintroducing a second geometry/material implementation. It
adds no full-buffer clear and preserves the existing bounded reflection ray
ceiling. Stacked panes remain transparent to the authoritative P0 receiver;
the optical event is currently the first supported pane, matching the bounded
adapter rather than claiming an unbounded transparent path integrator.

Runtime proof must cover normal-map distortion, transmission attenuation and
reflection on static, rigid, skinned, alpha-tested, emissive and indirectly lit
receivers, including two panes. The console contract is:

    glass optics requested/effective=1/1
    order=P0-behind/P0-pane-optics/D0/T0/S0/R0/compose
    receiverReplacement=0

DLSS-RR normal, depth, position and motion must continue to describe the
behind-glass receiver; distortion may offset the viewed result but the pane
must never become RR geometry.

Pipeline admission correction
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

The first S45.8 host integration allocated a second private material-feature
pipeline cache for UPT. Runtime reported every resource/cvar gate admitted but
`pipelines=0`. UPT now shares the proven clean-DI glass shader-library,
pipeline and shader-table cache. These objects are immutable execution state;
UPT still supplies its own bindings and optics-only constants, so sharing them
does not enable or dispatch clean DI and cannot replace the UPT receiver. No
additional pipeline-enable cvar exists or is required.
