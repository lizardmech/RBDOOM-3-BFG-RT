UPT-04 Minimal Unified Initial Sampler: GPU Work Admission
==========================================================

SUPERSEDED IN PART
------------------

The originally recorded initial-sampling design - a one-draw mixture over
transport families, M = 1, and a two-ray ceiling with direct/indirect mutually
exclusive - was not the design in the cited ReSTIR PT Enhanced paper. The live
implementation sections below have now been corrected to trace the primary NEE
ray in addition to the continuation, build a path tree, and let initial
resampling select among several candidate paths.

Read 13_upt04_corrections_and_paper_reference.txt before implementing or
reviewing D0. The resource ledger, descriptor ownership, host publications,
module boundary, and runtime wiring in this document remain valid.

------

contract, and fixed diagnostic readback are implemented and pass offline build,

The first live attempt with the default direct-only RayQuery route produced
Windows LiveKernelEvent 141. r_pathTracingUnifiedPtProofStage localized the
failure to GPU execution, and shader-proof modes 1 through 3 ran while mode 4
device-removed. Compact Slang and DXC probes (modes 7 and 8) then traversed the
same live game TLAS successfully. This proved the compiler, driver, NVRHI
RayQuery support, TLAS descriptor, TLAS state transition, and fixed ray were
valid rather than merely inferred from offline SPIR-V.

Modes 9 through 13 isolated the host descriptor ABI. Mode 12, containing only
the production t0 TLAS and u4 output, survived. Mode 13 added only the 128-byte
b0 push range and device-removed. The cause was a duplicate flattened Vulkan
binding in the host layout: UPT forced every NVRHI register-class offset,
including constantBuffer, to zero. This old NVRHI backend retains push constants
as a zero-count uniform-buffer layout entry for binding-index bookkeeping.
Consequently PushConstants(0) and RayTracingAccelStruct(0) both became Vulkan
binding 0. NVRHI's class-separated validation and Slang reflection could not see
that host-only collision, and traversal consumed an undefined acceleration-
structure descriptor.

UPT now keeps NVRHI's default constant-buffer offset of 256 while retaining the
explicit SRV/UAV/sampler offsets required by the Slang descriptor ABI. After
that one-line correction, the user confirmed both mode 13 and the original
181736-byte direct-only shader mode 4 survive the one-group live-TLAS gate. The
same latent zero-offset PushConstants(0) plus TLAS t0 collision was removed from
the particle-lighting RayQuery layout. The Vulkan NVRHI backend now rejects any
duplicate flattened binding before creating a descriptor-set layout, so a
future cross-register-class collision fails pipeline preparation instead of
reaching GPU traversal.

The screen remaining static during these probes is not a command-queue stall:
geometry frame numbers continue advancing. UPT is execution-exclusive and has
no presentation output yet, so it deliberately leaves the last legacy image on
screen.

A post-crash contract review found a second real device mismatch: the isolated
Slang/DXC lane requested scalar block layout and its private UPT-00/03 harnesses
enabled scalarBlockLayout, while the game device did not. Removing the compiler
flag was tested and rejected: Slang's standard std430 layout expanded the
UPT-00 ray output from 32 to 40 bytes while DXC retained 32-byte HLSL packing,
and GPU readbacks diverged. The game now queries and enables the Vulkan 1.2
scalarBlockLayout feature, matching the proven compiler/harness ABI. No extension
name is needed when the feature is enabled through Vulkan 1.2 core features.

The same review confirmed that survival-only proof modes are not data-correctness
proof. Modes 1..6 currently have no GPU readback. The separate fixed counter
specialization required by UPT-04 remains an acceptance blocker. It would prove
primary reads/reservoir writes and estimator/ray counts, although mode 2 alone
could not have diagnosed the TLAS/push binding-0 collision because it never
traverses the TLAS.

Exact estimator step admitted
-----------------------------

The baseline initial sampler traces a bounded path tree per valid primary
receiver. It evaluates primary NEE and, independently, one BSDF continuation.
Every resulting candidate is streamed through one reservoir, so the target
function is load-bearing in production D0. The finalized initial confidence is
c = 1 even though two candidates normally participate in weighted selection.

Enabled top-level families are:

    explicit local light
        Select one current sampleable manager record. Its record type chooses
        analytic versus emissive-triangle sampling. Evaluate the baseline
        material at the primary receiver and trace at most one visibility ray.

    environment
        Select a direction from the published environment provider and trace at
        most one visibility ray. This family remains disabled and its mixture
        probability is renormalized to zero until M6 publishes the provider.

    indirect continuation
        Ask the baseline MaterialSet for one continuation event and trace at
        most one continuation ray. A miss may consume the environment provider.
        An emissive hit may terminate with endpoint emission. At an opaque hit,
        evaluate one explicit local-light NEE proposal and trace at most one
        visibility ray for that connection.

This admits one logical candidate and therefore M = 1 for a defined trial in
the first production specialization. The shared reservoir is still required:
it fixes the selected-sample ABI, event classification, later reuse input, and
identical normalization for direct/global families. Raising the initial
candidate count is a new ledger decision, not a cvar hidden inside this pass.

The direct-light proposal provider may internally use a fixed RIS schedule to
produce that one logical candidate. Its normalization must count every
scheduled trial, including a mathematically defined zero-target trial. An
invalid/malformed proposal is never selectable and contributes zero weight,
but it does not shrink the fixed schedule after the draw. In particular, the
effective proposal PDF for selected target p_hat and accumulated RIS weight W
is:

    effectiveProposalPdf = p_hat * scheduledTrialCount / W

It must not use the number of positive proposals. Positive-only normalization
conditions the estimator on having found illumination: sparse receivers become
too bright, increasing the proposal count changes energy, and temporal reuse
then preserves a bright sparse outlier as a long ghost. This internal RIS count
does not change the finalized D0 reservoir confidence/M contract above; D0
still publishes one current-frame logical candidate after selected-sample
visibility.

The stored proposal PDF includes every probability used to create the event:

    top-level family probability
    local-light type/range and dense-record selection probability
    light-surface or environment-direction PDF
    material lobe and continuation-direction PDF where applicable

For an indirect opaque-hit NEE event, the stored forward path PDF also includes
the primary material continuation PDF. Russian roulette is absent. No
visibility probability is multiplied into a PDF; visibility changes the
defined candidate to VALID_ZERO when occluded.

Family disable rule
-------------------

Only available families participate in normalization. A missing environment,
an empty sampleable local-light range, or a material with no continuation lobe
removes that branch and renormalizes the remaining probabilities before the
family draw. A disabled branch creates no placeholder candidate.

If no family is available, the receiver writes canonical empty. If a selected
available technique produces a mathematically defined zero contribution, it is
VALID_ZERO. Broken identity, stale generation, zero/non-finite required PDF,
impossible hit route, or failed material decode is INVALID and cannot change M.

Ray ledger
----------

Per valid receiver, the bounded path-tree work is:

    path-tree edge/event            continuation rays   visibility rays
    primary x1 local-light NEE              0                   1
    x1 -> x2 BSDF continuation              1                   0
    x2 miss/environment endpoint            0                   0
    x2 emissive endpoint                    0                   0
    opaque x2 local-light NEE               0                   1

Absolute ceiling:

    primary/camera rays             0; consume current primary surface
    continuation rays               <= eligible receivers
    visibility rays                 <= 2 * eligible receivers
    total D0 rays                   <= 3 * eligible receivers
    resolve/reconnection rays       0

At k_max = 2, visibility rays <= k_max and continuation rays <= k_max - 1.
This is a 50 percent increase over the superseded two-ray ledger and is the
honest cost of the cited unified design. Candidates remain free bookkeeping:
an emissive opaque x2 can stream its BSDF endpoint and its NEE candidate without
another continuation ray. A visibility segment already proved by the selected
initial path is never retraced in UPT-05 resolve.

Backend A/B contract
--------------------

Two static composition entry points must call the same transport, material,
proposal, random, validation, update, and pack modules:

    initial_rayquery
        compute, 8 x 8 candidate group proposed for the first measurement

    initial_raygen
        ray-generation entry with the same receiver domain and candidate policy

Only the trace adapter differs. Both adapters return the same compact facts:

    miss/hit status
    instance, geometry, and primitive identity
    barycentrics, hit distance, and front-face state

Neither backend may shade inside its trace adapter. The caller-owned transport
loop passes hit facts to the selected MaterialSet/geometry adapter. The A/B uses
the same dimensions, scene, fixed random provider, family probabilities, and
ray ceiling. Pipeline order is alternated because UPT-00 proved first-created
pipeline timing can contaminate a comparison.

The losing backend is removed from the baseline specialization after the A/B.
Keeping both active or creating both pipelines on every launch is forbidden.

Secondary-hit/replay route matrix
---------------------------------

Every hardware hit must decode in O(1); no route-table scan is admitted:

    static bucket
        classify from the encoded 0x00800000 InstanceID bit, add the encoded
        packed triangle base to bucket-local PrimitiveIndex, require
        GeometryIndex == 0, then use the shared static pool

    monolithic static
        InstanceID == 0, PrimitiveIndex addresses the static triangle pool

    monolithic dynamic
        InstanceID == 1, PrimitiveIndex addresses the dynamic triangle pool

    rigid
        InstanceID - 2 directly addresses the rigid route instance; its local
        PrimitiveIndex addresses that route's index/triangle range

    skinned
        record zero publishes the contiguous first InstanceID and route count;
        subtraction gives the route record, whose source-index/output-vertex
        and triangle-metadata offsets resolve the hit directly

The full unified/emissive/indirect composition may bind only these existing
buffers in addition to the seven-binding direct closure:

    current emissive replay records
    static vertices, indices, triangle class, triangle material index
    dynamic vertices, indices, triangle class, triangle material index
    rigid vertices, indices, route instances
    skinned current vertices, source indices, route records, route triangles

That is sixteen existing SRVs. Material IDs are not duplicated: static/dynamic
stable identity uses material index plus the page generation; rigid and skinned
records already carry their material identity. A direct-analytic-only
specialization must not import or bind this geometry closure.

Static production specializations
---------------------------------

Production candidates:

    unified_white_<backend>
    direct_only_white_<backend>
    indirect_only_white_<backend>

modes 9/10 may retain a deliberately full host layout for ABI isolation, but
that diagnostic layout is not a production resource contract.

compact hit facts through the shared O(1) geometry adapter, terminates on
endpoint emission, or samples one local-light NEE connection at an opaque hit.
A miss while the environment provider is unavailable and defined zero BSDF,
emission, or light outcomes remain VALID_ZERO. They do not issue visibility
rays. Structural decode/identity/PDF failures remain INVALID and never enter M.

There is no selected-family probability. Each candidate carries its own path-
technique PDF and balance-heuristic MIS weight. Indirect NEE includes the
continuation, light-selection, and light-surface PDFs. The
work contract already carries path length, reconnection length, replay key,
path PDF, partial Jacobian, and accumulated roulette probability. The current
one-continuation specialization writes the same 64-byte reservoir that the
three-bounce/RR codec tests use; adding depths changes pathVertex and transport
policy, not this ABI.

Runtime wiring implemented
--------------------------

PathTraceUnifiedPt is a separate owner called after the shared primary UAV
barrier and before the single primary-history publication. It owns:

    one width * height * 64-byte structured page-0 UAV
    one set-0 binding layout and one cached binding set
    one selected backend/family pipeline
    no output, history, queue, constant buffer, or optional feature
    one optional 80-byte counter/signature UAV plus 80-byte CPU-read buffer
        owned only by the one-shot diagnostic specialization; the original 16
        counters remain words 0..15 and UPT-05 repeatability uses words 16..19

The route is execution-exclusive. r_pathTracingUnifiedPtEnable overrides the
default-on Clean-DI/GI execution request so legacy pipeline creation and GPU
work cannot contaminate UPT timing. Disabling UPT releases its page, binding,
shader, pipeline, and table handles. Changing backend or family releases the
old pipeline before synchronously creating the selected replacement.

Runtime controls:

    r_pathTracingUnifiedPtEnable 0/1
    r_pathTracingUnifiedPtBackend
        0 RayQuery compute (default)
        1 ray generation
    r_pathTracingUnifiedPtFamily
        0 unified direct + indirect
        1 direct-only (default bring-up)
        2 indirect-only
    r_pathTracingUnifiedPtShaderProof
        1 selected shader: UAV write only
        2 selected shader: primary read
        3 selected shader: proposal/material preparation without tracing
        4 selected shader: fixed valid RayQuery, status only
        5 selected shader: proposed visibility RayQuery, status only
        6 selected shader: committed-hit metadata and reservoir completion
        7 compact live-TLAS Slang query
        8 compact live-TLAS DXC-to-SPIR-V query
        9 minimal Slang query through complete production set 0 and bindless set 1
        10 pure b0/b4 query through the same full host layout
        11 pure query with complete set 0 and no bindless set 1
        12 production t0 TLAS plus u4 output only
        13 mode 12 plus the 128-byte production push range
    r_pathTracingUnifiedPtDiagnostics
        0 production specialization (default)
        1 one-shot RayQuery fixed-counter specialization and readback

The direct-only default creates only its statically pruned closure. Reflection
proves that it drops set 1 and the secondary-material resources. The unified
module is never created merely because the route exists. Unified/indirect retain
the resources required for secondary and textured-emissive material sampling.
Backend A/B within one family keeps identical resource ownership.

Raygen uses three SBT hit records, not the legacy renderer table. The live TLAS
contributes record 0 for legacy/static/rigid geometry and record 2 for skinned
geometry; record 1 is an addressable placeholder. All three records use the
same 32-byte trace-only closest-hit decoder. RayQuery has no SBT dependency.

Pipeline logs report backend, family, module bytes, FNV-1a module hashes,
driver-visible timestamps, group/payload shape, synchronous create time in
microseconds, deferred-host setting, and the fact that driver cache state is
opaque to NVRHI. Deferred host operations are disabled for this first ordinary
driver-managed measurement.

Nsight markers are separate:

    UPT.D0 Initial Bind+Barriers
    UPT.D0 Initial RayQuery Dispatch
        or UPT.D0 Initial RayGen DispatchRays

Emissive gate before unified indirect paths
-------------------------------------------

UPT follows the established Doom content policy controlled by
r_pathTracingReservoirTwoSidedEmissives. Emissive-triangle solid-angle replay
uses the absolute light-facing cosine when that policy is enabled. The policy
bit is passed explicitly into the shared replay helper by D0, T0, and S0; the
shared module must never read one pass's global control block. This prevents a
back-facing panel from being admitted initially and then disappearing during
temporal or spatial replay.

Visible primary-surface self-emission is a local resolve term, not a reservoir
candidate. P0 carries non-negative HDR emission in the existing compact48 and
compact32 receiver records using one previously available 32-bit word. R0 adds
that term only in the normal shaded view, even when the reusable reservoir is
empty. Debug reservoir views remain unchanged. Self-emission must never be
inserted into the reusable reservoir: doing so would let a surface-local value
migrate to another receiver during reuse.

This repair adds no full-frame buffer, clear, dispatch, texture sample, or ray.
The Vulkan build produces receiver-specific trace-free R0 variants so the host
layout exactly matches the active legacy176, compact48, or compact32 P0 record.
Changing the compact receiver encoding requires a version bump on both producer
and consumer and a rebuilt lean primary producer blob; a Slang-only rebuild is
not sufficient.

Reusable emissive-light candidates have a different contract. The unified CPU
light record retains an exact triangle/material identity and replay geometry,
but its constant estimated radiance is not the shaded emitter texel. D0, T0,
and S0 therefore replay the selected triangle UV and evaluate the current
material's emissive texture and dynamic stage before target evaluation. A pass
must not fall back to light.radianceAndLuminance.xyz merely because it is a
direct-only specialization; that silently turns textured emitters into flat or
zero-radiance lights. This exact evaluation uses existing tables and bindless
textures and adds no reservoir fields or full-frame resources.

Conditional translucent/additive signage is neither of those cases. It is a
primary-ray overlay that must be blended through to the opaque receiver, while
the emitter light proposal remains a separate exact triangle. The ordinary
primary producer has a three-layer decal bin plus liquid-pool transport. The
lean UPT producer deliberately does not restore that wide payload: it carries
one nearest signage tuple only (material index, packed UV, hit distance = 12
bytes), evaluates the live dynamic material record, and adds the active stage's
textured emission to the receiver. This is sufficient for mutually exclusive
parm-driven stages such as doorlocklightg without re-admitting general decal or
liquid candidate arrays. UPT is also an explicit emissive-map consumer in the
shared primary producer; gating emissive textures only on the clean-DI shaded
view loses vending-machine and other textured fixture emission before D0.

The final gate is proposal probability. One uniform emissive trial over every
emissive triangle in a Doom map makes textured emitters visible to the camera
but effectively absent from direct lighting. With direct proposal parity
enabled, D0 therefore selects its emissive trial from the manager-owned
power/area CDF. The selected probability is the exact CDF interval multiplied
by the analytic/emissive domain-mixture probability; it is not reconstructed
from the compact light record, which intentionally omits sourcePdf. The CDF's
positive-source order must match the unified manager's dense emissive order,
and D0 validates the selected manager record's sourceIndex before accepting
the replay. A mismatch falls back to the existing uniform proposal rather than
silently assigning the wrong source PDF.

This adds one existing read-only structured-buffer binding to the D0 closure
(set 0 binding 25, 16-byte entries). It adds no allocation, upload, clear,
full-frame buffer, dispatch, texture sample, or ray. Static specialization must
retain this binding in direct and unified families and strip it from the
indirect-only family. The reflection verifier freezes those exact closures.

Legacy/UPT emissive acquisition comparison, 2026-08-08
------------------------------------------------------

Runtime testing after the replay/self-emission fixes found a narrower UPT-only
failure: some emissive lights disappear at reproducible player portal positions
and return after moving through other portals. Legacy clean DI is not affected.
The same emitters can work in one position and fail in another. Static bucket
routing explained a separate color/white-replay defect but did not change the
disappearance, and the observed inventories remain below the 4096-triangle cap.

The producer audit establishes that both lanes receive the same upstream data:

    PathTraceSmokeSceneBuild publishes the emissive triangle inventory;
    PathTraceRemixLightManager publishes the current light payload and typed
        sampleable ranges;
    BuildSmokeEmissiveDistribution publishes the same power/area CDF and dense
        positive-emissive order.

The first material difference is downstream candidate persistence. Legacy clean
DI calls PathTraceCleanRoomResolvePreviousBestInitialSeed before ordinary RIS.
With r_pathTracingCleanRtxdiDiBestLights=1 (default), it reprojects the prior
winner, translates its light through the stable previous-to-current mapping,
replays it at the current receiver, and streams it once as a current proposal
before combining fresh candidates. UPT D0 currently performs fresh CDF/range
selection only. Its r_pathTracingUnifiedPtTemporalPreviousBest experiment is in
T0, defaults off, and was not runtime-accepted because it could darken or
overexpose the image.

The next D0 slice must therefore reproduce the accepted legacy ordering, not
enable the T0 alternate:

    reproject one prior selected direct light;
    translate and validate its stable manager identity/fingerprint;
    replay it at the current receiver with current material and light state;
    admit it once as a current proposal;
    exclude a duplicate fresh selection of the same sample;
    retain the existing one-winner visibility-ray ceiling.

Keep this behind a narrow A/B until the same emitter is traced in one working
and one broken portal position. If the reseed does not close the difference,
record failure counters/identity at the CDF interval, dense manager map, replay
tuple, triangle UV/material emission, target/source PDF, visibility, and final
reservoir selection boundaries. Do not add another emissive cap, portal-local
universe, or candidate-count workaround without that evidence.

D0 emissive acquisition repair, 2026-08-08
-------------------------------------------

The follow-up audit found a failure before proposal. UPT interpreted
gUpt04EmissiveDistribution.GetDimensions() as the live entry count. That value
is the allocation capacity of a reuse-grown structured buffer. It can retain a
larger high-water tail after a portal-frame rebuild publishes fewer positive
entries. Binary search could therefore enter stale, non-current CDF entries and
reject the resulting light before replay. The uniform-mixture experiment hid
the defect by keeping every current entry positive; it did not repair the
count contract.

The current-frame publication is now authoritative:

    emissiveDistributionCount selects the searchable CDF prefix;
    emissiveDistributionValid admits the weighted route;
    GetDimensions is used only as an out-of-bounds capacity guard;
    an invalid current CDF falls through to the existing typed uniform route.

D0 also owns an emissive-only previous-best proposal, independently controlled
by r_pathTracingUnifiedPtD0PreviousBest. It reprojects and validates the prior
receiver, decodes a structurally valid prior direct-emissive reservoir, maps its
stable dense identity through the manager's previous-to-current table, checks
the current fingerprint, replays the stored triangle barycentrics against the
current geometry/material state, evaluates the current receiver target, and
rejects invalid, dynamic-history, zero-target, or non-visible winners. A fresh
proposal of the same mapped light contributes zero to the fixed fresh schedule
and cannot enter twice. Analytic previous-best samples are not admitted by this
slice, so the accepted fresh analytic path is unchanged.

The reseed follows UPT's target-scaled mean-mass convention. Fresh RIS supplies
weightSum/candidateCount, the legacy-shaped seed supplies currentTarget with
source PDF one, and a two-source merge stores their mean. The packed reservoir
continues to carry one finalized current-frame proposal. Only the selected
proposal uses the existing D0 visibility ray; the reflection proof still finds
one trace site in direct-only and three in the unified family.

Focused diagnostic counters now separate previous lookup attempt/success,
stable remap failure, replay failure, current-target failure, visibility
failure, duplicate rejection, successful admission, fresh analytic selection,
fresh emissive selection, and unavailable current weighted CDF. The diagnostic
line also prints current CDF count, physical capacity, validity, and skipped
zero-PDF entries. This proves the audited portal-dependent failure was at the
pre-proposal CDF count boundary; any remaining runtime rejection can be placed
at remap, replay, target, or visibility without adding candidates or filters.
