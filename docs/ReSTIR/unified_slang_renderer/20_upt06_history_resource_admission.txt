UPT-06 History/Resource Page Admission
======================================

Scope
-----

UPT-06 admits resource ownership and history validity only. It adds no temporal
or spatial shader, neighbor read, shift, visibility ray, dispatch, output, or
third full-resolution scratch page. UPT-05 D0 still writes page 0 and R0 still
reads page 0.

Zero-only prerequisite
----------------------

The UPT-04 codec formerly finalized both of these to all-zero bytes:

    no mathematically defined candidate occurred;
    one or more VALID_ZERO candidates occurred but no sample was selectable.

That ambiguity is harmless for no-reuse display but incorrect once a valid
history sample is combined with the current proposal set: the current defined
zero trial must remain in the estimator normalization.

UPT-06 retains the 64-byte stride and defines the low-nibble record tags:

    0: canonical empty/no defined trial; all 64 bytes zero
    1: selected-sample record; existing payload contract
    2: count-only record; word1 is positive M, words2..15 are zero

The initial path-tree proposal set is collapsed to one reservoir candidate, so
zero-only initial output is tag 2 with M = 1. It has no selected identity,
weight, target, age, or history authority. Resolve continues to require tag bit
0 and therefore displays count-only exactly like black/empty while preserving
the information for reuse.

Physical pages and memory
-------------------------

The owner has exactly two structured buffers:

    page bytes = width * height * 64
    page count = 2
    total bytes = width * height * 128

At 2560 x 1440 this is 235,929,600 bytes per page and 471,859,200 bytes total.
There is no GPU metadata/header allocation. Page 0 receives its existing
allocation-only clear so partial proof stages remain deterministic. Page 1 is
never cleared; its bytes are unavailable until T0/S0 (or another explicitly
admitted full-domain producer) publishes fullyWritten=true.

Host metadata
-------------

Each physical page owns one PathTraceUnifiedPtPageMetadata record:

    fullyWritten
    width and height
    uint64 contentGeneration
    uint64 historyEpoch
    uint64 frameSerial

contentGeneration fingerprints the reservoir ABI, enabled family/backend,
proposal and transport policy, material policy, and output resolution. It
deliberately excludes live scene/geometry/material/texture/light publications,
route availability, range/count values, cameraProjection and
cpuUploadGeneration because all may change during an ordinary frame or portal
package transition. Current-domain replay and stable identity remapping own
those live changes.

frameSerial is a host-only serial incremented by every production full-frame
D0 publication. An admitted history page must be exactly current.frameSerial-1.
It is not packed into the reservoir and costs no GPU memory or bandwidth. This
closes the otherwise silent case where a stale physical page still matches the
extent, generation and epoch but belongs to N-2 or earlier.

historyEpoch is a full-width monotonic host token published by frame resources.
It advances on explicit output/scene/primary-history invalidation. Zero is
reserved for unpublished state. RT_FRAME_RESET_CAMERA_CUT is reserved for the
UPT-07 cut detector or an explicit game-owned cut signal; ordinary camera motion
must not set it. UPT-06 does not pretend that cameraProjection is a cut serial.

When the observed epoch changes, both metadata records are invalidated. Neither
buffer is cleared. After a production full-frame D0 dispatch, page 0 alone is
published fully written with the current generation and epoch. Partial proof
stages 7 and 8 never publish full coverage. R0 rejects page 0 unless its metadata
matches the current extent and epoch.

Page-role schedules
-------------------

No reuse:

    page 0 <- initial
    resolve <- page 0
    page 1 metadata remains invalid

Temporal only:

    roles flip once per fully published D0 frame
    current <- initial
    temporal reads current plus history and writes current in-place
    resolve <- current
    current becomes next history

If temporal setup or descriptor admission skips after D0 completed, the fresh
D0 current page is still promoted. The caller publishes the matching canonical
primary surface every frame; retaining the old reservoir history in that case
would pair frame N-2 reservoirs with frame N-1 surfaces on the next frame.

The in-place temporal write remains gated on proving that an invocation never
reads another current pixel after it may have been overwritten. Previous
history neighborhood reads always use the other physical page.

Spatial only:

    page 0 <- initial
    page 1 <- spatial(page 0)
    resolve <- page 1

Temporal plus spatial:

    page 0 <- initial
    page 0 <- temporal(page 0 current, page 1 previous history)
    full UAV barrier
    page 1 <- spatial(page 0)
    resolve <- page 1
    page 1 is already next history; physical roles do not flip

The invariant is publication pairing, not successful reuse: after every
full-frame D0, the reservoir page made available as next history must describe
the same rendered frame as the canonical primary-surface page published by the
caller. A failed D0/proof-stage frame has no publication and cannot change
roles. A spatial publication already lands in the history role. Otherwise every
completed D0 frame promotes the current page whether T0 ran, skipped, or was
disabled. D0 now consumes the previous page for its bounded emissive
previous-best proposal, so this role advance is required even in the
temporal-off/spatial-off acceptance configuration.

Every admitted producer must cover its full output domain with selected,
count-only, or canonical-empty records. No invalidation path may clear a page.
No third full-resolution reservoir is justified by these schedules.

Runtime acceptance
------------------

Use the normal UPT route with proofStage 9. The first enable must report:

    allocated pages 0+1 ... totalBytes=... page1Clear=never
    history metadata invalidated ... pageClear=none
    page metadata page0(...)=... page1Full=0 ... pages=2

Map/world reset and resize must advance the epoch and print metadata
invalidation without a page clear. Ordinary camera movement and a portal scene
package retirement/commit must not print invalidation: the old package remains
alive through deferred retirement and stable identities are remapped into the
new publication.
The resolved image must remain equivalent to UPT-05 because count-only records
have no selected contribution.

Observed acceptance, 2026-08-03
--------------------------------

The requested 2560 x 1440 full-frame unified configuration reported:

    history metadata invalidated epoch=4 reasons=0x00000000 pageClear=none
    allocated pages 0+1 ... bytes/page=235929600
        totalBytes=471859200 stride=64 page1Clear=never
    page metadata page0(full/generation/epoch)=1/.../4
        page1Full=0 clears(allocation/invalidation)=1/0 pages=2
    proofStage=9 reached=full-frame-dispatch

Ordinary camera movement did not print another history invalidation. This
accepts the UPT-06 allocation, full-coverage publication, no-clear invalidation,
and camera-motion gates. Reload/resize epoch advancement remains a regression
case, not a prerequisite for starting the first bounded UPT-07 shader slice.

The same validation-layer run exposed a separate compiler/device mismatch.
Slang lowered f32tof16/f16tof32 storage helpers into native SPIR-V %half and
%ushort types and declared OpCapability Float16 and Int16, while the Vulkan
device did not enable shaderFloat16 or shaderInt16. The shaders happened to run
on the test GPU, but that was invalid Vulkan and is not accepted proof.

The compact receiver, geometry, and light layouts remain byte-identical. Their
binary16 helpers now emit GLSL.std.450 PackHalf2x16/UnpackHalf2x16 with only
32-bit inputs/results. The build rejects native Int16/Float16 capabilities or
16-bit SPIR-V types in the compact production D0 and both pack passes. Enabling
broader device features was deliberately rejected because no UPT buffer or
algorithm requires native 16-bit arithmetic or storage.

UPT-07 boundary
---------------

UPT-07 owns the first temporal shader, prior-primary receiver admission,
reprojection/compatibility, explicit camera-cut observation, history page role
flip, and history candidate math. It must consume the host metadata before any
per-pixel history load and must not add a clear or a third page.

The implemented ownership/merge provider is recorded in
21_upt07_temporal_contract_slice.txt. It assigns packed word0 bit 2 as a
reservoir-local needs-rescue marker for non-selected records, fixes packed
word11 as finalized mean source weight for reuse, admits direct analytic and
emissive current-domain shift/replay plus one winner-only visibility ray, and
retains this UPT-06 page/serial/no-clear contract unchanged.

D0 previous-best ownership amendment, 2026-08-08
------------------------------------------------

UPT-04 D0 now reads the existing history page, matching previous canonical
primary receiver, compact32 sidecar when applicable, and stable light remap.
No page, clear, copy, or full-frame side buffer was added. The prior page is
admitted only when extent, content generation, history epoch, and published
frame serial match exactly. Allocation and invalidation remain metadata-only;
the two-page ceiling is unchanged.
