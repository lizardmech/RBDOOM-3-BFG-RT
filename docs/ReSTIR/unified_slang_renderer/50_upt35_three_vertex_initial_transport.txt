UPT-35 / UPT-10A: bounded three-vertex initial transport
===========================================================

Status
------

Implemented, built, statically verified and runtime accepted as a D0-only
specialization. The accepted `uptf2` one-continuation temporal/spatial
renderer remains unchanged.

Reference terminology and exact workload
----------------------------------------

The locally vendored NVIDIA FullSample performance presets use:

    restirPT.initialSampling.maxBounceDepth = 3
    enableRussianRoulette = true
    russianRouletteContinueChance = 0.8

The reference initial path tracer starts at bounceDepth 2 and does not run
roulette at that first continuation. With maxBounceDepth 3, its exact workload
after the primary receiver is:

    x1 -> x2 continuation                      always eligible
    NEE at x2                                  eligible
    roulette before x2 -> x3                  q = 0.8
    x2 -> x3 continuation                      only on survival
    emissive endpoint at x3                    eligible
    NEE at x3                                  rejected (path length 4)

In rbdoom terms this is `maxContinuationRaysAfterReceiver = 2`. It is not
three continuation rays and does not add a second light-candidate loop.

First implementation boundary
-----------------------------

The first candidate extends only the accepted split-initial indirect shader
with native geometry, compact32 receivers and compact64 lights. It adds:

    one secondary-surface BSDF sample at x2
    one fixed q=0.8 roulette draw at path vertex 1
    at most one x2 -> x3 closest-hit RayQuery
    one x3 endpoint proposal streamed into the same reservoir

The existing x1 direct proposal, x1 -> x2 endpoint proposal and x2 NEE proposal
are unchanged. No x3 NEE proposal is generated. The accepted one-continuation
shader remains a separate artifact and pays no instruction, binding, payload,
buffer, clear or pipeline cost for this feature.

The new endpoint is encoded as:

    eventKind                         4 (BSDF endpoint)
    pathLength                       2
    reconnectionVertexLength         1
    accumulatedRouletteProbability  0.8

This does not collide with the existing x2 NEE sample because that sample has
eventKind 1 or 2. The 64-byte reservoir ABI already stores all required fields.
No persistent field or descriptor binding is added.

Roulette and reservoir math
---------------------------

On survival:

    pathThroughput *= secondaryBsdfThroughput / q
    pathPdf        *= secondaryBsdfPdf * q
    accumulatedRouletteProbability *= q

The physical endpoint contribution contains the `1/q` compensation. Matching
the NVIDIA reference target convention, the stored target excludes roulette:

    rawTarget   = max(contribution)       // contains 1/q
    target      = rawTarget * q
    proposalPdf = q
    streamMass  = target / proposalPdf = rawTarget

Thus a survived execution contributes the compensated mass while its selected
target does not double-count roulette. Across executions, survival probability
q times contribution divided by q preserves the no-roulette expectation.
Roulette termination creates no reservoir candidate and emits no ray.

Reuse boundary
--------------

Current UPT temporal replay accepts only the x2 endpoint form
`eventKind=4,pathLength=1` and x2 NEE forms `eventKind=1/2,pathLength=2`.
It deliberately rejects `eventKind=4,pathLength=2`. Therefore UPT-35 is
effective only with temporal and spatial disabled. Extending T0/S0 is a later
task after D0 energy, identity and performance are accepted; reuse may not
guess a one-continuation interpretation for the new endpoint.

Ray/work ceiling
----------------

Per receiver, including the existing direct proposal, the specialization is
bounded to:

    continuation RayQueries <= 2
    visibility RayQueries   <= 2
    total RayQueries        <= 4

There is no loop with a runtime maximum, no wavefront queue, no per-frame
full-buffer clear and no new full-resolution allocation.

Validation gates
----------------

Offline:

    one-continuation artifacts remain byte-identical
    new shader has the existing descriptor layout and push-constant ABI
    static RayQuery sites match two continuations plus one x2 NEE visibility
    no TraceRay instruction exists
    q=1 CPU oracle matches no-roulette energy exactly
    q=0.8 oracle proves unbiased survival compensation and target convention

Runtime, with temporal and spatial disabled:

    requested/effective gate reports 1/1
    x3 emissive contribution appears without white/color corruption
    no ghost emitters, missing geometry or alpha-clip regression
    emissive-disabled and analytic-only scenes remain finite
    direct and one-continuation D0 output remain unchanged when disabled
    measured cost is consistent with one additional stochastic continuation

Only after these gates pass may temporal/spatial replay for the new endpoint be
designed. The accepted `uptf2` baseline remains the rollback configuration.

Runtime gate
------------

Run `exec uptb2`. Require:

    three-vertex initial requested/effective=1/1
    split indirect ... threeVertex=1 continuationRaysMax=2 rouletteQ=0.80

Temporal and spatial must report disabled. Compare image and D0 cost directly
against `exec uptf2` only after setting temporal/spatial to zero there as well,

Runtime result
--------------

The user ran `exec uptb2`; the three-vertex specialization activated and
worked without visual, stability or geometry issues. Treat the bounded D0
transport, fixed-q roulette compensation and x3 endpoint admission as runtime
accepted. This acceptance does not yet admit `eventKind=4,pathLength=2` into
temporal or spatial reuse; those passes remain deliberately disabled until
their two-continuation shift/replay contract is implemented and verified.

UPT-50 correction: complete x3 NEE, 2026-08-15
------------------------------------------------

The earlier workload interpretation above was incomplete. Direct source
comparison with NVIDIA FullSample's `RAB_PathTrace` / `handleHit` loop proves
that every accepted surface hit evaluates both terminal emission and NEE
before the next continuation decision. Consequently max bounce depth 3 adds:

    x2 -> x3 continuation
    x3 emissive endpoint
    x3 NEE selected from the bounce-index-3 light schedule

The former UPT specialization implemented only the first two lines. That made
the extra bounce useful only when x3 happened to land directly on emissive
geometry and explains why changing from two to three vertices barely changed
indirect sparsity. This was a base-estimator completeness defect, not evidence
that NEE cache or portal filtering was required.

The corrected specialization now runs an independent inner RIS at x3 using
the existing inverse-square schedule. With primary parity counts of 32
analytic and one emissive trial, x2 receives at most 8+1 trials and x3 receives
at most 3+1; 32 is not the per-bounce indirect count. Only the selected x3
light receives a visibility query. The selected stable light identity and
sample coordinates use the existing 64-byte reservoir ABI.

Corrected bounded ceiling:

    continuation RayQueries <= 2
    visibility RayQueries   <= 3
    total RayQueries        <= 5

There is no NEE cache, new descriptor, full-resolution allocation, queue or
per-frame clear. The Vulkan verifier now requires four static RayQuery sites,
an x3 `pathLength=3` light topology, winner-only visibility and zero TraceRay
sites. T0/S0 support is defined by the corresponding corrections in 51/53.
