What D0b taught that does / does not copy
-----------------------------------------
Megakernel I-fetch (sibling split)
  D0b was 5.5 ms / 8% RTCORE / 57% NI with bounce+OpenPBR+replay+vis+x3
  in one 8x8. D0a is already split-direct: pick + one vis ray, 14.6% NI.
  A 64x1 sibling for D0a would likely add overhead (first Q1 try). Skip.

Replay vs resolved ALU (ReplayFree)
  D0a still calls Upt04EvaluateSelectedLocalLight<TMaterialSet>
  (upt04_initial_direct.slang). With PACKED_LIGHT_RECORD it skips the
  *first* geometry replay (region weights live in the 64 B sidecar) but
  still does ReplayEmissiveTriangleBarycentrics + EvaluateEmissiveEndpoint
  (material sample) per emissive trial.

  When ReplayFree is on for GI, D0b sibling + D0x already use
  Upt56EvaluateResolvedEmissive. D0a does not: there is no
  split_direct_*_resolved.bin, and Upt04SplitDirectShaderPath ignores
  replayFreeSecondaryNee. So stacked ReplayFree leaves primary NEE on
  live UV sampling.

  Direct-only helper Upt04EvaluateSelectedLocalLightDirectOnly is even
  closer to a baked light (one replay, radiance from
  light.radianceAndLuminance). D0a does not call it.

  Easy A/B: light64 split-direct + UPT04_REPLAY_FREE_SECONDARY_NEE=1,
  select it when compactLights && ReplayFree. Same L0 pack already
  fills slot 36. Expect a smaller win than D0x (~0.5 ms) because D0a
  is already healthy and RIS may mix analytic spheres. Image: same
  four-region vs live UV as GI.

Token / VRAM padding
  D0a writes the 64 B intermediate page only. No W x H 128 B work
  queue. x3 96 B / Q1 112 B does not apply.

Light tiles
  A D0a tiles blob exists. InputsValid forbids tiles with compactLights
  and with 3-vtx Q1+Q2. Not an uptx A/B.

OnePath
  D0a does not decode GI hits; primary is compact32 TEX. OnePath is a
  D0b geometry lever.

Do not
  pin anything on D0a
  split D0a into a sibling
  resume Track B / noinline / unroll because D0a NI is 14.6%
  turn LightTiles on this stack
