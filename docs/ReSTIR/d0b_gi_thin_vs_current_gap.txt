Thin produce vs current X produce — gap, not NEE cache
======================================================

Date: 2026-08-20
Status: diagnosis only. No shader/host change in this note.

NEE cache is the wrong lever for low RT utilization.
Legacy NEECACHE-01 was a quality prepass. RTXDI FullSample
has none. UPT NeeCache is the same ABI reader, not a new
cache, and empty-cell fallback is Q1 — same estimator.

The gap is the inlined GI body in the same 8x8
----------------------------------------------
Produce still does, in one kernel:
  1. first-bounce ray + closest-hit RayQuery
  2. one-path hit decode
  3. OpenPBR + 11 texture samples (inlined)
  4. Q1 light pick + emissive replay/geometry still referenced
  5. NEE visibility RayQuery (the second init/proceed)
  6. x3 prepare + queue write
  7. ~18x the NaN/Inf guards of thin, minced through the body

FullSample PT indirect is *larger* (23748 ops, 31 img, 5 rq)
with 4.2% NI. Size is not the mechanism. Their dead code is
contiguous; ours is interleaved with the hot path (GCC I-fetch
still ~21% of L2).

Do not
------
  treat NEE cache as the RT-util fix
  more stride / LSU / extra TEX pages for lights or X3
  pin NeeCache
  resume register-cut / Enhanced T/S / noinline / unroll
