SCOPE

CURRENT RASTER JOINT PRODUCER
-----------------------------
R_SetupDrawSurfJoints is the draw-surface producer:

  neo/renderer/tr_frontend_addmodels.cpp

For a surface with staticModelWithJoints and r_useGPUSkinning=1 it:

  reads the current instance model's jointsInverted/numInvertedJoints;
  allocates that exact byte range with vertexCache.AllocJoint when the cached
    handle is not current;
  stores the returned vertCacheHandle_t in drawSurf_t::jointCache.

The handle encodes:

  frontend frame number;
  byte offset;
  byte size;
  static/dynamic storage class.

The normal animated path uses frameData[listNum].jointBuffer. BeginBackEnd
unmaps the written frame, moves listNum to drawListNum, increments
vertexCache.currentFrame, and maps the next frontend slot. The backend accepts
only a handle whose frame equals currentFrame-1.

Vertex-cache facts:

  NUM_FRAME_DATA = 3;
  allocation alignment = uniformBufferOffsetAlignment;
  idJointMat size/layout = three float4 rows, 48 bytes;
  the NVRHI joint buffer is a structured buffer with structStride=16 bytes;
  dynamic joint storage is CPU mapped for frontend writes and GPU readable
    after BeginBackEnd unmaps it;
  PathTracePrimaryPass executes in DrawViewInternal on the backend after this
    handoff and before the same draw surfaces are rasterized.

RenderBackend_NVRHI resolves the same jointCache handle to:

  vertexCache.frameData[drawListNum].jointBuffer.GetAPIObject();
  byte offset extracted from the handle.

This is renderer-authoritative current-pose data. GEO-07 must stop recovering
the pose through staticModelWithJoints->jointsInverted when its new gate is
active.

CURRENT PT SKINNING ROUTE
-------------------------
The existing r_pathTracingGpuSkinning modes are diagnostic/cutover scaffolding:

  mode 0:
    capture CPU pre-skins and feeds the merged dynamic BLAS;

  mode 1:
    capture still CPU pre-skins;
    CPU code copies current joint matrices into a PT buffer;
    compute writes a separate diagnostic output;

  mode 2:
    capture still CPU pre-skins;
    the same CPU-copied joints drive compute;
    compute overwrites the merged dynamic vertex range before BLAS build.

Therefore mode 2 proves compute ordering and numerical parity but is not
authoritative jointCache consumption and does not remove CPU skinning cost.

The current retained temporal bridge is also not authoritative:

  m_smokePreviousSkinnedSurfaceRecords;
  m_smokePreviousSkinnedVertexData;
  m_smokePreviousSkinnedJointMatrices.

All three are process-global PathTracePrimaryPass members overwritten after
every 3D view. geometry_geo18 proved that a subview which omits a Fatzombie can
erase its primary-view record. GEO-07 must not use that bridge for authoritative
previous output.

DIRECT BINDING VERSUS STAGED COMPACT ARRAY
-------------------------------------------
Direct binding is technically possible but rejected for the first cut:

  the raster buffer's structured stride is 16 bytes while the existing PT
    shader's PathTraceSkinnedJointMatrix stride is 48 bytes;
  direct use would require a shader ABI/resource-type change and row-addressed
    absolute offsets;
  it exposes the entire frame joint allocation to every job;
  current storage is only one vertex-cache frame slot, while previous skinning
    must survive under an explicit logical history owner;
  a direct current binding does not solve previous-pose ownership.

Selected design: staged compact joint array.

For every accepted job, resolve jointCache with vertexCache.GetJointBuffer on
the backend, then enqueue a same-command-list GPU buffer copy:

  source:
    renderer vertex-cache joint buffer;
  source offset:
    resolved joint subrange offset;
  size:
    jointCount * sizeof(idJointMat), required to equal the handle range;
  destination:
    compact PT-owned current-joint buffer;
  destination offset:
    checked append allocation in 48-byte matrix units.

Benefits:

  consumes the renderer-authoritative GPU-visible bytes;
  performs no CPU pose read/copy;
  preserves the already-validated 48-byte PT shader ABI;
  bounds each job to its declared joint range;
  stays on the same command list before skinning dispatch and BLAS work;
  permits the compact buffer to become owner-keyed previous input next frame.

The cost is one bounded GPU copy per distinct staged joint range. GEO-07 must
measure copy count/bytes/time; deduplication is allowed only for identical
jointCache subranges belonging to the same live instance. No cross-instance or
per-model pose sharing is allowed.

AUTHORITATIVE JOB CONTRACT
--------------------------
Each candidate job must contain value-owned metadata only:

  PtCanonicalHistoryOwnerKey historyOwner;
  PtCanonicalInstanceKey instance;
  PtCanonicalMeshKey sourceMesh;
  uint32 modelSurfaceIndex;
  uint64 jointCacheHandle;
  uint64 jointSourceByteOffset;
  uint64 jointByteCount;
  uint32 jointCount;
  uint64 sourceVertexOffset/count;
  uint64 outputVertexOffset/count;
  uint64 previousOutputOffset/count or invalid;
  current and previous object-to-world rows;
  terminal funnel result and history-invalid reason.

Acceptance requires:

  a valid primary history owner;
  a valid canonical skinned instance/source binding;
  r_useGPUSkinning=1;
  current jointCache handle resolves to the backend draw-list joint buffer;
  handle byte size equals jointCount * 48 without overflow;
  every source joint index is below jointCount;
  immutable source and mutable output ranges pass checked 64-bit bounds;
  current and previous state belong to the same history owner.

Subview policy for the first cut:

  subviews may skin current geometry for their own rendering;
  they must not read or overwrite PrimaryGameplay previous state;
  until a durable Subview owner producer exists, previous motion is invalid for
    subview jobs rather than borrowed from the primary view.

  exact == 1

SLICE 5 ENTRY RECONCILIATION (2026-07-25)
-----------------------------------------
The original slice-5 sentence says to allocate per-instance mutable output
ranges and source them from GEO-06 immutable records. The live contracts do
not yet permit that:

  PtGeometrySourceRegistry::Observe accepts only:
    sourceDomain = RegisteredRenderModel
    deformationClass = Rigid

  PtGeometryLifecycleWorldRegistry::ObserveImmutableSource explicitly counts
  SkinnedBindSource/Skinned observations as sourceSkinnedNegative and returns.
  Its reason is still valid: the resolved frontend surface is an animated MD5
  snapshot, not proven immutable bind data.

  GEO-06 runtime acceptance deliberately treats skinned observations as
  negative controls. Its GPU source pools therefore contain no canonical
  skinned bind-source record to resolve today.

The current GPU-skinning scaffold instead:

  reads tri->verts while building the current frame;
  repacks PathTraceSkinnedSourceVertex for every eligible record every frame;
  concatenates output offsets in current capture order;
  owns one monolithic current-output buffer;
  has no persistent full-InstanceKey range allocation or retirement contract.

Different actors currently receive different concatenated offsets by
construction, but that is an incidental frame layout, not the required
per-instance ownership proof. Coding the old slice-5 wording directly would
either fail every canonical source lookup or silently keep the transient
tri->verts bridge while claiming GEO-06 ownership.

Revised implementation order:

  5A. Resolve each SkinnedSurface InstanceKey through the imported GEO-04/05
      identity binding to its SkinnedBindSource MeshKey. Admit a value-owned
      bind/source payload only after proving its producer is source pose, not
      an animated snapshot. Require stable checksum across animation and one
      shared source checksum for duplicate MD5 instances.

  5B. Add a checked mutable-output allocator keyed by the full InstanceKey.
      Same-instance reuse is allowed; cross-instance alias is forbidden even
      for one shared MeshKey. Define growth generation, in-flight retirement,
      removal and entity-slot generation behavior in a pure CPU harness.

  5C. Route comparison dispatches from the immutable source record to the
      distinct mutable range. Prove two Fatzombies share the source but have
      non-overlapping output offsets. CPU pre-skinning and live BLAS traversal
      remain unchanged.

This is a validated correction to the proposed plan, not permission to widen
GEO-06's accepted rigid route implicitly.

SLICE 5B FULL-INSTANCE MUTABLE-OUTPUT ALLOCATOR (2026-07-25)
------------------------------------------------------------
Added a behavior-neutral planning allocator:

  neo/renderer/NVRHI/PathTraceSkinnedOutputAllocator.h/.cpp

Ownership and range rules:

  only a valid SkinnedSurface PtCanonicalInstanceKey is eligible;
  the allocator world must equal the key's worldGeneration;
  same full InstanceKey plus the same vertex count reuses the exact range;
  different InstanceKeys always append distinct ranges, even when their
    MeshKeys/source records are identical;
  a vertex-count change appends a replacement and increments that instance's
    allocation revision; old bytes are not silently reused;
  an exact identity Remove retires the range and the retired key cannot
    resurrect;
  reusing a render-def slot requires a new renderDefGeneration and therefore a
    new full key/range;
  world replacement retires the active storage generation and clears all keys.

Storage and lifetime rules:

  offsets/counts/byte ranges use checked uint64 arithmetic;
  shader-visible counts are bounded to uint32;
  capacity grows geometrically only up to the configured maximum;
  a growth preserves live offsets but creates a new monotonic storage
    generation;
  the old storage generation enters a pending-retirement list;
  no pending generation is released until the caller explicitly acknowledges
    that generation as completed;
  retired/resize ranges are tombstoned rather than reused in the same storage
    generation.

This defines the ownership and in-flight contract without pretending a CPU
frame age is a GPU completion fence. Slice 5B owns only planner state. It does
not allocate an NVRHI output buffer, change dispatch offsets, alter the current
monolithic GPU output, skip CPU skinning, or change BLAS traversal.

The live shadow integration:

  begins/resets by the lifecycle CanonicalWorldKey;
  consumes exact SkinnedSurface Remove operations from the imported identity
    transport snapshot;
  admits a range only after the active InstanceKey resolves to the exact
    slice-5A SkinnedBindSource/Skinned record with matching vertex count and a
    nonzero checksum;
  reports full-key ranges, source sharing, pairwise overlap, storage generation
    and pending-retirement counts in the existing one-shot GEO-07 dump.

SLICE-6 ENTRY AUDIT - DEPENDENCY CORRECTION
-------------------------------------------
The proposed standalone CPU pre-skin-removal slice is not viable.

The exact live producer/consumer chain is:

  AppendSmokeSurfaceGeometry
    -> BuildSmokeSurfaceVertexFromSource
       applies joint matrices and object-to-world on the CPU
    -> dynamicVertexData
    -> smokeDynamicVertexBuffer upload
    -> merged smokeDynamicBlas build
    -> live TLAS instance 1 traversal.

The accepted mode-1 compute route instead writes:

  m_smokeSkinnedCurrentOutputVertexBuffer

That buffer ends in ShaderResource state and no BLAS descriptor references it.
The current per-instance allocator supplies vertex ranges only; source indexes
remain in the canonical GEO-06 GPU index pool.

Consequences:

  - skipping BuildSmokeSurfaceVertexFromSource's joint transforms while leaving
    traversal unchanged makes the merged BLAS consume bind-pose positions;
  - leaving zero/placeholders is worse because the BLAS remains live;
  - redirecting the BLAS to the new output is a GEO-08 traversal promotion,
    explicitly forbidden by the old GEO-07 guardrail;
  - `dispatchedGpu` is finalized after capture and does not by itself provide a
    same-frame CPU fallback if a later resource/binding failure occurs;
  - posed positions are also used during capture for zero-area rejection and
    attribute diagnostics, so the capture split needs an explicit replacement
    contract rather than simply bypassing four transform calls.

Validated first GEO-08 input shape:

  vertex buffer:
    per-instance output buffer, PathTraceSmokeVertex stride 112
  vertex offset:
    PtSkinnedOutputRange.vertexOffset * 112
  vertex count:
    exact canonical mesh vertexCount
  index buffer:
    canonical GEO-06 source index pool
  index offset/count:
    exact PtGeometryGpuPoolRecord index range
  transform:
    identity in the first cut because the compute output is world-space
  build flags:
    AllowUpdate + PreferFastBuild; PerformUpdate only after an initial build
  ordering:
    joint copy -> skin dispatch -> UAV/AS barrier -> BLAS build/update -> TLAS
  invalidation:
    full InstanceKey, output storage generation/range, source checksum and GPU
    pool generation, topology, and explicit rebuild cadence

Revised disposition:

  GEO-07 is accepted as the numerically validated renderer-joint-to-distinct-
  instance-output producer. The Phase C requirement to remove CPU pre-skinning
  is not waived. It moves to the GEO-08 live traversal cutover, after a
  comparison route proves hit identity, primitive/material addressing, motion,
  lifecycle and rollback. Structural failures remain on same-frame CPU capture.
  Late failures after CPU capture is skipped require an explicitly validated
  prior-pose hold or route suppression; they cannot honestly claim CPU fallback
  and may never expose bind-pose or zero sentinel output.
