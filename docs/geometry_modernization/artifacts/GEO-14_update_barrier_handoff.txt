GEO-14 Vulkan skinned UPDATE barrier handoff
================================================

SCOPE
-----
This checkpoint identifies the first concrete Vulkan contract mismatch behind
the revoked per-instance skinned BLAS route. It adds and measures a full-BUILD
control, repairs the NVRHI Vulkan UPDATE state transition, and leaves both the
comparison route and capture split default off.

This is not final GEO-14 promotion. The full GEO-09 consumer/lifecycle matrix
and a longer human visual traversal still remain before either default changes.

VULKAN CONTRACT MISMATCH
------------------------
NVRHI's Vulkan `buildBottomLevelAccelStruct` selected UPDATE mode and set the
same acceleration structure as source and destination, but automatic state
tracking required only `AccelStructWrite` for its backing buffer.

That is incomplete for UPDATE:

  - Vulkan UPDATE reads the prior BLAS as the source;
  - the state therefore needs AS-build read access as well as write access;
  - when comparison BLASes are excluded from the TLAS, the backing buffer can
    remain in the same write state across frames;
  - same-state tracking emits no new dependency, so a later UPDATE can read a
    prior UPDATE result without an AS-build write-to-read barrier.

This exactly matches the historical failure boundary: device removal remained
possible with zero skinned descriptors submitted to the TLAS, so the fault did
not require a hit shader or traversal consumer.

FIX
---
For Vulkan PerformUpdate only:

  1. require `AccelStructBuildBlas` on the prior BLAS backing buffer;
  2. commit that AS-build write-to-read dependency;
  3. require `AccelStructBuildBlas | AccelStructWrite`;
  4. commit before vkCmdBuildAccelerationStructuresKHR.

Full BUILD behavior is unchanged. Vertex/index build-input state remains under
the existing automatic barrier path. No shader, descriptor, SBT, payload,
geometry-storage, or route ABI changes.

PERFORMANCE DISPOSITION
-----------------------
The barriered path is roughly 0.58 ms slower than the historical unbarriered
UPDATE median because the generic NVRHI entry point commits source-read and
combined read/write transitions per BLAS. It remains about 3.8 ms faster than
the full-BUILD control and, with capture split enabled, removes the measured
CPU skinned append work.

Do not optimize this by deleting either dependency. A later GEO-14 slice may
batch the state transitions and build submissions, but only if it preserves
the now-explicit prior-write -> source-read -> destination-write contract.
