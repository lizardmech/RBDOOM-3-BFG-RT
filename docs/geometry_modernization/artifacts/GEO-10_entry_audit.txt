GEO-10 ENTRY AUDIT AND STEP 1/2 CHECKPOINT
==========================================

DATE
----
2026-07-26

SCOPE
-----
This checkpoint validates and implements only deterministic static bucket
identity and exact surface/primitive assignment. It does not change production
BLAS construction, TLAS membership, shader routing, or the monolithic rollback
path.

ENTRY CONTRACT TRACE
--------------------
The production path still owns one static vertex/index/triangle-metadata pool,
one static BLAS, and TLAS instance 0. The existing static-bucket planner was
being fed one observation per persistent surface while:

  monolithicStaticBlas              = true
  shaderSupportsStaticBucketRoutes  = false

Those observations were planning diagnostics, not real bucket BLAS ownership.
The current shader contract also treats InstanceID 0 as the only static route.
Therefore merely enabling the existing planner would mismatch BLAS primitive
locality, triangle metadata, and the rigid/skinned InstanceID namespace.

AUTHORITATIVE PORTAL-AREA OWNER
-------------------------------
BoundsInAreas, centerArea, and offCenterArea are useful selection evidence but
are not the authored owner. idRenderWorldLocal::AddWorldModelEntities creates
one static model named `_areaN` for each portal area and explicitly links that
entity to area N. GEO-10 now parses this exact model identity and persists N on
each static geometry record.

Malformed, missing, or out-of-world `_areaN` identities use the explicit
fallback area -1. They are counted and remain assigned; they are never silently
dropped.

STEP 1/2 IMPLEMENTATION
-----------------------
BuildSmokeStaticBucketAssignmentPlan is CPU-only and owns no renderer pointers
or GPU handles. Its bucket tuple is:

  world generation
  portal area
  deterministic size-split index
  source generation
  storage generation

Within an area it sorts by stable surface key and source ranges, then greedily
splits against independent vertex, index, and triangle limits. A surface larger
than a limit receives its own explicitly oversized bucket. Invalid-area
surfaces enter the fallback bucket. Invalid ranges and duplicate surface keys
fail exact coverage and are counted.

Each accepted surface produces exactly one assignment. The assignment records
its bucket, source range, and bucket-local primitive offset. The resulting
signature is independent of producer enumeration order and changes with the
bucket generations.

The legacy persistent-cache lookup key is not used as bucket identity. A first
step-3 run proved it could change between fresh processes even when every
generation and geometry count was identical. Static records now retain a
separate authored key derived from model name, entity/surface ordinal, material
name, and geometry shape. The legacy key remains untouched for cache lookup and
GEO-02 rollback behavior.

The diagnostic limits are currently:

  vertices   65,536
  indexes   196,608
  triangles  65,536

They are split thresholds, not admission caps. The one-shot command is:

  r_pathTracingGeometryStaticBucketAudit 1

It is shadow-only and resets itself after printing the summary and at most 16
bucket samples.

STEP 3 SHADOW GEOMETRY
----------------------
BuildSmokeStaticBucketGeometryPack copies each assigned full-fidelity source
range into deterministic bucket-local order. It:

  copies PathTraceSmokeVertex bytes without format conversion;
  rebases each absolute source index into the packed vertex pool;
  requires every index to remain inside its source surface vertex range;
  copies triangle class and material IDs exactly;
  emits surface key, source-record index, and source-local primitive index for
  every packed triangle;
  records 64-bit vertex, index, and triangle-metadata byte ranges per bucket;
  rolls back an entire bucket on any invalid assignment or topology range.

The standalone harness proves exact copying, rebasing, material/class identity,
surface-local primitive identity, producer-order independence, bad-index
rejection, and local-primitive-offset rejection.

STEP 4 RESIDENT GPU STORAGE AND BLAS OWNERSHIP
----------------------------------------------
The resident source is deliberately separate from the selected/pruned
production cache. RtPathTraceSceneUniverse builds every authored static-world
surface into a cap-free full-map RtSmokeGeometryUniverse. The old monolithic
compile-time cap is not consulted and rigid objects are not folded into this
static owner.

The resident universe persists across portal changes and is cleared on the
normal map/resource-reset path. Each frame's portal selection produces a
separate active-area mask; fallback-area records remain active rather than
being silently lost. Assignment and packing use the resident storage
generation while active membership may change without repacking or rebuilding
unchanged BLASes.

One shared packed GPU pool owns:

  PathTraceSmokeVertex bytes;
  absolute packed indexes;
  triangle class IDs;
  triangle material IDs;
  surface/source/local-primitive identity tuples.

Every bucket owns one BLAS descriptor and handle over its exact index slice.
Packed indexes remain absolute, so BLAS vertexOffset is zero and indexOffset is
the bucket's 64-bit packed byte offset. Content and backing-buffer identities
form the BLAS input signature. Changed storage retires/recreates the affected
record; unchanged records reuse their handle and build state.

The safe shadow controls are:

  r_pathTracingGeometryStaticBucketBlas 1
  r_pathTracingGeometryStaticBucketBlasBuild 1
  r_pathTracingGeometryStaticBucketBlasBuildLimit 2
  r_pathTracingGeometryStaticBucketBlasForceRebuild 0
  r_pathTracingGeometryStaticBucketPortalSteps 1

Both resource/build gates default off. The build limit is per frame; zero is
uncapped. No bucket BLAS is inserted into the production TLAS.
