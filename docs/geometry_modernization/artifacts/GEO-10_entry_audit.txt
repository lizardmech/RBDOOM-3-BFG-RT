GEO-10 ENTRY AUDIT AND STEP 1/2 CHECKPOINT
==========================================

DATE
----
2026-07-26

SCOPE
-----
This checkpoint validates and implements only deterministic static bucket
identity and exact surface/primitive assignment. It does not change production
BLAS construction, TLAS membership, shader routing, or the monolithic rollback
path.

ENTRY CONTRACT TRACE
--------------------
The production path still owns one static vertex/index/triangle-metadata pool,
one static BLAS, and TLAS instance 0. The existing static-bucket planner was
being fed one observation per persistent surface while:

  monolithicStaticBlas              = true
  shaderSupportsStaticBucketRoutes  = false

Those observations were planning diagnostics, not real bucket BLAS ownership.
The current shader contract also treats InstanceID 0 as the only static route.
Therefore merely enabling the existing planner would mismatch BLAS primitive
locality, triangle metadata, and the rigid/skinned InstanceID namespace.

AUTHORITATIVE PORTAL-AREA OWNER
-------------------------------
BoundsInAreas, centerArea, and offCenterArea are useful selection evidence but
are not the authored owner. idRenderWorldLocal::AddWorldModelEntities creates
one static model named `_areaN` for each portal area and explicitly links that
entity to area N. GEO-10 now parses this exact model identity and persists N on
each static geometry record.

Malformed, missing, or out-of-world `_areaN` identities use the explicit
fallback area -1. They are counted and remain assigned; they are never silently
dropped.

STEP 1/2 IMPLEMENTATION
-----------------------
BuildSmokeStaticBucketAssignmentPlan is CPU-only and owns no renderer pointers
or GPU handles. Its bucket tuple is:

  world generation
  portal area
  deterministic size-split index
  source generation
  storage generation

Within an area it sorts by stable surface key and source ranges, then greedily
splits against independent vertex, index, and triangle limits. A surface larger
than a limit receives its own explicitly oversized bucket. Invalid-area
surfaces enter the fallback bucket. Invalid ranges and duplicate surface keys
fail exact coverage and are counted.

Each accepted surface produces exactly one assignment. The assignment records
its bucket, source range, and bucket-local primitive offset. The resulting
signature is independent of producer enumeration order and changes with the
bucket generations.

The legacy persistent-cache lookup key is not used as bucket identity. A first
step-3 run proved it could change between fresh processes even when every
generation and geometry count was identical. Static records now retain a
separate authored key derived from model name, entity/surface ordinal, material
name, and geometry shape. The legacy key remains untouched for cache lookup and
GEO-02 rollback behavior.

The diagnostic limits are currently:

  vertices   65,536
  indexes   196,608
  triangles  65,536

They are split thresholds, not admission caps. The one-shot command is:

  r_pathTracingGeometryStaticBucketAudit 1

It is shadow-only and resets itself after printing the summary and at most 16
bucket samples.

STEP 3 SHADOW GEOMETRY
----------------------
BuildSmokeStaticBucketGeometryPack copies each assigned full-fidelity source
range into deterministic bucket-local order. It:

  copies PathTraceSmokeVertex bytes without format conversion;
  rebases each absolute source index into the packed vertex pool;
  requires every index to remain inside its source surface vertex range;
  copies triangle class and material IDs exactly;
  emits surface key, source-record index, and source-local primitive index for
  every packed triangle;
  records 64-bit vertex, index, and triangle-metadata byte ranges per bucket;
  rolls back an entire bucket on any invalid assignment or topology range.

The standalone harness proves exact copying, rebasing, material/class identity,
surface-local primitive identity, producer-order independence, bad-index
rejection, and local-primitive-offset rejection.

STEP 4 RESIDENT GPU STORAGE AND BLAS OWNERSHIP
----------------------------------------------
The resident source is deliberately separate from the selected/pruned
production cache. RtPathTraceSceneUniverse builds every authored static-world
surface into a cap-free full-map RtSmokeGeometryUniverse. The old monolithic
compile-time cap is not consulted and rigid objects are not folded into this
static owner.

The resident universe persists across portal changes and is cleared on the
normal map/resource-reset path. Each frame's portal selection produces a
separate active-area mask; fallback-area records remain active rather than
being silently lost. Assignment and packing use the resident storage
generation while active membership may change without repacking or rebuilding
unchanged BLASes.

One shared packed GPU pool owns:

  PathTraceSmokeVertex bytes;
  absolute packed indexes;
  triangle class IDs;
  triangle material IDs;
  surface/source/local-primitive identity tuples.

Every bucket owns one BLAS descriptor and handle over its exact index slice.
Packed indexes remain absolute, so BLAS vertexOffset is zero and indexOffset is
the bucket's 64-bit packed byte offset. Content and backing-buffer identities
form the BLAS input signature. Changed storage retires/recreates the affected
record; unchanged records reuse their handle and build state.

The safe shadow controls are:

  r_pathTracingGeometryStaticBucketBlas 1
  r_pathTracingGeometryStaticBucketBlasBuild 1
  r_pathTracingGeometryStaticBucketBlasBuildLimit 2
  r_pathTracingGeometryStaticBucketBlasForceRebuild 0
  r_pathTracingGeometryStaticBucketPortalSteps 1

Both resource/build gates default off. The build limit is per frame; zero is
uncapped. No bucket BLAS is inserted into the production TLAS.

STEP 5 SHARED ACTIVE PUBLICATION EPOCH
--------------------------------------
The shadow publisher consumes the exact packed bucket records and resident
BLAS state. It hashes the source, storage, material, packed-content, and
active-set identities into a nonzero publication generation. One loop then
creates:

  one identity-transform TLAS instance descriptor per active bucket;
  one checked packed-range route record per stable resident-bucket ordinal;
  identical generation values for TLAS and route publication.

The route record preserves absolute packed vertex/index/triangle offsets,
counts, surface count, bucket key, and the 64-bit publication generation.
The CPU epoch validator requires:

  expected, TLAS, and route generations are all nonzero and equal;
  active bucket and TLAS descriptor counts are equal;
  resident bucket and route record counts are equal;
  active bucket count does not exceed resident bucket count;
  the active set is exact and every active BLAS is ready;
  every packed range is valid and the 24-bit InstanceID namespace fits.

Failure clears both output vectors. There is no partial active publication and
no fallback that inserts inactive resident buckets.

SHADER-ROUTE ABI FOUNDATION
---------------------------
The proposal's packed geometry retained material IDs but did not retain the
material-table index consumed by primary-hit, alpha, decal, liquid, and DI
surface helpers. That would have produced valid geometry with incorrect or
missing materials after cutover.

The corrected shadow ABI binds:

  t83  checked active-bucket route records;
  t84  full-map packed vertices;
  t85  full-map absolute indexes;
  t86  packed triangle class/flags;
  t87  packed triangle material IDs;
  t88  packed triangle material-table indexes.

Each active triangle's material ID is resolved against the current material
table. Any unresolved active index makes publication inexact and clears both
the TLAS descriptor vector and route vector. Inactive resident triangles may
carry the invalid sentinel until their area becomes active; they cannot enter
the published active set.

The material-index and route buffers have a separate upload signature including
packed content, material generation, publication generation, resolved indexes,
and route bytes. Unchanged frames reuse the upload. The primary producer now
declares the exact 48-byte route record ABI, but no bucket instance is yet put
in the production TLAS.

LIVE-CUTOVER FOUNDATION: CHECKED NAMESPACE AND SHARED CLEAN-DI ABI
-----------------------------------------------------------------
The consumer audit rejected shifting rigid and skinned InstanceIDs. Too many
existing primary, any-hit, temporal, clean-DI, and GI helpers assume:

  static       InstanceID 0
  dynamic      InstanceID 1
  rigid        InstanceID 2 + rigid route index
  skinned      after the live rigid route count

Static buckets instead reserve the high 24-bit range beginning at 0x00800000.
This remains below the Vulkan InstanceID limit and does not disturb any current
rigid/skinned identity. Dense route index N maps to InstanceID 0x00800000 + N.

The shader control tuple is:

  x  first InstanceID, exactly 0x00800000
  y  published route count, zero means unavailable
  z  publication generation low 32 bits
  w  publication generation high 32 bits

PathTraceTryLoadStaticBucketTriangleRoute fails closed unless:

  the namespace base, count, and nonzero generation are present;
  the route buffer contains at least the published count at 48-byte stride;
  InstanceID, generation, primitive count, and triangle topology match;
  vertex/index/class/material/material-index ranges do not overflow and fit;
  the packed vertex stride is exactly 112 bytes;
  all three absolute vertex indexes stay inside the bucket's vertex range.

The primary producer keeps t83 through t88. The shared clean-DI sentinel,
initial, temporal, glass, transmission, and compact skinned-hit libraries use
the same six resources at t100 through t105 to avoid the material-feature t87
contract. The clean-DI constant buffer grew from 480 to 512 bytes; the new
uint4 is appended, so every prior field offset is unchanged.

The acceleration submit plan now carries two independent facts:

  hasStaticBlas                 retain/build the rollback BLAS
  includeStaticBlasInTlas       emit monolithic instance 0

It also permits a TLAS containing only extra bucket/rigid/skinned instances.
The CPU harness proves a cached monolithic BLAS can remain owned while instance
0 is excluded and a bucket-only TLAS is submitted. Production explicitly keeps
includeStaticBlasInTlas=true.

PRIMARY HISTORY AND MOTION
--------------------------
The primary motion supplier previously recognized only monolithic instance 0
as static. A bucket hit therefore fell through static snapshot history and
then failed object motion after the bounded rigid/skinned predicates rejected
its high InstanceID.

The primary producer now supplies an entry-specific predicate for checked
bucket IDs. A bucket surface:

  is reported as PT_MOTION_VECTOR_SOURCE_STATIC;
  uses its current immutable world position as previous world position;
  uses the existing previous-camera projection for pixel motion and depth;

PERFORMANCE OBSERVATION
-----------------------

`r_pathTracingGeometryStaticBucketBlas 1` currently has very high CPU overhead.
Although GPU buffers and completed BLASes are reused, the shadow path rebuilds
the full static bucket source, active mask, assignment plan, packed geometry,
and material-index resolution every frame. This is not acceptable steady-state
behavior and no GEO-10 performance claim may be made from the current route.
After correctness, cache the full-map resident pack by geometry/material
generation and derive only the portal active set and TLAS list per frame.
