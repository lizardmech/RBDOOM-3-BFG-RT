GEO-05 - per-world lifecycle owner audit and first runtime gate
================================================================
Status: shadow registry implemented; snapshot restoration validated; callback
MD5 source discovery awaiting focused runtime validation.
Date: 2026-07-23, updated 2026-07-24.

HOOK AUDIT
----------
The existing Add/Update/Free hooks were real but incomplete:

1. AddEntityDef called UpdateEntityDef and notified Add afterward.
   Direct UpdateEntityDef creation of an unused handle had no Add notification.
   GEO-05 makes UpdateEntityDef notify Add for a newly allocated def and removes
   the wrapper's duplicate responsibility.

2. The exact-memcmp early return performed no lifecycle observation.
   GEO-05 reports it as unchanged.

3. The callback fast-update early return changed render parms but performed no
   lifecycle observation.
   GEO-05 reports it as Update after copying the new parms.

4. AddWorldModelEntities allocates authored static area entities directly and
   deliberately bypasses AddEntityDef.
   GEO-05 adds an explicit Add notification after derivation and area linking.

5. FreeWorld calls FreeDefs, which calls FreeEntityDef for every owned entity
   before inline models and world storage are deleted.
   This is the safe exact-removal point. A new world generation is allocated
   only after those Free notifications complete.

6. InitFromMap has three reset shapes:

     empty world        FreeWorld -> new generation -> ClearWorld
     retained same map FreeDefs  -> new generation -> re-add area entities
     full reload/change FreeWorld -> new generation -> load/re-add entities

   mapLoadSerial increments before all three. The shadow owner allocates a new
   monotonic WorldKey and primary HistoryOwnerKey at the marked boundary.

PER-WORLD OWNER
---------------
idRenderWorldLocal now owns one opaque
PtGeometryLifecycleWorldRegistry pointer. Construction allocates it; destruction
first frees world defs, then destroys it. The old process-global
unordered_map<renderWorld pointer, state> is gone.

The only process-global identity state is three monotonic atomic allocators:

  world generation;
  logical history-owner generation;
  shadow asset ID.

They contain no live-object pointers or records.

PtRenderDefKey remains transitional because live legacy consumers still carry
the raw world pointer. It now also carries worldGeneration, and liveness rejects
a key whose generation does not match the world's current owner. Canonical
InstanceKey uses only the numeric world generation, slot generation and surface
ordinal.

SHADOW RECORDS
--------------
Gate:

  r_pathTracingGeometryShadowRegistry 0

Default is off. When enabled, the owner bootstraps current entityDefs once and
then follows Add/Update/Unchanged/Free. It never drives traversal.

Each registry-eligible model surface produces:

  canonical InstanceKey;
  canonical MeshKey;
  copied transform;
  material ID/name;
  model name;
  vertex/index/triangle counts;
  lifecycle class and last-modified frame.

No shadow mesh or instance record stores:

  idRenderEntityLocal pointer;
  idRenderModel pointer;
  srfTriangles_t pointer;
  drawSurf pointer;
  frontend/cache address;
  NVRHI resource or AS handle.

The shadow asset namespace is world-owner-local for GEO-05. Full model-name +
source-domain equality allocates a monotonic numeric asset ID; the name hash is
not identity. Repeated instances of the same model in one world share MeshKeys.
GEO-06 must move registered-model asset generation to the pooled mesh owner
before cross-world sharing or live storage.

Topology signature is derived from immutable vertex/index counts and the full
local index sequence. Material, transform and output/cache addresses are
excluded.

Mesh records remain after liveReferences reaches zero. The transition is
counted as deferredMeshEviction; GEO-05 has no implicit frame-age eviction.

DUMP CONTRACT
-------------
Trigger:

  r_pathTracingGeometryShadowRegistryDump 1

The next PT frame prints one summary and up to 16 bounded samples, prioritizing
non-static instances. Summary fields:

  worldGeneration / previousWorldGeneration / mapLoadSerial;
  primaryHistoryOwner;
  reset count and records discarded at the last reset;
  interval add/update/remove/unchanged;
  interval collision/stale/missing/transient/deferredMesh;
  live instance/referenced-mesh/zero-ref-mesh/asset counts;
  shared mesh count and maximum references to one mesh;
  static/rigid/skinned instance counts;
  live vertex/index/triangle totals;
  interval removed vertex/index/triangle totals.

Interval counters reset after each dump. Live record totals do not reset. This
makes the medkit removal delta machine-checkable without contaminating it with
earlier map-load events.

RUNTIME CRASH CORRECTION (2026-07-24)
-------------------------------------
The first deployed GEO-05 observer produced two repeatable CPU access
violations after roughly one minute of play:

  0xc0000005 at executable RVA 0x5f3cbb
  0xc0000005 at executable RVA 0x5fcc23

Windows Application Error/WER identified RBDoom3BFG.exe itself as the faulting
module; there was no Vulkan device-removed event. Disassembly of the exact
deployed executable localized the first RVA to a virtual model-surface-count
call in the new shadow observation path. The second RVA dereferenced the raw
idRenderWorldLocal pointer while resolving a PtRenderDefKey to its per-world
registry.

Both accesses violated existing renderer lifetime rules:

  * unchanged and callback-fast entity updates deliberately return without
    dereferencing hModel, so a passive observer cannot add model traversal to
    those paths;
  * retained PtRenderDefKey world pointers are opaque identity values and may
    outlive the idRenderWorldLocal object, so lookup cannot dereference them.

Correction:

  * the shadow registry no longer bootstraps by traversing all existing
    entityDefs when enabled;
  * unchanged updates only refresh lifecycle liveness and do not classify or
    traverse model surfaces;
  * callback-fast updates explicitly mark their source as unstable and do not
    classify or traverse model surfaces;
  * callback/generated sources are rejected before any model virtual call;
  * free diagnostics use the class stored during the last stable add/update;
  * a mutex-protected non-owning live-world directory validates opaque world
    pointer values before returning a registry. All slot, mesh, instance,
    generation and history state remains owned by the per-world registry.

Operational consequence: enable the shadow registry before mapRestart or a map
load. Mid-map enable starts observing only subsequent stable add/update events;
it intentionally does not reconstruct a complete snapshot from potentially
unsafe retained pointers.

MAP-RELOAD AREA-REFERENCE CRASH (2026-07-24)
--------------------------------------------
geometry_geo19.log reached the first PT frame after same-map reload, printed the
map serial transition 1 -> 2 and then terminated before any requested GEO-05
dump. Windows recorded a new 0xc0000005 at executable RVA 0x5f3c9a for deployed
executable SHA-256:

  2AAF930B03C7093FC3FADF2D405A154389466B3CBF85AE23A71E490766BD66AE

Initial disassembly-only comparison placed the fault in
RefreshRigidResidencyAreaWalk. That attribution is superseded by the exact
Release map evidence recorded below; both the legacy area walk and entity feed
have structurally similar portal-reference/model loops.

This is separate from the two lifecycle-observer faults above. The immediate
correction builds a pointer-only live membership set from renderWorld->entityDefs
before walking selected portal areas. An area reference must be present in that
set and must round-trip through world/index/entityDefs before any entity field
is read. Stale references are rejected and counted as rejected area-walk
entities.

This is a crash guard, not the final ownership architecture. The late portal
area walk still consumes mutable engine structures and must be replaced by the
engine-owned snapshot boundary in the later modernization steps.

EXACT SYMBOL CORRECTION AND ENTITY-FEED GUARD (2026-07-24)
----------------------------------------------------------
A current Release map was generated from the exact source/object set after the
same RVA 0x5f3dcb recurred with V2 diagnostics confined to snapshots. The map
places the fault inside:

  CaptureEntityFeedRigidSurfaces
  function start RVA 0x5f31f0
  fault delta +0xbdb

The faulting instruction is the hModel virtual call for NumSurfaces. This
explains the reported spatial correlation with animated objects: the V2 feed
walked reachable area references, read entity->parms.hModel, and enumerated
surfaces before rejecting callback/skinned/generated entities which cannot be
admitted by this rigid-only feed.

Correction:

  * area-reference entity pointers must belong to the current entityDefs set
    and round-trip through world/index/entityDefs before any entity field read;
  * callback, force-update, jointed, depth-hack and generated/dynamic-model
    entities are rejected before any hModel virtual call;
  * the resident store now keys same-object map reloads by mapLoadSerial;
  * resident entity slots now compare worldGeneration as well as raw world,
    index and render-def generation.

The mapLoadSerial/worldGeneration omissions were independent correctness bugs:
a same-map reload could otherwise retain surface/material/model facts from the
previous world generation even when the world pointer and slot generation were
reused.

SECOND EXACT SYMBOL CORRECTION AND SMP CONTAINMENT (2026-07-24)
---------------------------------------------------------------
The first guarded build did not remove the crash. The replacement executable
was confirmed live: its PE timestamp changed from 0x6a62dd49 to 0x6a62e01a and
the fault RVA moved from 0x005f3dcb to 0x005f4be2.

The matching Release map places CaptureEntityFeedRigidSurfaces at RVA
0x005f31f0. Exact disassembly of the replacement executable resolves
0x005f4be2 to:

  mov rcx, qword ptr [rcx]

This is the increment of the portal-area linked-list walk:

  ref = ref->areaNext

The crashing value can therefore be a node that the frontend unlinked and
returned to areaReferenceAllocator while the backend was processing the
previous frame. The animated-object correlation is causal evidence: ordinary
animated entity updates rebuild their area references. RenderCommon.h states
the governing engine contract directly:

  * viewEntity_t is a frame-temporary backend copy because the frontend may
    modify idRenderEntityLocal simultaneously in SMP mode;
  * the backend must not reference viewEntity_t::entityDef.

The entity feed violated the stronger form of that contract by walking
renderWorld->portalAreas[].entityRefs and dereferencing entityDefs from the
backend. Pointer-membership checks cannot repair a concurrently mutating list;
the node can be freed after any check.

Containment:

  * with the default com_smp=1, ProduceEntityFeedRigidEntities now fails closed
    before reading renderWorld, portal entityRefs, or entityDefs;
  * the existing frame-owned draw-surface mirror remains the visible-geometry
    producer;
  * com_smp=0 retains the old feed for single-thread diagnosis only.

Required architectural follow-up:

  Build an immutable, frontend-owned entity-feed frame snapshot and attach it
  to the view command. It must contain value-copied identity, transform,
  classification, material, area-membership, and stable rigid mesh references.
  The backend must consume that snapshot without dereferencing
  idRenderEntityLocal, areaReference_t, or mutable renderWorld entity arrays.
  The off-screen rigid feed must not be re-enabled under SMP until this
  producer/consumer handoff is validated.

FRONTEND FRAME SNAPSHOT RESTORATION (2026-07-24)
------------------------------------------------
The next implementation replaces the containment-only shutdown with a frame
snapshot captured in R_RenderView immediately before R_AddDrawViewCmd.

Frontend producer contract:

  * compute the reachable portal-area set while the frontend owns the live
    render world;
  * walk portal entity references only on the frontend;
  * admit only non-world DM_STATIC models with drawing surfaces and reject
    callback, force-update, jointed, depth-hack and generated-model entities
    before the command boundary;
  * clone the required renderEntity values, transform matrices, reference
    bounds and stable renderer-asset pointers into frame memory;
  * clear callbackData, callback, joints, GUI, remote-view, sound, decal,
    overlay, interaction and live area-reference pointers;
  * capture the lifecycle render-def key, model epoch, map-load serial,
    area/depth and current-frame visibility as values;
  * build frame-owned area lists whose nodes refer only to frame-owned entity
    clones.

Backend consumer contract:

  * com_smp requires the snapshot attached to the exact view command; a
    missing snapshot still fails closed;
  * reachable areas, entity membership, area links, identity, epoch,
    transform and visibility come from the snapshot;
  * the render-world pointer is opaque identity and the residency store uses
    the captured map-load serial instead of reading mutable world fields;
  * visible draw-surface matching uses the captured source pointer only as an
    opaque map key and never dereferences it;
  * only stable DM_STATIC model, triangle, material, skin and shader assets are
    retained for same-frame classification and mesh ingestion;
  * the old animated/single-bone/joint/reachable diagnostic walks are disabled
    under com_smp because they independently dereference live entity arrays.

CALLBACK MD5 SOURCE-DISCOVERY PREREQUISITE (2026-07-24)
-------------------------------------------------------
The GEO-06 entry audit found a contradiction in the accepted GEO-05 evidence:
crowded MD5 entities were alive in the renderer, but every shadow-registry dump
reported:

  instanceClass(static/rigid/skinned)=.../.../0

The Add notification for a deferred entity occurs before its render callback
has necessarily supplied hModel. ShadowSourceDomain also deliberately rejected
all callback entities because lifecycle fast paths do not own a safe model
surface traversal. Later callback fast updates use sourceStable=false, so those
updates correctly avoid dereferencing the model but also cannot discover the
bind source. The result was a permanent canonical-record gap for callback MD5
entities.

The bounded correction preserves the lifetime rule:

  Add/Free lifecycle hooks remain instance-liveness authority;
  R_RenderView calls ObserveFrontendDeformingEntities after R_AddModels;
  this frontend boundary has resolved callback models and owns viewEntitys;
  first discovery traverses the immutable DM_CACHED bind source once;
  later observations refresh only entity values/transforms;
  duplicate viewEntity entries are suppressed;
  no live entity/model/surface pointer crosses to the SMP backend.

New interval diagnostics:

  frontendDeforming(discovered/refreshed)=<first-records>/<value-refreshes>

This remains observation-only under the existing default-off
r_pathTracingGeometryShadowRegistry gate. It does not route skinned output,
change BLAS ownership, or modify shader inputs.
