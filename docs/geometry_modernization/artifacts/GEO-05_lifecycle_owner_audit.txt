GEO-05 - per-world lifecycle owner audit and first runtime gate
================================================================
Status: initial shadow-registry implementation, runtime validation pending.
Date: 2026-07-23.

HOOK AUDIT
----------
The existing Add/Update/Free hooks were real but incomplete:

1. AddEntityDef called UpdateEntityDef and notified Add afterward.
   Direct UpdateEntityDef creation of an unused handle had no Add notification.
   GEO-05 makes UpdateEntityDef notify Add for a newly allocated def and removes
   the wrapper's duplicate responsibility.

2. The exact-memcmp early return performed no lifecycle observation.
   GEO-05 reports it as unchanged.

3. The callback fast-update early return changed render parms but performed no
   lifecycle observation.
   GEO-05 reports it as Update after copying the new parms.

4. AddWorldModelEntities allocates authored static area entities directly and
   deliberately bypasses AddEntityDef.
   GEO-05 adds an explicit Add notification after derivation and area linking.

5. FreeWorld calls FreeDefs, which calls FreeEntityDef for every owned entity
   before inline models and world storage are deleted.
   This is the safe exact-removal point. A new world generation is allocated
   only after those Free notifications complete.

6. InitFromMap has three reset shapes:

     empty world        FreeWorld -> new generation -> ClearWorld
     retained same map FreeDefs  -> new generation -> re-add area entities
     full reload/change FreeWorld -> new generation -> load/re-add entities

   mapLoadSerial increments before all three. The shadow owner allocates a new
   monotonic WorldKey and primary HistoryOwnerKey at the marked boundary.

PER-WORLD OWNER
---------------
idRenderWorldLocal now owns one opaque
PtGeometryLifecycleWorldRegistry pointer. Construction allocates it; destruction
first frees world defs, then destroys it. The old process-global
unordered_map<renderWorld pointer, state> is gone.

The only process-global identity state is three monotonic atomic allocators:

  world generation;
  logical history-owner generation;
  shadow asset ID.

They contain no live-object pointers or records.

PtRenderDefKey remains transitional because live legacy consumers still carry
the raw world pointer. It now also carries worldGeneration, and liveness rejects
a key whose generation does not match the world's current owner. Canonical
InstanceKey uses only the numeric world generation, slot generation and surface
ordinal.

SHADOW RECORDS
--------------
Gate:

  r_pathTracingGeometryShadowRegistry 0

Default is off. When enabled, the owner bootstraps current entityDefs once and
then follows Add/Update/Unchanged/Free. It never drives traversal.

Each registry-eligible model surface produces:

  canonical InstanceKey;
  canonical MeshKey;
  copied transform;
  material ID/name;
  model name;
  vertex/index/triangle counts;
  lifecycle class and last-modified frame.

No shadow mesh or instance record stores:

  idRenderEntityLocal pointer;
  idRenderModel pointer;
  srfTriangles_t pointer;
  drawSurf pointer;
  frontend/cache address;
  NVRHI resource or AS handle.

The shadow asset namespace is world-owner-local for GEO-05. Full model-name +
source-domain equality allocates a monotonic numeric asset ID; the name hash is
not identity. Repeated instances of the same model in one world share MeshKeys.
GEO-06 must move registered-model asset generation to the pooled mesh owner
before cross-world sharing or live storage.

Topology signature is derived from immutable vertex/index counts and the full
local index sequence. Material, transform and output/cache addresses are
excluded.

Mesh records remain after liveReferences reaches zero. The transition is
counted as deferredMeshEviction; GEO-05 has no implicit frame-age eviction.

DUMP CONTRACT
-------------
Trigger:

  r_pathTracingGeometryShadowRegistryDump 1

The next PT frame prints one summary and up to 16 bounded samples, prioritizing
non-static instances. Summary fields:

  worldGeneration / previousWorldGeneration / mapLoadSerial;
  primaryHistoryOwner;
  reset count and records discarded at the last reset;
  interval add/update/remove/unchanged;
  interval collision/stale/missing/transient/deferredMesh;
  live instance/referenced-mesh/zero-ref-mesh/asset counts;
  shared mesh count and maximum references to one mesh;
  static/rigid/skinned instance counts;
  live vertex/index/triangle totals;
  interval removed vertex/index/triangle totals.

Interval counters reset after each dump. Live record totals do not reset. This
makes the medkit removal delta machine-checkable without contaminating it with
earlier map-load events.

FIRST RUNTIME CAPTURE
---------------------
Use a new log, geometry_geo19.log. Enable the shadow registry before restarting
or loading the test map:

  r_pathTracingGeometryShadowRegistry 1
  mapRestart

In game/mc_underground area 25, settle, then:

  spawn func_static model models/items/medkit/medkit_large.lwo name geom_lifecycle_probe
  echo === GEO05_VISIBLE ===
  r_pathTracingGeometryShadowRegistryDump 1
  r_pathTracingGeometryLifecycleDump 1

Move to another portal area and return:

  echo === GEO05_RETURNED ===
  r_pathTracingGeometryShadowRegistryDump 1

Open and close the PDA:

  echo === GEO05_PDA_RETURN ===
  r_pathTracingGeometryShadowRegistryDump 1

Immediately remove the probe:

  remove geom_lifecycle_probe
  echo === GEO05_REMOVED ===
  r_pathTracingGeometryShadowRegistryDump 1
  r_pathTracingGeometryLifecycleDump 1

Required:

  visible/returned/PDA live record and geometry totals are identical;
  worldGeneration and primaryHistoryOwner are identical across those labels;
  collision=0 and stale=0;
  removal interval:
      remove=2
      removedGeometryInterval=120/552/184
  live totals after removal:
      exactly 2 fewer instances
      exactly 120/552/184 fewer vertices/indexes/triangles
  two mesh records may remain with zero references; that is the required
  deferred-eviction behavior, not a live-instance leak.

Then run:

  echo === GEO05_MAP_RESTART_BEFORE ===
  r_pathTracingGeometryShadowRegistryDump 1
  mapRestart
  echo === GEO05_MAP_RESTART_AFTER ===
  r_pathTracingGeometryShadowRegistryDump 1

Required after restart:

  worldGeneration changed;
  previousWorldGeneration equals the pre-restart generation;
  primaryHistoryOwner changed;
  resetDiscarded liveInstances=0;
  collision=0 and stale=0.

The crowded MD5 comparison and visible/area/lifecycle tuple comparison are the
next GEO-05 slice after this owner/lifetime gate passes.

RUNTIME CRASH CORRECTION (2026-07-24)
-------------------------------------
The first deployed GEO-05 observer produced two repeatable CPU access
violations after roughly one minute of play:

  0xc0000005 at executable RVA 0x5f3cbb
  0xc0000005 at executable RVA 0x5fcc23

Windows Application Error/WER identified RBDoom3BFG.exe itself as the faulting
module; there was no Vulkan device-removed event. Disassembly of the exact
deployed executable localized the first RVA to a virtual model-surface-count
call in the new shadow observation path. The second RVA dereferenced the raw
idRenderWorldLocal pointer while resolving a PtRenderDefKey to its per-world
registry.

Both accesses violated existing renderer lifetime rules:

  * unchanged and callback-fast entity updates deliberately return without
    dereferencing hModel, so a passive observer cannot add model traversal to
    those paths;
  * retained PtRenderDefKey world pointers are opaque identity values and may
    outlive the idRenderWorldLocal object, so lookup cannot dereference them.

Correction:

  * the shadow registry no longer bootstraps by traversing all existing
    entityDefs when enabled;
  * unchanged updates only refresh lifecycle liveness and do not classify or
    traverse model surfaces;
  * callback-fast updates explicitly mark their source as unstable and do not
    classify or traverse model surfaces;
  * callback/generated sources are rejected before any model virtual call;
  * free diagnostics use the class stored during the last stable add/update;
  * a mutex-protected non-owning live-world directory validates opaque world
    pointer values before returning a registry. All slot, mesh, instance,
    generation and history state remains owned by the per-world registry.

Operational consequence: enable the shadow registry before mapRestart or a map
load. Mid-map enable starts observing only subsequent stable add/update events;
it intentionally does not reconstruct a complete snapshot from potentially
unsafe retained pointers.

MAP-RELOAD AREA-REFERENCE CRASH (2026-07-24)
--------------------------------------------
geometry_geo19.log reached the first PT frame after same-map reload, printed the
map serial transition 1 -> 2 and then terminated before any requested GEO-05
dump. Windows recorded a new 0xc0000005 at executable RVA 0x5f3c9a for deployed
executable SHA-256:

  2AAF930B03C7093FC3FADF2D405A154389466B3CBF85AE23A71E490766BD66AE

Exact executable disassembly and the matching source control flow place the
fault in RefreshRigidResidencyAreaWalk. A portal area's linked reference node
was still readable, but its entity pointer was no longer a live entityDef; the
fault occurred on the first read of entity->parms.hModel.

This is separate from the two lifecycle-observer faults above. The immediate
correction builds a pointer-only live membership set from renderWorld->entityDefs
before walking selected portal areas. An area reference must be present in that
set and must round-trip through world/index/entityDefs before any entity field
is read. Stale references are rejected and counted as rejected area-walk
entities.

This is a crash guard, not the final ownership architecture. The late portal
area walk still consumes mutable engine structures and must be replaced by the
engine-owned snapshot boundary in the later modernization steps.

V2 DIAGNOSTIC AREA-WALK REMOVAL (2026-07-24)
--------------------------------------------
The guarded build completed the requested V2 residency dump, survived same-map
reload, spawned the medkit probe and emitted both GEO-05 shadow and lifecycle
dumps. During later ordinary traversal it crashed with 0xc0000005 at executable
RVA 0x5f3dcb.

The membership guard had rejected stale entity pointers, but exact executable
disassembly showed this new fault at model->NumSurfaces() deeper in the same
RefreshRigidResidencyAreaWalk path. Membership in entityDefs does not extend the
lifetime contract of a retained hModel pointer into this late PT diagnostic.

For residency V2, r_pathTracingRigidResidencyDump no longer activates the
legacy portal-area walk. The dump now reports the V2 entity-feed/residency
snapshot already used by the live route. The legacy walk remains reachable
only when r_pathTracingGeometryResidencyV2 is explicitly disabled; replacing
that legacy ownership path is later modernization work.
