ENTRY CONTRADICTION
-------------------
The old GEO-07/GEO-08 boundary required CPU pre-skinning to disappear before
GEO-08 while also forbidding GEO-07 from routing the new output through a BLAS.
The live renderer cannot satisfy both statements:

  BuildSmokeSurfaceVertexFromSource
    -> CPU-skinned world-space dynamicVertexData
    -> smokeDynamicVertexBuffer
    -> merged smokeDynamicBlas
    -> live TLAS traversal.

The accepted GEO-07 mode-1 compute output is a different buffer with no BLAS
consumer. Skipping CPU skinning first would leave bind-pose or invalid data in
the live merged BLAS. D25 therefore moves CPU pre-skin removal to the GEO-08
traversal cutover.

FROZEN FIRST-CUT INPUT CONTRACT
-------------------------------
Per eligible canonical SkinnedSurface InstanceKey:

  vertex buffer/range:
    accepted per-instance PathTraceSmokeVertex output;
    112-byte stride;
    checked output buffer generation, byte offset, count and capacity;

  index buffer/range:
    exact canonical GEO-06 GPU index-pool record;
    checked pool generation, aligned byte offset, count and capacity;
    source indexes remain local to the surface;

  source identity:
    exact SkinnedBindSource/Skinned MeshKey and nonzero source checksum;

  transform:
    identity TLAS transform for the first cut because the accepted compute
    shader writes world-space positions and attributes;

  queue order:
    renderer joint copy -> skin compute -> UAV/AS barrier ->
    per-instance BLAS build/update -> TLAS build;

  update eligibility:
    initial build completed;
    full InstanceKey unchanged;
    mesh/source/index-pool/output storage contract unchanged;
    fixed rebuild cadence not reached;

  retirement:
    exact lifecycle removal, render-def generation replacement, world change,
    or referenced output-buffer generation replacement;
    release requires explicit in-flight completion.

  IDevice::setEventQuery records the graphics queue's last submitted ID;

STEP 8/9 CPU-CAPTURE SPLIT AUDIT AND ACCEPTANCE
-----------------------------------------------
The cutover is controlled by the independent, default-off
`r_pathTracingGeometrySkinnedCaptureSplit` gate. The planner is pure and is
covered by PathTraceSkinnedHitRouteHarness cases for gate-off, absent prior
route, changed source contract, missing joints, and source-only route
construction. A live surface is admitted before append only when:

  - the split gate is enabled;
  - an earlier use of the same exact visible-set signature completed route,
    resource, BLAS, SBT, capacity, and TLAS admission;
  - full InstanceKey and mesh/source checksum identity match;
  - source vertex/index/triangle counts match;
  - current joint data is present.

An admitted surface records `cpuCaptureOmitted`, leaves its legacy dynamic
offsets invalid, and appends neither CPU-skinned vertices nor indexes. Its hit
route uses canonical source indexes plus source-only material, class, primitive,
and emissive metadata. Current vertices are generated into per-instance GPU
output. Previous vertices can be regenerated from the retained previous joint
matrices, so motion transport does not depend on prior CPU-skinned vertex
history.

The view cache is an exact-set cache bounded to eight entries by default; the
validation-only limit cvar can reduce it as far as one to force eviction.
Each entry has a pending frame-local route build and the last TLAS-accepted
build. Capture consumes the accepted build only after its source, output
generation, AS state, BLAS handle, and index/output buffers are revalidated.
The current source-only upload may refresh frame-local triangle metadata
without forcing CPU skinning merely because its byte signature changed. The
current upload must still match the omitted InstanceKey set one-for-one and
pass normal route/resource/BLAS/SBT/TLAS planning before promotion. A late
failure clears only that signature's accepted build and suppresses it for the
current frame. It is never reported as same-frame CPU fallback.
