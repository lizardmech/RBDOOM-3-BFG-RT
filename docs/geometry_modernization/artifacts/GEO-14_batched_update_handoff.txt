GEO-14 batched skinned UPDATE transition handoff
================================================

SCOPE
-----
Optimize only the synchronization shape accepted by D182. Do not remove the
prior-write -> source-read -> combined source-read/destination-write contract,
change Vulkan UPDATE semantics, change BLAS scratch ownership, change route
identity, or change either production default.

IMPLEMENTATION
--------------
`SubmitSmokeSkinnedComparisonBlases` now separates validation/resource
preparation from submission:

  1. validate the same exact source, output, generation, topology, and range
     contract and prepare an immutable submission record;
  2. transition every PerformUpdate BLAS to `AccelStructBuildBlas`;
  3. commit all prior-write -> source-read barriers together;
  4. transition every PerformUpdate BLAS to
     `AccelStructBuildBlas | AccelStructWrite`;
  5. commit all source-read -> combined read/write barriers together;
  6. issue the same individual NVRHI UPDATE calls with automatic barriers
     disabled only for the jobs whose complete states were prepared above;
  7. restore automatic barriers immediately after each such call.

Full BUILD and rebuild jobs continue through NVRHI automatic barriers. Shared
GPU vertex/index inputs are transitioned once before the job list. State-table
success and resource BLAS generations are published only after each command is
issued, as before.

This slice batches state transitions, not Vulkan build commands or scratch
allocations. NVRHI's D182 backend fallback remains correct for any caller that
does not prepare a batch.
