GEO-12 / Q2 skinned write-vs-derive measurement
================================================
Date: 2026-07-30
Status: candidate rejected on numeric fidelity; current write path retained

QUESTION
--------
Q2 asked whether the PT skinning compute should continue writing posed normal
and tangent data once per vertex per frame, or whether hit shading could derive
the basis from the posed geometric triangle plus immutable stored deltas.

This artifact settles the first concrete and least invasive derivation shape.
It does not change the production vertex ABI or claim that every imaginable
compression has been disproved.

CANDIDATE CONTRACT
------------------
For every triangle corner:

  1. Construct an orthonormal frame from the canonical bind triangle.
  2. Express the canonical source normal and tangent in that frame.
  3. Construct the corresponding orthonormal frame from the exact current
     posed triangle.
  4. Reconstruct the two directions from the same coefficients.
  5. Compare them with the current full-fidelity linear-blend-skinned output.

The survey uses unquantized float directions. It is therefore a best case for
a stored-delta implementation. The reported eight bytes per corner model two
signed oct16 direction coefficients only for storage accounting; quantization
is not applied to the error result.

The diagnostic is pure observation:

  r_pathTracingGeometrySkinnedAttributeDeriveDump 1

It adds this request to the existing one-frame CPU-reference capture condition,
then resets itself after printing. It does not upload derived data, change
BLAS/TLAS input, alter hit reconstruction, or change a production default.

CONTROL INTERPRETATION
----------------------
Rigid-like surfaces validate the join and frame math:

  soft_desk_chair2, 477 vertices:
    normal RMS/max  0.00297 / 0.02798 degrees
    tangent RMS/max 0.00314 / 0.02798 degrees

  small head surfaces:
    maximum about 0.03 degrees

True deformers reject the candidate:

  each zfat surface, 3,050 vertices / 15,288 corners:
    normal RMS about 13.0-13.85 degrees
    tangent RMS about 9.61-10.05 degrees
    normal maximum 178.72 degrees

  suit surface 5, 536 vertices / 2,334 corners:
    normal RMS/max  23.71 / 169.57 degrees
    tangent RMS/max 20.07 / 137.43 degrees

The fact that the same exact machinery is sub-degree on single-bone and
rigid-like surfaces but fails on articulated surfaces localizes the error to
the reconstruction model under deformation, rather than a source-index,
current-range, coordinate-space, or general winding mismatch.

BYTE ACCOUNTING
---------------
Current PathTraceSmokeVertex writes three float4 basis values:

  9,889 vertices * 48 bytes = 474,672 bytes per frame

An optimistic precomputed candidate stores two oct16 directions per corner:

  47,886 corners * 8 bytes = 383,088 persistent bytes

These have different lifetimes and must not be subtracted as a combined saving.
The candidate storage is already 80.71 percent of the avoided per-frame write
count before alignment, route metadata, and hit-fetch cost. Recomputing the
coefficients instead would avoid that storage only by adding canonical source
reads and bind-frame construction to every hit.

The 474,672-byte write figure is also optimistic: it assumes bitangent can be
derived. GEO-12's representative rendered survey independently found four
invalid bitangent reconstructions and a 10.6427-degree valid maximum, so a
fidelity-preserving implementation may save only the 32 normal/tangent bytes
per vertex while retaining bitangent output.

DECISION
--------
Reject this triangle-frame derivation before shader implementation or timing.
Its unquantized numeric error is far outside the full-fidelity reference on
the exact monsters and characters Q2 needs to serve, while its best-case byte
shape is not compelling enough to justify per-hit source/frame work.

Retain the established production contract:

  - skin positions, normal, tangent, and bitangent once per vertex per frame;
  - write the existing 112-byte PathTraceSmokeVertex output;
  - let all hit families consume the same posed basis;
  - do not add another source/delta descriptor or decode path.

This resolves Q2 for the proposed geometric-frame/stored-delta alternative.
Future representation work must propose a different exact reconstruction and
pass a pure numeric survey before any shader fan-out or performance A/B.
