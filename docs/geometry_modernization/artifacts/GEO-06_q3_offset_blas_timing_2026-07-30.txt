GEO-06 / Q3 pooled index-offset BLAS timing
===========================================
Date: 2026-07-30
Status: accepted; retain the shared uint32 index pool

QUESTION
--------
Q3 asks whether Vulkan BLAS build performance is sensitive to a mesh's
non-zero byte offset inside a shared uint32 index pool. GEO-06 already proved
correct non-zero-offset addressing, but its `buildSubmitUs` value is CPU
command-recording time for one build and cannot answer the GPU performance
question.

CONTROLLED EXPERIMENT
---------------------
The default-off command is:

  r_pathTracingGeometryOffsetBlasTiming 64

The diagnostic selects the largest eligible canonical mesh whose production
pool records all have non-zero offsets. It copies that mesh's exact local
uint32 index stream twice into one scratch index buffer:

  control range     byte offset 0
  treatment range   byte offset 61,184

The ranges do not overlap and contain identical bytes. Both BLAS descriptors
use the same canonical pooled vertex buffer and vertex offset, vertex/index
counts, formats, strides, topology, and PreferFastTrace build flag. Only
`GeometryTriangles.indexOffset` differs. Each successive pair reverses build
order. Neither result is placed in a TLAS or used by a shader.

Each build has its own NVRHI Vulkan GPU timer query. Query polling begins after
four frames. The scratch buffer and two BLASes enter the existing GEO-11 rigid
GPU-event retirement path only after every query resolves.

ORDER CONTROL
-------------
The relatively wide per-pair tails are an ordering effect:

  zero-offset built first:
    paired non-zero-minus-zero median          -1.6805 percent

  non-zero-offset built first:
    paired non-zero-minus-zero median          +2.1415 percent

The second build tends to be faster regardless of which offset it uses.
Alternating order balances that cache/scheduling effect. The aggregate means,
medians, and p95 values then agree to substantially less than one tenth of one
percent.

DECISION
--------
There is no measurable Vulkan BLAS-build penalty attributable to the non-zero
index offset in this controlled workload. Retain the shared uint32 index pool
and its checked per-record byte offsets. Do not introduce per-mesh index
buffers to improve BLAS build time.

This experiment isolates index offset only. It does not claim that source
upload, allocation, or pool growth are free; those remain governed by GEO-06's
separate immutable-upload and generation-safe growth contracts.
