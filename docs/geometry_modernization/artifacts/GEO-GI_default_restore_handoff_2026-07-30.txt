USER-REPORTED REGRESSION
------------------------
After the geometry packet was marked complete, the normal launcher no longer
produced GI. Before the geometry work, clean GI launched and ran without a
manual warmup override.

ROOT CAUSE
----------
The visible GI controls were still enabled:

  r_pathTracingCleanRestirGiEnable       1
  r_pathTracingCleanRestirGiResolve      1
  r_pathTracingCleanRestirGiView         0

However, geometry checkpoint e89e7b53ad changed:

  r_pathTracingCleanRestirGiPipelineWarmupLimit  16 -> 0

Limit zero prevents all sixteen Vulkan GI ray pipelines from being built.
No partial limit dispatches GI. The result was therefore an effectively
disabled production GI lane despite enable and resolve remaining one.

The later geometry validation explicitly accepted the complete 16/16 lane in
geometry_geo_step18.log, then added a narrow safety guard for the one unstable
intersection:

  clean GI + refracted glass PSR + static bucket route one

That guard retains GI and refraction but selects the monolithic static route
for this conjunction. It does not require GI itself to remain disabled. The
accepted warmup default was simply never restored after the diagnostic ladder.

CHANGE
------
Only the warmup default is changed:

  r_pathTracingCleanRestirGiPipelineWarmupLimit  0 -> 16

GI enable, resolve, view, final mix, blue noise, shaders, static-bucket
defaults, and the GI+refracted-glass monolithic safety guard are unchanged.
Zero remains the explicit rollback that builds no GI ray pipelines.
