--------------

particle-lighting compute path is not required for the failure. Scene-build

creation in ExecutePathTraceParticleComposite, but the A/B does not prove that
as the cause. Buffer growth, texture/batch churn, and later Vulkan submission
or descriptor reclamation remain possible.

TRANSIENT SURFACE LIFETIME FAILURE
----------------------------------
While preparing the brush-BLAS A/B, the same gameplay section repeatedly
stopped an attached Visual Studio debugger a few seconds after load. A matching
RelWithDebInfo executable and PDB localized two successive first-chance access
violations in the particle composite producer.

First boundary:

  material: textures/particles/barrelpoof
  surface index: 149
  entity index before retirement: 76
  call: AppendSmokeSurfaceGeometry -> SmokeTryCopyMemory
  draw-surface ambient/index cache state: non-current / non-current
  retained triangle vertices/indexes: 0xDDDDDDDDDDDDDDDD

The existing SEH copy guard would catch this exception outside an attached
debugger, but using a caught access violation as routine transient-surface
validation is not an acceptable lifetime contract.

After rejecting that stale geometry, the next run exposed a second boundary in
the same class:

  call: ParticleCompositeHasExplicitEffectContext
  view entity: still present in the backend draw surface
  entity definition index: 0xDDDDDDDD
  hModel and callback pointers: 0xDDDDDDDDDDDDDDDD
  faulting operation: hModel->Name()

FIXED CONTRACT
--------------
`ValidateSmokeDrawSurface` now:

  - proves a non-world entity pointer is still present in the current render
    world's `entityDefs` array before reading `renderEntity_t` or `hModel`.

The particle route carries `viewDef` through every call. Particle inspection
and capture first require structurally plausible draw-surface/triangle
pointers, counts, and pointer identity. The final CPU geometry copy remains
guarded by `SmokeTryCopyMemory`, so an already-retired vertex/index allocation
is dropped without retaining poisoned data. Entity/model-derived particle
traits are read only after the entity pointer is found in the current render
world.

Non-current draw-surface cache handles are NOT by themselves a rejection
reason. Transient particles legitimately use live CPU fallback geometry after
those cache handles stop being current.

VALIDATION
----------
The first lifetime build broadly rejected every non-current draw-surface cache
handle. Although extended play no longer crashed, runtime validation showed
that it also removed nearly every particle in the game. That behavior was
rejected and removed.

stalls with reported particle ranges near 0.5-0.8 ms. Those values cannot yet

The reported GPU times repeat exactly every 16 invocations, matching the
timer-ring size. On Vulkan, `beginTimerQuery` records the query-pool reset in
the command list. Reusing a query and polling it before that recorded reset has
executed can observe the previous use's available bit and return the old time.
The diagnostic therefore associated stale query results with new frame
metadata.

The timer ring must delay polling a newly reused slot by at least the renderer
frame-data depth, matching the existing render-log timer discipline. Repeat
the same monster-fire capture after that correction. Do not advance to
