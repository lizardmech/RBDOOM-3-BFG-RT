FIRST RUNTIME RESULT - GEOMETRY_GEO13
-------------------------------------
Mode 0 bookkeeping passed:

  candidates/resultTotal/exact  15/15/1
  cpuFallback                   15
  singleBoneObserved             2

Mode 1 exposed a real dispatch binding failure:

  dispatchedGpu                 15
  samples/current failures      24/24
  GPU current position           0,0,0 for every sample
  previous failures              0

Mode 2 reported 24/24 exact current samples, but this was not independent
compute proof: the dynamic output buffer was pre-seeded with the CPU current
vertices. The previous-position buffer was likewise pre-seeded. Therefore the
mode 2 and previous-position matches were false-positive pass-through evidence.

SPIR-V disassembly resolved the contradiction:

  resource                         compiled Vulkan binding
  SkinnedSourceVertices            0
  SkinnedSurfaceDispatch           1
  SkinnedCurrentJointMatrices      2
  SkinnedPreviousJointMatrices     3
  SkinnedCurrentOutputVertices     384
  SkinnedPreviousPositions         385

The C++ skinning binding layout incorrectly set both SRV and UAV base offsets
to zero. The layout therefore did not match the active SPIR-V ABI. GEO-03
corrects only that binding offset to 384. It does not change joint ownership,
the CPU reference, or the BLAS route.

CURRENT MODE CONTRACT
---------------------
r_pathTracingGpuSkinning 0
  - CPU pre-skinning remains authoritative.
  - Dynamic BLAS consumes the CPU-built PathTraceSmokeVertex stream.
  - The retained CPU previous-position bridge can still build the motion lookup
    scaffold when motion-vector consumers require it.

r_pathTracingGpuSkinning 1
  - CPU pre-skinning still runs and remains the BLAS input.
  - Compute skins the same frame into a separate diagnostic output buffer.
  - GEO-03 reads this output back and compares it to the CPU current stream.

r_pathTracingGpuSkinning 2
  - CPU pre-skinning still runs first and supplies the same-frame reference.
  - Compute overwrites skinned ranges in the dynamic vertex buffer.
  - Dynamic BLAS consumes that overwritten GPU output.

The current compute scaffold still stages joints from the retained CPU bridge.
It does not consume the raster jointCache. That source-authority cutover remains
GEO-07 work.

FUNNEL CONTRACT
---------------
Every captured SkinnedDeformed surface ends in exactly one terminal counter:

  eligibleGpu
  dispatchedGpu
  notReadyJointData
  unsupportedLayout
  invalidWeightsOrJoints
  allocationFailure
  explicitSingleBoneRoute
  cpuFallback

The log prints candidates, resultTotal, and exact. Acceptance requires:

  resultTotal == candidates
  exact == 1

eligibleGpu is an intermediate state before dispatch finalization and therefore
should normally be zero in the emitted terminal line. In mode 0, every candidate
ends in cpuFallback. In modes 1 and 2, a valid candidate ends in dispatchedGpu;
a valid candidate that cannot reach dispatch ends in allocationFailure.

The current implementation has no explicit single-bone execution route.
Therefore explicitSingleBoneRoute is expected to remain zero. singleBoneObserved
is a separate observation counter and does not claim that those surfaces were
rerouted. This distinction preserves D06: classifier evidence alone is not
permission to promote a surface.

The validator rejects a compute candidate when:

  - its triangle/source/current-output range is unavailable;
  - current joint data is unavailable;
  - any of the four indices read by the current shader is outside jointCount;
  - a source position is non-finite; or
  - packed byte weights do not sum to 255 within one quantization unit.

The current shader reads all four joint indices even when a corresponding
weight is zero, so validation intentionally checks all four indices.

READBACK CONTRACT
-----------------
The one-shot command samples at most 24 vertices. It chooses local vertex 0,
the midpoint, and the last vertex from successive dispatched surfaces.

On the one-shot frame, GPU current output ranges and valid GPU previous-output
ranges are first filled with zero sentinels. Mode 2 also replaces the CPU seed
in dispatched dynamic ranges with the sentinel before compute. A passing sample
therefore proves that compute overwrote the sentinel; it cannot pass merely
because a CPU seed survived.

Every sample retains:

  entity index
  model name
  captured draw-surface index
  skinned record index
  local vertex index
  bind-pose position
  four joint indices and four weights
  same-frame CPU and GPU current positions
  CPU and GPU previous positions when valid previous joints exist
  derived CPU and GPU current-to-previous motion
  previous-history invalid-reason flags
  temporal-state flags

The tolerance is declared before evaluation:

  absolute position tolerance  0.001
  relative position tolerance  0.00001
  finite values required       yes

Each component must satisfy:

  abs(cpu - gpu) <= absolute + relative * max(1, abs(cpu), abs(gpu))

ACCEPTANCE / ESCALATION
-----------------------
Accept the observability plumbing only when every capture has exact=1 and all
available parity summaries pass.

Stop and preserve the log if any of these occurs:

  exact=0
  allocationFailure greater than zero
  invalidWeightsOrJoints greater than zero
  a non-finite output
  any current/previous/motion failure
  a mode 2 bind pose, corrupt surface, crash, or missing skinned geometry

A localized numeric mismatch is evidence for GEO-07 unless the copied offsets or
CPU reference in the GEO-03 sample are demonstrably wrong. Do not remove CPU
pre-skinning or claim a performance win from this test.
