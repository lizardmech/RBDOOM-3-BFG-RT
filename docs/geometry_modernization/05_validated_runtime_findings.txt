GPU-SKINNING NUMERIC PARITY RESULT
----------------------------------
GEO-03 added an exact per-surface result funnel and bounded current/previous
GPU readback. The first capture, geometry_geo13.log, exposed that the existing
Vulkan compute scaffold had never proved a write:

  mode 1 current output   zero for 24/24 samples
  mode 2 current output   matched its CPU upload seed
  previous output         matched its CPU upload seed

SPIR-V disassembly showed UAV registers at Vulkan bindings 384 and 385 while
the C++ binding layout overrode the UAV base to zero. Correcting the C++ layout
to the compiled ABI and zero-seeding dispatched output ranges converted the
readback into independent compute proof.

The corrected geometry_geo14.log reported:

  mode 1/2 candidates/resultTotal/exact    15/15/1 in both modes
  mode 1/2 dispatchedGpu                   15 in both modes
  sentinel current/previous ranges         5,371/5,371 in both modes
  sampled current/previous/motion failures 0/0/0 in both modes
  non-finite outputs                       0
  maximum observed error                   0.0000152588
  declared tolerance                       abs 0.001 + rel 0.00001

The samples covered one-, two-, three-, and four-weight vertices. The funnel
observed two single-bone surfaces, but the original first-eight-surface sampler
did not read those surfaces back. This accepts the Vulkan binding correction
and same-scene staged-joint parity for the sampled surfaces. It does not
authorize removal of CPU pre-skinning or claim the authoritative raster
jointCache cutover; those remain GEO-07 work. The sampler now prioritizes
requested asset identities, distinct models, and single-bone observations.
geometry_geo15.log then closed the missing asset-coverage gap:

  mode 1 candidates/dispatched/exact          7 / 7 / 1
  mode 2 candidates/dispatched/exact         23 / 23 / 1
  mode 2 single-bone surfaces observed        3
  sampled vertices per mode                  24
  current/previous/motion failures            0 / 0 / 0
  non-finite outputs                          0
  maximum observed error                      0.0000610352

The mode 2 sample explicitly covered player surfaces, two Fatzombie entities,
an ordinary maintenance zombie, mixed four-weight vertices, and two proven
single-bone chair surfaces. Current-position parity passed for every sample,
and available previous-position/motion parity also passed.

This capture also exposed a narrower temporal-contract gap: every sampled
Fatzombie and maintenance-zombie surface reported hasPrevious=0, including a
Fatzombie observed in both captures more than 1,200 frames apart. Player and
prop surfaces did have valid previous data. This is not a numeric GPU-skinning
failure; previous parity is skipped when the upstream surface-history contract
rejects a match. GEO-03 now logs the record's invalid-reason and temporal-state
flags so the next capture can distinguish spawn invalidation from unstable
animated-surface identity before any production identity change is considered.
Spawn/despawn, offscreen/return, PDA, and the full mode transition remain
pending.

geometry_geo16.log narrowed the monster-history rejection:

  mode 1 Fatzombie invalid/temporal   0x00000001 / 0x00000000
  mode 2 Fatzombie invalid/temporal   0x00000002 / 0x00000000
  stable mode 2 actors/props          0x00000000 / 0x0000007f

Bit 0 is NO_PREVIOUS_FRAME: at the mode 1 observation, both retained previous
records and the retained previous vertex stream were empty. Bit 1 is
NO_PREVIOUS_SURFACE: at the later mode 2 observation, a previous frame existed,
but no record matched the Fatzombie bridge key. The loose key currently
requires entity index, entityDef pointer, source-model pointer, and transient
triangle pointer to all match. Because the rejection occurs before topology,
skeleton, material, transform, and retained-buffer checks, none of those later
contracts has failed.

The GEO-03 diagnostic now reports same-entity candidates and compares
entityDef/model/triangle pointers plus drawSurf modelSurfaceIndex. This remains
passive observability: production matching is unchanged. If the stable entity,
model, and model-surface ordinal match while only the triangle pointer differs,
the durable identity repair belongs to GEO-04/GEO-07 rather than this ticket.

geometry_geo17.log did not demonstrate pointer churn. The capture followed two
Fatzombie spawn commands and reported:

  Fatzombie previous identity candidates     0
  mode 2 candidates/dispatched/exact         17 / 17 / 1
  samples/current/previous/motion failures   24 / 0 / 0 / 0
  non-finite outputs                         0
  maximum observed error                     0.0000152588

`sameEntityCandidates=0` proves that the immediately preceding captured frame
contained no record for entity 1065. There was therefore no prior key whose
pointer components could disagree. This is correct first-observation or
visibility-return invalidation, not evidence authorizing a production identity
change. A settled back-to-back pair without spawning or camera movement remains
necessary: the second capture must either acquire valid previous history,
report intermittent same-entity absence again, or expose an actual component
mismatch.

geometry_geo18.log supplied that pair. Two settled Fatzombies were present in
both one-shots. Their identity values were unchanged across frames 1590 and
1982:

  entity 120  modelSurface 0  entityDef/model/tri unchanged
  entity 1064 modelSurface 0  entityDef/model/tri unchanged

Both captures nevertheless reported sameEntityCandidates=0 and
NO_PREVIOUS_SURFACE for both monsters. The two numeric summaries remained
clean:

  candidates/dispatched/exact         10 / 10 / 1 in both captures
  samples                              24 in both captures
  current/previous/motion failures      0 / 0 / 0
  non-finite outputs                    0
  maximum observed error               0.0001220703

This rules out pointer churn as the cause of the Fatzombie history loss. The
capture path consumes only the current viewDef drawSurf list, while
PathTracePrimaryPass::Execute runs for every 3D DrawViewInternal invocation,
including subviews. One global m_smokePreviousSkinnedSurfaceRecords vector is
replaced after every invocation. History ownership is therefore "last 3D view
wins", not same-logical-view history. A later view that omits the Fatzombie can
erase its prior record while actors shared by both views retain valid history.

GEO-03 has proved current GPU parity and available previous/motion parity. It
must not hide this ownership defect by weakening surface matching. Canonical
logical-view/history ownership is now a mandatory GEO-04 contract input and
GEO-07 must not make this global last-view bridge authoritative.

VALIDATED PRIORITY ORDER
------------------------
1. Reproduce, instrument, and fix the PT-only comm1 static failure.
2. Add GPU-skinning counters and GPU-versus-CPU parity readback.
3. Establish one mesh registry plus per-world instance registries in shadow
   mode, driven by existing Add/Update/Free lifecycle hooks.
4. Make GPU skinning the authoritative skinned-position producer.
5. Replace the merged skinned BLAS rebuild with per-instance update/refit.
6. Move static world geometry to portal-area/size-bounded bucket BLASes.
7. Add build budgets, correct in-flight lifetimes, and compaction.
8. Measure and adopt attribute compression; remove legacy hard caps only
   as each old route loses all mandatory consumers.
9. Retain a small explicit dynamic fallback only for particles, callbacks,
   GUIs where supported, and true transients.

- Skinned geometry needs per-instance state; do not share one live BLAS per
  character model merely because the source mesh is shared.
- Existing GPU mode 2 is visually viable but provides no CPU-cost win.
- Runtime material IDs can enter the material universe; texture safety is a
  separate contract.
