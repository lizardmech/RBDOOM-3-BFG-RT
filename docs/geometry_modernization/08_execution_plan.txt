Geometry modernization - ordered execution plan
================================================
Status: completed controlling phase plan, updated 2026-07-30.

OBJECTIVE
---------
Replace the three coexisting PT geometry routes with a measured, incremental
system built around shared immutable mesh records, per-render-world instances,
per-instance skinned outputs, and portal-area static buckets. Preserve all
current shading, motion, material, emissive, and transient consumers while each
producer migrates.

ORDER AND DEPENDENCIES
----------------------
Execute the tickets in tasks/ in this order:

  PHASE A - freeze evidence and remove known correctness uncertainty
    GEO-00 runtime baseline and reproducible artifacts
      -> GEO-01 comm1 PT-only static contract instrumentation
      -> GEO-02 narrow comm1 static fix
      -> GEO-03 GPU-skinning observability and parity

  PHASE B - establish the common identity/ownership/storage foundation
    GEO-04 canonical mesh/instance ABI and consumer map
      -> GEO-05 per-world lifecycle shadow registry
      -> GEO-06 pooled mesh ingestion and shared-rigid compare route

The slice-6 entry audit rejects CPU pre-skin removal as an independent GEO-07
change. AppendSmokeSurfaceGeometry currently produces the only world-space
skinned vertex stream consumed by the merged dynamic BLAS. The accepted
mode-1 output is a separate ShaderResource buffer and is not referenced by any
BLAS. Skipping the CPU transform before changing traversal would therefore
feed bind-pose/invalid positions to the live BLAS. Feeding the new output to a
BLAS is exactly the GEO-08 ownership change that the GEO-07 guardrail defers.

The order is corrected as follows:

  1. GEO-07 is accepted through the validated GPU source/joint/output producer
     and exact failure funnel. Full CPU capture remains the rollback/reference
     path.
  2. GEO-08 first adds per-instance updateable BLAS state and comparison TLAS
     routing from the accepted output ranges, without removing the merged
     dynamic path.
  3. Only after GEO-08 proves compute -> barrier -> BLAS build/update -> TLAS
     traversal and hit/material/motion parity may eligible surfaces leave the
     merged dynamic capture and skip full CPU pre-skinning.
  4. Structural ineligibility must be known before capture and stays on the CPU
     route. A failure discovered after CPU capture has been skipped cannot
     truthfully claim same-frame CPU fallback; its explicit fail-safe must be a
     validated prior-pose hold or route suppression, never bind-pose output.

This is a dependency correction, not a relaxation of the Phase C gate. CPU
pre-skin removal remains required before Phase C completes, but it lands with
the GEO-08 traversal cutover rather than before it.

ROLLBACK PHILOSOPHY
-------------------
Until GEO-13, each migration lane retains one default-off master gate that can
restore the last verified producer without changing unrelated rendering lanes.
Rollback is a normal validation tool, not a substitute for fixing a mismatch.

PERFORMANCE TARGETS
-------------------
Targets are acceptance directions, not invented guarantees:

  - eliminate the 9-10 ms CPU skinning sub-step measured in Capture B for
    eligible GPU-skinned surfaces;
  - make immutable source geometry upload scale with unique meshes, not frames
    or instances;
  - replace full merged skinned BLAS rebuild work with per-instance updates plus
    bounded periodic rebuilds;
  - make static BLAS/TLAS work scale with dirty/active buckets;
  - remove whole-payload byte hashing from steady immutable geometry;
  - admit modern assets by checked memory budget rather than compile-time caps.

If measurements contradict one of these targets, the owning ticket stops and
updates the decision register before later tickets proceed.
