Geometry modernization - decision register
===========================================
Status: controlling decisions, 2026-07-23.

This register converts measured facts into implementation constraints. A
worker may challenge a decision only with a current-code contradiction or a
reproducible measurement. Record the contradiction before changing course.

D01. MIGRATION SHAPE
--------------------
Decision: extend the working rigid-route concepts into a shared mesh registry
and per-render-world instance registry. Run new paths in shadow/compare mode
before switching a consumer. Do not introduce a fourth independent geometry
universe.

D02. THREE ACCEL OWNERSHIP SHAPES, NOT ONE BLAS GRANULARITY
-----------------------------------------------------------
Decision:

  authored static world  -> portal-area, then size-bounded bucket BLASes;
  rigid/model geometry   -> one shared BLAS per immutable mesh record;
  true skinned geometry  -> shared source mesh plus one mutable position
                            stream and updateable BLAS per live instance.

Reason: the comm1 failure had 609 active static surfaces. One BLAS/TLAS
instance per static surface would exceed the current total instance budget
once rigids are included. A single retained monolith cannot express the
active portal-area set safely. Area/size buckets provide the required middle
granularity.

D03. TLAS POLICY
----------------
Decision: keep a full TLAS rebuild per frame. Measured totals were 64-113 out
of 512. Do not add PTLAS or GPU-driven instance culling. Resolve in-flight
result/instance-buffer lifetime before changing ownership; double-buffer per
world unless inspection proves the current submission lifetime sufficient.

D04. SKINNED INSTANCE POLICY
----------------------------
Decision: correctness is per instance. Share immutable bind-pose source,
indices, attributes, materials, and skin-weight data by mesh; do not share
live output positions or the updateable BLAS between independently animated
entities. Pose-sharing is deferred.

D05. GPU-SKINNING SOURCE AND FALLBACK
-------------------------------------
Decision: the authoritative GPU path consumes the engine's raster jointCache,
not retained frontend model pointers. During migration:

  r_useGPUSkinning=1 -> eligible for authoritative PT GPU skinning;
  r_useGPUSkinning=0 -> remain on the legacy CPU-deformed dynamic fallback;
  any GPU gate fail  -> named failure plus an explicit CPU/held-pose fallback,
                        never silent bind pose.

Do not remove CPU pre-skinning until GEO-03 parity readback passes and GEO-07
provides loud readiness/failure accounting.

D06. SINGLE-BONE MD5 POLICY
----------------------------
Decision: keep single-bone surfaces as rigid-promotion candidates. Promote
only when the canonical snapshot proves one stable joint controls the whole
surface and supplies current/previous joint transforms. Mixed surfaces stay
true-deforming. The measured classifier split is evidence to continue the
lane, not enough to skip the proof.

D07. LIVENESS AND EVICTION
--------------------------
Decision: Add/Update/Free entityDef hooks are the liveness authority for
instances. Area walks and drawSurf mirrors are validation/discovery safety
nets during migration. Once exact liveness is authoritative, frame age is
not allowed to delete live instances; memory-pressure eviction applies only
to unreferenced mesh/BLAS storage.

D08. STATIC ACTIVE-SET POLICY
-----------------------------
Decision: the PT active static set follows portal-area selection. Inactive
resident buckets may keep GPU memory, but must not be traversable through an
active TLAS instance. Active-set membership, bucket BLAS handles, route-table
records, and shader addressing must share one generation token.

D09. MATERIAL AND EMISSIVE OWNERSHIP
------------------------------------
Decision: geometry registry records carry stable material IDs and registration-
time summaries, but material texture safety remains owned by the material/
texture registries. The Fatzombie descriptor failure is a separate ticket/lane.
Emissive triangle identities must be derived from mesh identity + local
primitive + instance identity, not transient merged-buffer offsets.

D10. MOTION CONTRACT
--------------------
Decision: no geometry route may become default without current and previous
position/transform data consumed by the existing ReSTIR DI/GI and DLSS-RR
motion paths. Layout and motion-vector bridge ship in the same ticket slice.

D11. DYNAMIC FALLBACK
---------------------
Decision: retain a small per-frame merged fallback for particles, true
transients, callback-generated surfaces, and explicitly supported GUI cases.
After cutover it must reject static, rigid, and eligible skinned surfaces with
named counters. It must have configurable byte/surface budgets and report
deferred/dropped work; silent cap refusal is forbidden.

D12. BUILD SCHEDULING
---------------------
Decision: start with separate command lists on the same Vulkan queue, submitted
BLAS work before TLAS work without a CPU fence wait. Budget both scratch bytes
and build count per frame. A real async-compute queue is deferred until Nsight
shows same-queue contention worth the ownership complexity.

D13. STORAGE AND ATTRIBUTES
---------------------------
Decision: split raw float3 positions from attributes immediately at the new
registry ABI. Keep full-fidelity attributes until the UV survey and shader A/B
settle encoding. Compression is not allowed to block registry/skinning work and
is not allowed to land without a wide-UV escape.

D14. HARD CAPS
--------------
Decision: replace compile-time scene/capture limits with checked 64-bit byte
budgets and paged/suballocated storage. Remove each old cap only when the route
it protects has no mandatory static/rigid/skinned consumer. No ticket may raise
a cap and call the scalability problem solved.

D15. PT-ONLY COMM1 FAILURE
--------------------------
Decision: treat maps/game/comm1.map area 41 as a phase-zero regression gate.
The fix must identify the first disagreeing producer/consumer tuple. A broad
static rewrite is not an acceptable diagnostic. Preserve raster behavior and
add a durable automated or deterministic replay check where practical.

D16. LOGICAL VIEW HISTORY OWNERSHIP
----------------------------------
Decision: current and previous geometry must belong to the same logical render
view/history owner. A process-global "last 3D view wins" record is not an
authoritative temporal source because DrawViewInternal may execute PT for
multiple 3D views, including subviews. Missing same-owner history invalidates
motion; it must not be repaired by loose cross-view surface matching.

D17. IDENTITY, CONTENT, STORAGE, AND ROUTING ARE DISTINCT
---------------------------------------------------------
Decision: canonical MeshKey and InstanceKey contain only durable source/world/
slot/surface identity. Material binding, classifier state, transforms, content
revision, buffer offsets, cache addresses, AS handles, route indices and frame
numbers are separate record fields/generations. Hash equality alone never
merges records; full tuple equality is authoritative and collisions are
reported.

D18. WORLD AND INSTANCE REUSE
-----------------------------
Decision: a non-zero monotonic WorldKey is allocated at PT render-world
registration and invalidated by explicit teardown. InstanceKey is WorldKey +
renderDef slot/generation + sub-instance/surface ordinal. Raw renderWorld
pointers, map names and timestamps are not persistent identity. Free advances
slot generation before reuse; model/material/transform changes revise a live
record without redefining its entity-slot identity.

D19. HARDWARE INSTANCE IDS AND OFFSETS
--------------------------------------
Decision: TLAS InstanceID and shader route indices are checked dense uint32
frame/page mappings, not canonical instance hashes. Registry storage uses
checked uint64 byte offsets/sizes; uint32 narrowing is allowed only after page
base subtraction, alignment/range checks and a named rejection result.

D20. EMISSIVE GEOMETRY IDENTITY
-------------------------------
Decision: emissive temporal identity is InstanceKey + MeshKey + local primitive
ordinal. Material-table index, classifier flags and transient merged-buffer
offsets are excluded. Material/emission revisions are compatibility inputs
which may reset payload history without pretending the geometric primitive is
a different object.

D18. GEO-07 JOINTCACHE BINDING STRATEGY
---------------------------------------
Decision: use a staged compact GPU joint array for the first authoritative PT
skinning cut, not direct binding of the raster vertex-cache joint buffer.

R_SetupDrawSurfJoints already publishes the authoritative current pose through
drawSurf_t::jointCache. On the backend, resolve that handle to the current
draw-list joint buffer and exact byte range, then issue bounded GPU-to-GPU
copies into a PT-owned compact 48-byte-matrix buffer on the scene command list.
This preserves the validated skinning shader ABI and avoids CPU pose reads.

Direct binding is deferred because the raster buffer has 16-byte structured
stride, whole-frame scope and only vertex-cache-frame lifetime. It does not
provide same-owner previous state. The compact current buffer is retained as
previous input only by the matching PtCanonicalHistoryOwnerKey. Subviews must
not read or overwrite PrimaryGameplay history.

D21. GPU-SKINNING PARITY ORACLES MUST BE FRAME-OWNED
----------------------------------------------------
Decision: do not use tri->staticModelWithJoints->jointsInverted as a backend
numeric oracle for a submitted draw surface. drawSurf_t explicitly identifies
frontEndGeo as mutable frontend-owned state, and the SMP loop can regenerate a
cached dynamic model in place while the backend executes the previous command
buffer. The renderer jointCache retains the submitted pose; the late CPU model
pointer may contain a newer pose.

Production mode consumes jointCache without a CPU pose copy. When exact
same-frame validation is armed, retain a bounded frame-owned copy at the
R_SetupDrawSurfJoints upload boundary and transport it through drawSurf_t. This
copy is validation-only and must be removed from production measurements.

D22. SKINNED IMMUTABLE SOURCE PRODUCER
--------------------------------------
Decision: the first canonical skinned source is the MD5 model's load-time
deformInfo vertex/index geometry, addressed by model-surface ordinal. The
resolved per-frame srfTriangles_t is an animated snapshot and is not eligible
as immutable source ownership.

Admission requires the exact SkinnedBindSource/Skinned pair, an MD5 source
model, matching canonical vertex/index counts, and matching index-topology
signature. The registry value-copies the full source payload and retains no
model/deformInfo pointer. Duplicate actors may share this MeshKey/source
record, but their mutable output ranges, pose history and later BLAS state
remain keyed by full InstanceKey and may not alias.

D23. SKINNED MUTABLE OUTPUT OWNERSHIP AND RETIREMENT
----------------------------------------------------
Decision: allocate skinned mutable output ranges by the complete canonical
SkinnedSurface InstanceKey. MeshKey sharing affects only immutable source
storage. Different InstanceKeys never alias current output, previous output,
pose history, or later acceleration-structure state.

Within one storage generation, stable key/count observations reuse their exact
range. Resizes and new keys append; retired bytes are tombstoned rather than
reused while they may be in flight. Exact identity Remove deltas retire exact
keys, and an explicitly retired render-def generation cannot resurrect. A
replacement entity-slot generation receives a new key/range.

Capacity growth and world replacement create monotonic storage generations.
The old generation remains pending until the GPU-lifetime owner explicitly
acknowledges completion; CPU frame age is not a substitute for that signal.
Slice 5B is planner-only. Physical buffer creation, copy/rewrite behavior and
dispatch routing belong to slice 5C and must keep the current route live until
numeric comparison passes.

D24. FIRST SHARED-SOURCE COMPARISON ROUTE
-----------------------------------------
Decision: validate immutable-source ownership without changing the skinning
shader ABI or live BLAS route. In mode 1 with both canonical gates enabled,
convert the value-owned slice-5A record to PathTraceSkinnedSourceVertex once
per exact MeshKey/checksum in the current comparison build, then dispatch every
instance to its slice-5B full-InstanceKey output range.

This deliberately separates contract proof from a direct binding of the split
GEO-06 GPU position/attribute pools. It removes duplicate per-instance source
packing within the frame and proves two independently posed actors can share
source bytes while writing non-overlapping outputs. Persistent source upload,
CPU pre-skin removal and live BLAS use require their later gates and evidence.
Disabling the canonical source-registry gate restores the prior transient
comparison layout.

DEFERRED OUTSIDE THIS PACKET
----------------------------
- RTX Mega Geometry / cluster AS implementation.
- Authored or runtime LOD.
- Pose sharing / animation instancing.
- A custom software BVH or non-hardware traversal path.
- DX12 shader or runtime validation.
- General material-texture remediation, including the Fatzombie descriptor.
