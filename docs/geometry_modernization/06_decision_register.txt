Geometry modernization - decision register
===========================================
Status: controlling decisions, 2026-07-23.

This register converts measured facts into implementation constraints. A
worker may challenge a decision only with a current-code contradiction or a
reproducible measurement. Record the contradiction before changing course.

D01. MIGRATION SHAPE
--------------------
Decision: extend the working rigid-route concepts into a shared mesh registry
and per-render-world instance registry. Run new paths in shadow/compare mode
before switching a consumer. Do not introduce a fourth independent geometry
universe.

D02. THREE ACCEL OWNERSHIP SHAPES, NOT ONE BLAS GRANULARITY
-----------------------------------------------------------
Decision:

  authored static world  -> portal-area, then size-bounded bucket BLASes;
  rigid/model geometry   -> one shared BLAS per immutable mesh record;
  true skinned geometry  -> shared source mesh plus one mutable position
                            stream and updateable BLAS per live instance.

Reason: the comm1 failure had 609 active static surfaces. One BLAS/TLAS
instance per static surface would exceed the current total instance budget
once rigids are included. A single retained monolith cannot express the
active portal-area set safely. Area/size buckets provide the required middle
granularity.

D03. TLAS POLICY
----------------
Decision: keep a full TLAS rebuild per frame. Measured totals were 64-113 out
of 512. Do not add PTLAS or GPU-driven instance culling. Resolve in-flight
result/instance-buffer lifetime before changing ownership; double-buffer per
world unless inspection proves the current submission lifetime sufficient.

D04. SKINNED INSTANCE POLICY
----------------------------
Decision: correctness is per instance. Share immutable bind-pose source,
indices, attributes, materials, and skin-weight data by mesh; do not share
live output positions or the updateable BLAS between independently animated
entities. Pose-sharing is deferred.

D05. GPU-SKINNING SOURCE AND FALLBACK
-------------------------------------
Decision: the authoritative GPU path consumes the engine's raster jointCache,
not retained frontend model pointers. During migration:

  r_useGPUSkinning=1 -> eligible for authoritative PT GPU skinning;
  r_useGPUSkinning=0 -> remain on the legacy CPU-deformed dynamic fallback;
  any GPU gate fail  -> named failure plus an explicit CPU/held-pose fallback,
                        never silent bind pose.

Do not remove CPU pre-skinning until GEO-03 parity readback passes and GEO-07
provides loud readiness/failure accounting.

D06. SINGLE-BONE MD5 POLICY
----------------------------
Decision: keep single-bone surfaces as rigid-promotion candidates. Promote
only when the canonical snapshot proves one stable joint controls the whole
surface and supplies current/previous joint transforms. Mixed surfaces stay
true-deforming. The measured classifier split is evidence to continue the
lane, not enough to skip the proof.

D07. LIVENESS AND EVICTION
--------------------------
Decision: Add/Update/Free entityDef hooks are the liveness authority for
instances. Area walks and drawSurf mirrors are validation/discovery safety
nets during migration. Once exact liveness is authoritative, frame age is
not allowed to delete live instances; memory-pressure eviction applies only
to unreferenced mesh/BLAS storage.

D08. STATIC ACTIVE-SET POLICY
-----------------------------
Decision: the PT active static set follows portal-area selection. Inactive
resident buckets may keep GPU memory, but must not be traversable through an
active TLAS instance. Active-set membership, bucket BLAS handles, route-table
records, and shader addressing must share one generation token.

D09. MATERIAL AND EMISSIVE OWNERSHIP
------------------------------------
Decision: geometry registry records carry stable material IDs and registration-
time summaries, but material texture safety remains owned by the material/
texture registries. The Fatzombie descriptor failure is a separate ticket/lane.
Emissive triangle identities must be derived from mesh identity + local
primitive + instance identity, not transient merged-buffer offsets.

D10. MOTION CONTRACT
--------------------
Decision: no geometry route may become default without current and previous
position/transform data consumed by the existing ReSTIR DI/GI and DLSS-RR
motion paths. Layout and motion-vector bridge ship in the same ticket slice.

D11. DYNAMIC FALLBACK
---------------------
Decision: retain a small per-frame merged fallback for particles, true
transients, callback-generated surfaces, and explicitly supported GUI cases.
After cutover it must reject static, rigid, and eligible skinned surfaces with
named counters. It must have configurable byte/surface budgets and report
deferred/dropped work; silent cap refusal is forbidden.

D12. BUILD SCHEDULING
---------------------
Decision: start with separate command lists on the same Vulkan queue, submitted
BLAS work before TLAS work without a CPU fence wait. Budget both scratch bytes
and build count per frame. A real async-compute queue is deferred until Nsight
shows same-queue contention worth the ownership complexity.

D13. STORAGE AND ATTRIBUTES
---------------------------
Decision: split raw float3 positions from attributes immediately at the new
registry ABI. Keep full-fidelity attributes until the UV survey and shader A/B
settle encoding. Compression is not allowed to block registry/skinning work and
is not allowed to land without a wide-UV escape.

D14. HARD CAPS
--------------
Decision: replace compile-time scene/capture limits with checked 64-bit byte
budgets and paged/suballocated storage. Remove each old cap only when the route
it protects has no mandatory static/rigid/skinned consumer. No ticket may raise
a cap and call the scalability problem solved.

D15. PT-ONLY COMM1 FAILURE
--------------------------
Decision: treat maps/game/comm1.map area 41 as a phase-zero regression gate.
The fix must identify the first disagreeing producer/consumer tuple. A broad
static rewrite is not an acceptable diagnostic. Preserve raster behavior and
add a durable automated or deterministic replay check where practical.

D16. LOGICAL VIEW HISTORY OWNERSHIP
----------------------------------
Decision: current and previous geometry must belong to the same logical render
view/history owner. A process-global "last 3D view wins" record is not an
authoritative temporal source because DrawViewInternal may execute PT for
multiple 3D views, including subviews. Missing same-owner history invalidates
motion; it must not be repaired by loose cross-view surface matching.

D17. IDENTITY, CONTENT, STORAGE, AND ROUTING ARE DISTINCT
---------------------------------------------------------
Decision: canonical MeshKey and InstanceKey contain only durable source/world/
slot/surface identity. Material binding, classifier state, transforms, content
revision, buffer offsets, cache addresses, AS handles, route indices and frame
numbers are separate record fields/generations. Hash equality alone never
merges records; full tuple equality is authoritative and collisions are
reported.

D18. WORLD AND INSTANCE REUSE
-----------------------------
Decision: a non-zero monotonic WorldKey is allocated at PT render-world
registration and invalidated by explicit teardown. InstanceKey is WorldKey +
renderDef slot/generation + sub-instance/surface ordinal. Raw renderWorld
pointers, map names and timestamps are not persistent identity. Free advances
slot generation before reuse; model/material/transform changes revise a live
record without redefining its entity-slot identity.

D19. HARDWARE INSTANCE IDS AND OFFSETS
--------------------------------------
Decision: TLAS InstanceID and shader route indices are checked dense uint32
frame/page mappings, not canonical instance hashes. Registry storage uses
checked uint64 byte offsets/sizes; uint32 narrowing is allowed only after page
base subtraction, alignment/range checks and a named rejection result.

D20. EMISSIVE GEOMETRY IDENTITY
-------------------------------
Decision: emissive temporal identity is InstanceKey + MeshKey + local primitive
ordinal. Material-table index, classifier flags and transient merged-buffer
offsets are excluded. Material/emission revisions are compatibility inputs
which may reset payload history without pretending the geometric primitive is
a different object.

D18. GEO-07 JOINTCACHE BINDING STRATEGY
---------------------------------------
Decision: use a staged compact GPU joint array for the first authoritative PT
skinning cut, not direct binding of the raster vertex-cache joint buffer.

R_SetupDrawSurfJoints already publishes the authoritative current pose through
drawSurf_t::jointCache. On the backend, resolve that handle to the current
draw-list joint buffer and exact byte range, then issue bounded GPU-to-GPU
copies into a PT-owned compact 48-byte-matrix buffer on the scene command list.
This preserves the validated skinning shader ABI and avoids CPU pose reads.

Direct binding is deferred because the raster buffer has 16-byte structured
stride, whole-frame scope and only vertex-cache-frame lifetime. It does not
provide same-owner previous state. The compact current buffer is retained as
previous input only by the matching PtCanonicalHistoryOwnerKey. Subviews must
not read or overwrite PrimaryGameplay history.

D21. GPU-SKINNING PARITY ORACLES MUST BE FRAME-OWNED
----------------------------------------------------
Decision: do not use tri->staticModelWithJoints->jointsInverted as a backend
numeric oracle for a submitted draw surface. drawSurf_t explicitly identifies
frontEndGeo as mutable frontend-owned state, and the SMP loop can regenerate a
cached dynamic model in place while the backend executes the previous command
buffer. The renderer jointCache retains the submitted pose; the late CPU model
pointer may contain a newer pose.

Production mode consumes jointCache without a CPU pose copy. When exact
same-frame validation is armed, retain a bounded frame-owned copy at the
R_SetupDrawSurfJoints upload boundary and transport it through drawSurf_t. This
copy is validation-only and must be removed from production measurements.

D22. SKINNED IMMUTABLE SOURCE PRODUCER
--------------------------------------
Decision: the first canonical skinned source is the MD5 model's load-time
deformInfo vertex/index geometry, addressed by model-surface ordinal. The
resolved per-frame srfTriangles_t is an animated snapshot and is not eligible
as immutable source ownership.

Admission requires the exact SkinnedBindSource/Skinned pair, an MD5 source
model, matching canonical vertex/index counts, and matching index-topology
signature. The registry value-copies the full source payload and retains no
model/deformInfo pointer. Duplicate actors may share this MeshKey/source
record, but their mutable output ranges, pose history and later BLAS state
remain keyed by full InstanceKey and may not alias.

D23. SKINNED MUTABLE OUTPUT OWNERSHIP AND RETIREMENT
----------------------------------------------------
Decision: allocate skinned mutable output ranges by the complete canonical
SkinnedSurface InstanceKey. MeshKey sharing affects only immutable source
storage. Different InstanceKeys never alias current output, previous output,
pose history, or later acceleration-structure state.

Within one storage generation, stable key/count observations reuse their exact
range. Resizes and new keys append; retired bytes are tombstoned rather than
reused while they may be in flight. Exact identity Remove deltas retire exact
keys, and an explicitly retired render-def generation cannot resurrect. A
replacement entity-slot generation receives a new key/range.

Capacity growth and world replacement create monotonic storage generations.
The old generation remains pending until the GPU-lifetime owner explicitly
acknowledges completion; CPU frame age is not a substitute for that signal.
Slice 5B is planner-only. Physical buffer creation, copy/rewrite behavior and
dispatch routing belong to slice 5C and must keep the current route live until
numeric comparison passes.

D24. FIRST SHARED-SOURCE COMPARISON ROUTE
-----------------------------------------
Decision: validate immutable-source ownership without changing the skinning
shader ABI or live BLAS route. In mode 1 with both canonical gates enabled,
convert the value-owned slice-5A record to PathTraceSkinnedSourceVertex once
per exact MeshKey/checksum in the current comparison build, then dispatch every
instance to its slice-5B full-InstanceKey output range.

This deliberately separates contract proof from a direct binding of the split
GEO-06 GPU position/attribute pools. It removes duplicate per-instance source
packing within the frame and proves two independently posed actors can share
source bytes while writing non-overlapping outputs. Persistent source upload,
CPU pre-skin removal and live BLAS use require their later gates and evidence.
Disabling the canonical source-registry gate restores the prior transient
comparison layout.

D25. CPU PRE-SKIN REMOVAL CUTS OVER WITH PER-INSTANCE BLAS TRAVERSAL
--------------------------------------------------------------------
Decision: reject the proposed standalone GEO-07 CPU pre-skin-removal slice.
The CPU-skinned dynamic vertex stream is still the sole vertex input to the
live merged dynamic BLAS. The accepted GEO-07 mode-1 output is separate and no
BLAS references it. Removing the CPU transform first would make live traversal
consume bind-pose or invalid positions; pointing traversal at the new output is
the GEO-08 ownership change.

GEO-07 therefore completes the validated GPU producer and exact failure funnel.
GEO-08 owns the comparison BLAS/TLAS route and the eventual capture split. Only
after per-instance hit/material/motion parity passes may eligible surfaces stop
performing full CPU pre-skin/copy. Structural ineligibility must be decided
before that split and retains same-frame CPU fallback. A late failure after CPU
work was skipped must use a validated prior-pose hold or suppress the instance;
it must never expose bind pose or be mislabeled as CPU fallback.

D26. SKINNED BLAS STATE IS FULL-INSTANCE AND GENERATION-EXACT
-------------------------------------------------------------
Decision: one PtCanonicalInstanceKey with SkinnedSurface kind owns one BLAS
state record. Shared MeshKey/source data never shares mutable AS state.

An initial exact observation requests build. A stable source/index/output
contract requests update. Mesh topology, source checksum, source GPU index-pool
generation/range, output buffer generation/range, failed submission, forced
rebuild, or the fixed rebuild cadence requests a full rebuild. If any of these
change while work is pending, the prior planned action is invalidated rather
than submitted against stale storage.

Removal and world replacement create explicit retirement tokens. Frame age
alone does not release an AS or its referenced output generation. Slice 1 is a
pure state table and harness. Slice 2 adds physical initial-generation
ownership and live shadow observation. Slice 3 adds exact graphics-submission
completion; NVRHI AS handles and traversal remain later GEO-08 slices.

D27. PHYSICAL SKINNED OUTPUT GENERATIONS ARE ONE-TO-ONE IN SHADOW MODE
----------------------------------------------------------------------
Decision: a nonzero PtSkinnedOutputAllocator storage generation owns one
physical output buffer contract. Reuse requires the same generation, sufficient
capacity, 112-byte stride, UAV capability, and acceleration-structure-build-
input capability. A generation change forces a new handle; generation identity
is propagated through commit and retired scene packages.

Only a finalized dispatchedGpu GEO-07 job may be observed by the BLAS state
table, and only after its exact GEO-06 source GPU index range and committed
output range pass checked generation/offset/count/capacity validation.
Observation remains shadow-only: it neither creates nor submits a BLAS and
cannot affect TLAS traversal.

r_pathTracingSceneRetireFrames is an optional minimum delay only. D28 defines
the GPU-completion authority that must also pass before package release.
Physical growth/release still needs a targeted runtime exercise before
traversal cutover.

D28. RETIRED SCENE PACKAGES REQUIRE EXACT GPU EVENT COMPLETION
-------------------------------------------------------------
Decision: each replaced PT scene package owns an NVRHI IEventQuery. The query
is armed immediately after the main graphics command list is submitted. On
Vulkan this captures the queue tracking timeline semaphore's last submitted
ID; release polls that exact ID. A package without a query fails safe by
remaining retained until reset.

r_pathTracingSceneRetireFrames no longer authorizes release. It is only a
minimum additional CPU-frame delay after the event query completes. Output
allocator generations are acknowledged only after the completed packages are
dropped and neither the active package nor another retained package names the
generation. The same completion token/handle ownership pattern must contain
future per-instance BLAS and comparison TLAS handles.

geometry_geo64_auto sets the minimum delay to zero and proves that package
token 1 is armed with one pending package, then released only after token 1
completes. This accepts the completion mechanism, but not physical buffer
growth or live AS traversal.

D29. INITIAL SKINNED COMPARISON BLAS IS ONE FULL INSTANCEKEY AND TLAS-EXCLUDED
-------------------------------------------------------------------------------
Decision: each exact BuildPending SkinnedSurface record owns one comparison
BLAS resource keyed by its complete InstanceKey. The resource retains its
vertex and index buffer handles and records the exact MeshKey, source checksum,
source index generation/range, and output generation/range used to create it.
Shared immutable MeshKey/index data does not permit shared mutable BLAS state.

The first build uses the per-instance world-space PathTraceSmokeVertex output
at 112-byte stride, local R32_UINT indexes from the exact GEO-06 pool record,
and AllowUpdate + PreferFastBuild. It is recorded after the current frame's
skin compute and input-state barriers. MarkSubmitted(Build, true) occurs only
after command recording.

These handles are diagnostic comparison resources and are excluded from every
TLAS. geometry_geo65_auto proves 12/12 exact BuildPending contracts create and
submit 12/12 distinct initial builds with zero failure while existing skinning
parity remains green. This decision does not authorize PerformUpdate, rebuild
replacement, physical output growth, or traversal. Those require explicit
completion-owned retirement and separate runtime proof in the next slice.

D30. STABLE SKINNED BLAS UPDATES REUSE THE EXACT HANDLE; REPLACEMENTS DEFER
-----------------------------------------------------------------------------
Decision: UpdatePending may submit PerformUpdate only when the complete stored
resource contract still matches the current state record: full InstanceKey,
MeshKey, source checksum, source index generation/range and retained buffer,
plus output generation/range and retained buffer. A missing update owner fails
closed and becomes a later full rebuild.

RebuildPending may record a full build on the existing AllowUpdate handle when
that same complete contract is unchanged, including the fixed 60-frame cadence.
A mismatch requiring a new AS handle is counted and left pending. The old
resource is neither overwritten nor dropped because its last graphics-queue
use has not yet been tied to a completion-owned retirement package.

geometry_geo68_auto proves the stable sequence: 12 initial builds on frame 2,
12 PerformUpdate submissions on frame 3, and 12 same-handle full rebuilds on
frame 63, all exact with zero deferral/failure and no TLAS use. Slice 5B must
add event-query-protected replacement/removal retirement before changed
contracts or physical generation growth can be accepted.

D31. REPLACED AND REMOVED SKINNED BLAS OWNERS RETIRE BY EXACT QUEUE COMPLETION
-------------------------------------------------------------------------------
Decision: replacing or removing a comparison BLAS moves the exact BLAS, vertex
buffer, index buffer and contract generations into a retained retirement
package. Each package owns an NVRHI event query armed only after the graphics
command list containing its last use is submitted. CPU frame age is only an
optional minimum; package release requires the exact query to complete.

State-table retirement tokens remain ordered independently from physical-owner
packages. An exact removed InstanceKey carries its state token in the matching
package. A token with no physical owner receives an empty completion package so
later tokens cannot overtake it. Replacement and gate-off packages may carry
state token zero, but still retain their physical resources through completion.
Release advances the state table only through the greatest completed ordered
state token.

The allocator may acknowledge an old output generation only after neither an
active comparison BLAS nor a retained comparison package names that generation.
geometry_geo69_auto proves exact removal: eleven owners queue with eleven state
packages, event tokens 1..11 arm, and all eleven physical owners plus state
tokens release only after token 11 completes. geometry_geo71_auto proves
changed-contract growth: output grows from generation 1 / 1,835,008 bytes to
generation 2 / 3,670,016 bytes, twelve BLAS resources are replaced, their
packages arm and complete through token 12, and only then does the scene
completion owner acknowledge generation 1 with
`releasedStorageGenerations=1`. Fifteen exact active records and numeric
skinning parity remain green. These resources are still comparison-only and
excluded from all TLAS routes; D31 does not authorize traversal.

D32. SKINNED HIT PRIMITIVES ARE SOURCE-LOCAL AND USE A DISJOINT INSTANCE RANGE
-------------------------------------------------------------------------------
Decision: a future skinned per-surface TLAS descriptor must not reuse the
merged-dynamic InstanceID=1 meaning, and it must not enter the existing broad
`InstanceID >= 2` rigid interpretation. The ordered namespace is:

  0                                merged static
  1                                merged dynamic rollback/reference
  [2, 2 + rigidRouteCount)         canonical rigid-route records
  [2 + rigidRouteCount, ...)       per-surface skinned-route records

The hardware InstanceID is a dense frame-local route-table slot, not durable
identity. Each skinned route record retains the full InstanceKey on CPU and a
collision-checked 64-bit canonical-instance hash for GPU identity consumers.
The 24-bit hardware instance-ID limit is checked before a record is admitted.

PrimitiveIndex for a per-surface skinned BLAS is the immutable source mesh's
local primitive index. The route record therefore names the exact GEO-06
source-index range, GEO-07 current-output range, optional previous-position
range, and a per-source-primitive metadata range. Each metadata record carries
material ID, material-table index, triangle class/flags, canonical primitive
hash, and canonical-instance/source-primitive emissive identity.

Legacy merged capture may omit posed zero-area triangles. Its compact primitive
index is only comparison evidence: the pure planner proves the compact index
triples are an ordered subsequence of source topology and records a legacy
primitive index only when matched. Source-only primitives remain explicit and
receive named surface metadata; they are never silently renumbered.

geometry_geo72_auto accepts the CPU/live shadow: twelve routes occupy slots
113..124 and map all 15,962 source primitives to 15,962 legacy primitives with
zero source-only entries, rejection, identity collision, or missing motion
range. The harness separately proves the filtered source-only case and
fail-closed mismatch/duplicate/24-bit-overflow behavior. D32 does not authorize
TLAS insertion. Current HLSL consumers still interpret every InstanceID >= 2
as rigid; the next slice must replace that assumption and bind the skinned
route/metadata/current/source/previous buffers consistently across primary,
shadow, clean DI, GI, NEE/ReGIR debug, and emissive consumers.

D33. SKINNED HIT-ROUTE TRANSPORT USES A HEADERED, ALWAYS-BOUND GPU TABLE
-----------------------------------------------------------------------
Decision: every active Vulkan ray pipeline receives two persistent structured
SRVs, route records at t18 and source-local triangle metadata at t19. A route
record is exactly 80 bytes and a triangle record is exactly 36 bytes. Record
zero repeats the logical route count and total metadata count so shaders can
classify the disjoint InstanceID range without extending a per-pass constant
buffer. An empty table still uploads one zero-count route and triangle
sentinel, keeping every descriptor layout valid.

The GPU table is built only from the last accepted CPU hit-route shadow. Its
logical scene-input counts must describe the bytes actually uploaded in that
frame, not the newer shadow being prepared for the following frame. Both
buffers participate in scene-package comparison, transition signatures,
retirement capture, and reset/commit ownership.

geometry_geo73_auto and geometry_geo74_auto prove byte-exact transport:
12 records and 15,962 triangle records, 575,592 bytes, signature
de825e58306bf8f1, first InstanceID 113, and exact record/triangle/header
readback 1/1/1. All affected Vulkan pipelines initialize and no fatal,
device-removal, NVRHI-error, or validation-error marker is present. These runs
used GPU-skinning authority mode 1 and therefore do not supersede the accepted
mode-2 numeric parity evidence from geometry_geo72_auto.

D33 is transport-only. The helper ABI may classify and validate records, but
no skinned comparison BLAS enters a TLAS yet. Step 6B2 must bind the canonical
source index, current output vertex, and previous-position domains required by
hit shading, then replace every broad `InstanceID >= 2` rigid assumption with
explicit rigid and skinned ranges across primary, shadow, clean DI, GI,
NEE/ReGIR debug, motion, material, and emissive consumers.

D34. SKINNED OUTPUT ATTRIBUTES ARE WORLD-SPACE; OVERSIZED LIBRARIES STAY LIGHT
-------------------------------------------------------------------------------
Decision: the accepted GPU skinning producer writes current positions, normals,
tangents, and bitangents in world space. Its retained previous-position output
is also world space. Skinned hit and motion consumers therefore read these
values directly and must not apply ObjectToWorldKHR. Rigid route vertices remain
source-local and use the explicit current/previous transform rows stored in
their route record.

Step 6B2 binds canonical source indexes at t28, current skinned output vertices
at t29, and previous positions at t32 across the Vulkan ray/compute layouts.
Full reconstruction is enabled in the main primary/shadow path, clean-DI
transmission/spatial, ReGIR/NEE debug, material/class/UV/color, and motion
consumers.

The clean-DI sentinel and clean-GI libraries are explicit temporary exceptions.
Their unchanged baseline SPIR-V sizes are 5,929,604 and 9,385,432 bytes. Adding
the full shared route helpers causes DXC to fail legalization with SPIR-V ID
overflow. A lightweight include keeps their code generation at the exact
baseline size and keeps the new descriptors bound, but does not authorize a
skinned hit. Step 7 is blocked until these libraries are split or an equivalent
narrow boundary compiles and bounded runtime proof succeeds. Compiler flags,
DX12 builds, and disabling SPIR-V validation are not accepted workarounds.

D35. OVERSIZED RAY LIBRARIES USE COMPACT HIT MODULES AND A TWO-RECORD SBT STRIDE
-------------------------------------------------------------------------------
Decision: Vulkan ray pipelines may combine shader handles obtained from
different NVRHI shader libraries. The Vulkan backend retains each originating
module and registers it independently in one ray pipeline. Skinned instances
therefore use `instanceContributionToHitGroupIndex = 2`: primary rays select
SBT record 2 and shadow rays select record 3, preserving the existing
primary/shadow records 0/1 for static, merged-dynamic, and rigid instances.

The clean-DI sentinel implements the first half of this split. Its compact
skinned-hit library contains only the sentinel's five-word payload ABI,
t18/t19 route/triangle lookup, t13/t80 material visibility state, and the
existing primary/shadow any-hit decisions. The compiled module is 17,196
bytes, has exactly four hit exports, passes `spirv-val`, and disassembles to
bindings b2/t13/t18/t19/t80 with b2 offsets 40, 56, and 144. NVRHI appends
`SkinnedHitGroup` and `SkinnedShadowHitGroup` to the sentinel shader table.
No TLAS instance uses contribution 2 in this slice, so traversal is unchanged.

DXC `-exports` and `-export-shaders-only` were tested against the full sentinel
source and still overflowed during SPIR-V legalization. Export filtering is
therefore not an accepted substitute for a source-level compact module. Local
Remix code supports the architectural direction by assembling narrowly scoped
hit variants into a pipeline, but this repository's payload, resource, and SBT
contracts remain authoritative.

D35 is offline-only until bounded runtime pipeline creation succeeds. Clean-GI
now has the equivalent compact boundary: its 172,820-byte module preserves the
full hit payload plus alpha, translucency, and liquid-pool candidate behavior.
It exports only primary/shadow any-hit and closest-hit stages, passes Vulkan
1.2 validation, and disassembles to the intended resource bindings and b2
offsets 144/464/516/672/684/688. Both GI pipelines append the new groups at
records 2/3 without changing either monolithic GI blob. No skinned comparison
BLAS enters the shared TLAS until both mixed pipelines receive bounded runtime
creation proof and the contribution planner has exact offline assertions.

D36. GI RAYGEN PIPELINES WARM IN SOURCE-PARTITIONED, HOST-BOUNDED STEPS
-----------------------------------------------------------------------
Decision: the eager clean-GI Vulkan pipeline construction used by the first
mixed-module checkpoint is rejected. Its first user run left Windows alive and
the game progressing underneath, but starved system input badly enough that
the machine had to be shut down with the power button. There was no Vulkan
device-removed report and no new condump. This is a failed runtime gate, not an
accepted slow first-load result.

DXC export filtering is not the partition boundary: a filtered compile still
spends minutes legalizing the monolithic source before pruning. Each of the
sixteen GI raygeneration attributes is therefore source-gated. The Vulkan
build emits one debug and one production library per raygen. Every library
contains exactly:

  its one intended raygeneration entry;
  Miss and ShadowMiss;
  AnyHit, ShadowAnyHit, ClosestHit, and ShadowClosestHit.

The runtime creates one pipeline for one such library at a time. It orders
lighter modules before heavier ones, leaves fifteen ordinary frames between
pipeline builds, and does not overwrite the existing PT/DI output while
warmup is incomplete. The Vulkan backend opts these pipelines into
VK_KHR_deferred_host_operations with one joining thread and a one-millisecond
yield between driver work units. If a driver completes synchronously, the
small source-partitioned library remains the fallback bound.

`r_pathTracingCleanRestirGiPipelineWarmupLimit` is the bounded validation gate.
Its unvalidated default is 0. Value 1 allows a user run to prove only the
smallest pipeline build; values 2..15 stop after that many ordered modules and
16 permits the complete lane. Raising the value resumes from the retained
index. No partial limit makes GI dispatchable. The default may move to 16 only
after responsive 16/16 runtime acceptance.

Offline acceptance is exact: 32/32 blobs pass `spirv-val --target-env
vulkan1.2`; all 32 have the seven-entry inventory above; their combined size
is 24,526,784 bytes; and the largest single blob is 2,148,184 bytes. The
monolithic debug and production hashes remain
FDAEE58F4981A5ED662E89119FF7B87F9E629C05CE0AD6C064BFE1DF0D0B550A and
425B224669C89E9FB5DA84E6F6B2CE94E354FD0F79B3E890F37C5FA85B799FFF.
The release build and exact SBT contribution harness pass.

D36 is not runtime-accepted. The lock-producing executable is superseded and
must not be launched again. No comparison skinned BLAS enters a TLAS until a
later, explicitly bounded user run proves the partitioned warmup preserves
system responsiveness and reaches 16/16 initialization.

geometry_geo77 resolves the pre-pipeline input gate: only t28 skinned source
indexes and t29 current skinned output vertices were absent
(`route=00000300`). No skinned comparison instance exists in the TLAS at this
stage, so requiring physical skinned storage before pipeline creation was
incorrect. The GI binding now mirrors the accepted primary binding contract:
t28 falls back to the legacy dynamic index buffer and t29 to the legacy dynamic
vertex buffer until real skinned storage exists. A later TLAS cutover still
requires the exact physical buffers before contribution 2 can be selected.
Missing optional producer inputs in production view 0 disable GI for the frame
without clearing the already-valid DI/PT output magenta.

D37. RIGID BLAS IDENTITY EXCLUDES MATERIAL; ROUTE INSTANCES OWN MATERIAL
-----------------------------------------------------------------------
Decision: a canonical rigid mesh remains geometry/topology identity and does
not add material ID to its hash merely to repair shading. Multiple skins and
runtime material overrides must continue sharing one immutable BLAS. The
