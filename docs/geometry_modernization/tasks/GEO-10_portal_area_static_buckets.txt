GEO-10 - Replace monolithic static traversal with portal-area buckets
====================================================================

GOAL
----
Build resident static BLAS buckets by portal area and bounded size, then place
only active buckets in the TLAS while preserving full static shading identity.

PRECONDITIONS
-------------
- Phase C gate passes.
- GEO-02 comm1 invariant is retained as a mandatory regression.
- New static route is default off and compare-capable.

IMPLEMENTATION STATUS
---------------------
Steps 1 through 5 are complete in shadow mode. Static world records now carry the
authoritative `_areaN` owner assigned by AddWorldModelEntities. The CPU-only
assignment planner uses world/area/split/source/storage identity, deterministic
ordering, bounded splitting, explicit fallback ownership, and exact duplicate,
unassigned, invalid-area, invalid-range, oversized, split, and key-collision
counters.

PathTraceCpuPlanningHarness passes the deterministic and failure cases.
geometry_geo187_auto accepts 589/589 surfaces and 22,558/22,558 primitives
across 14 active area buckets with every failure counter zero and a nonzero
world/source/storage generation tuple. geometry_geo189_auto and
geometry_geo190_auto then produce identical fresh-process assignment and
packed-content signatures while copying all 26,926 vertices, 67,674 indexes,
and 22,558 material/class/source-identity triangles into contiguous
bucket-local ranges with all six packing failure counters zero. Production
remains the monolithic static BLAS.

The step-4 source is now a separate cap-free full-map resident universe, not
the selected/pruned production cache. geometry_geo193_auto packs 1,789/1,789
surfaces and 50,108/50,108 triangles into 56 area buckets, uploads 8,846,672
bytes of vertex/index/class/material/identity storage once, and incrementally
builds all 56 bucket BLASes at two per frame. The selected-area mask marks only
3 buckets active and retains 53 inactive. No bucket enters the production TLAS;
the shadow planner blocks its route because shader support is deliberately
still false.

Step 5 derives one publication generation from the source, storage, material,
packed-content, and active-set identities. The active TLAS descriptors and
checked route records are constructed together and carry that same generation.
Publication fails closed until every active bucket BLAS is ready, if counts
differ, or if any generation is zero or mixed. geometry_geo194_auto observes
the expected empty publication while the three active BLASes converge, followed
by an exact atomic 3/3 publication. The live production TLAS remains
monolithic; these descriptors and route records are still shadow-only.

The shader-route ABI foundation is also complete in shadow mode. The audit
found that material IDs alone were insufficient because the primary producer
also consumes a table index per triangle. The packed route now publishes and
binds all six checked SRV streams: route records, vertices, indexes, triangle
classes, material IDs, and resolved material indexes. geometry_geo195_auto
reports zero missing active material indexes, successful GPU route upload, and
zero Vulkan binding errors. Live bucket instances are still excluded.

The first live-cutover foundation is now present without changing traversal.
Static buckets reserve the high 24-bit InstanceID range beginning at
0x00800000, leaving the established static/dynamic/rigid/skinned IDs unchanged.
The primary producer and clean-DI shared libraries receive an explicit route
count plus both 32-bit halves of the publication generation. Their common
loader rejects a wrong namespace, count, 48-byte record stride, generation,
packed range, 112-byte vertex stride, index topology, or material/class range.
The acceleration submit plan now separates retaining/building the monolithic
static BLAS from including instance 0 in the TLAS, so rollback ownership can
survive the eventual bucket-only submission.

geometry_geo197_auto accepts creation of the enlarged clean-DI constant buffer,
all six clean-DI route bindings, and the affected Vulkan pipelines. It settles
to the same exact 3/3 publication, builds all 56 resident BLASes, reports zero
binding/device/validation errors, and shuts down normally. Traversal remains
monolithic because actual primary/any-hit/spatial/GI hit reconstruction and
static-emissive identity have not moved. geometry_geo196_auto is rejected as an
early-terminated first-load diagnostic, not a runtime failure.

The primary-surface producer is now the first complete checked hit consumer.
Its triangle validation, material ID/class/table-index lookup, alpha/decal
texture and vertex-color interpolation, semantic liquid-card evidence,
any-hit support predicate, and closest-hit vertex reconstruction all recognize
the reserved bucket namespace. Every bucket access goes through the common
generation/range/topology loader before reading packed storage. Monolithic
static, dynamic, rigid, and skinned fallback behavior is unchanged. This code
is deliberately unreachable until the later all-consumer cutover gate admits
bucket instances to the production TLAS.

Standalone clean-DI spatial now consumes the same checked route tuple and six
packed SRVs already present in its binding set. Its receiver triangle
reconstruction, emissive replay geometry, live material-index recovery, and
shadow any-hit material lookup all fail closed through the common loader.
Both debug and production view-16 Vulkan variants build and deploy, while the
live TLAS remains monolithic.

Remix GI now mirrors the complete 512-byte clean-DI constants prefix instead
of placing its private tail over the final 32 bytes. Its independent layout
binds the six bucket streams at t100 through t105. Central hit-range,
material-ID/index, class, full-surface, compact-geometry, ray-query, any-hit,
and emissive replay consumers use one non-inlined checked route loader. Vulkan
uses only the split GI libraries; the two unused monolithic SPIR-V build
outputs were removed after the enlarged source exceeded their compiler ID
limit. All 32 runtime split libraries and both compute wrappers build and
deploy. Bucket traversal remains off.

The bucket-capable clean-DI libraries now use the same checked loader for live
material-table recovery, material ID/class lookup, full secondary-hit
attributes, primary-record barycentric recovery, and transmission UVs. This
covers initial and temporal debug/production, glass, and transmission. The
all-views sentinel is already at DXC's Vulkan ID ceiling: importing even the
smallest live bucket lookup overflows legalization. It therefore remains
byte-identical and explicitly does not advertise bucket capability. The later
cutover gate must reject bucket TLAS submission whenever that sentinel route
is selected, unless a compact bucket hit library is added first. This
restriction does not affect current production because bucket traversal is
still shadow-only.

Primary history and motion now classify a checked bucket InstanceID as static
world geometry. Bucket vertices are immutable world-space data, so their
previous position is the current hit position and the existing previous-camera
projection produces motion pixels and depth. This bypasses monolithic static
snapshot indexing without entering rigid/skinned object-motion arithmetic.
The legacy smoke library compiles the old contract byte-for-byte; only the
primary producer enables the bucket-motion predicate.

Current-frame bucket preparation now runs once after material-table completion
and before emissive construction, acceleration submission, binding creation,
and scene-input commit. One frame result owns the pack, resolved material
indexes, BLAS state, active publication, route upload result, and generation.
The later GEO-10 diagnostics read that result instead of rebuilding or patching
the already committed `m_sceneInputs`. The fresh local scene-input package now
receives the route count, generation, and validity before resource commit.
This closes the stale publication-order blocker while traversal remains
shadow-only.

The emissive-identity audit then rejected dense active-subset InstanceIDs:
adding or removing an earlier portal-area bucket could renumber a still-visible
bucket. Publication now assigns InstanceID from the stable resident-bucket
ordinal. The TLAS still contains only active buckets, while the checked route
table contains one record for every resident bucket. CPU validation accepts an
active TLAS count independently from the complete resident route count and
proves the route count remains complete when the active subset changes.

A shadow static-emissive builder now reads the exact current-frame packed
bucket ranges and emits only active-bucket records using resident InstanceID
plus bucket-local primitive index. Static/dynamic summaries recognize both
monolithic instance 0 and the reserved bucket namespace as static. The
one-shot GEO-10 audit reports monolithic/bucket counts plus zero-identity and
collision counts. Production emissive publication remains monolithic until the
same default-off gate switches traversal and emissive identity atomically.

`r_pathTracingGeometryStaticBucketRoute 1` is now that default-off gate. A
request never allocates resources or submits BLAS builds implicitly. Explicitly
enable the bucket resource and build gates after cold pipeline warmup; the live
route continues rendering monolithic until every resident bucket is ready.
Cutover additionally requires an exact current-frame publication, complete
resident route table, successful route upload, debug mode 0, clean DI enabled,
and clean-DI view 2 through 25. View 1 explicitly fails the gate because the
all-views sentinel could not compile bucket hit support. Acceptance uses the
same boolean to omit monolithic TLAS instance 0, append active bucket instances,
and replace monolithic static-emissive records with bucket-local records.
Setting the cvar back to 0 restores both monolithic contracts.

The CPU harness accepts the exact fully resident route and rejects unsupported
consumer, partial residency, incomplete route table, and default-off cases.
The Vulkan release build passes with all SPIR-V up to date. Live runtime proof
is still required before the route can be considered accepted.

`r_pathTracingGeometryStaticBucketAudit 1` is a one-shot shadow audit.
`r_pathTracingGeometryStaticBucketBlas 1` owns the full-map shadow resources,
and `r_pathTracingGeometryStaticBucketBlasBuild 1` submits bounded shadow
builds. All are default off and intentionally independent from the route
request. See artifacts/GEO-10_entry_audit.txt.

STEPS
-----
1. Define a static bucket key: world generation, portal area, size split, and
   source/storage generation. Define deterministic splitting and stable order.
2. Assign each static surface/primitive to exactly one bucket. Emit duplicate,
   unassigned, invalid-area, oversized, and split counters.
3. Build bucket geometry from GEO-06-style pooled full-fidelity ranges. Preserve
   local primitive -> material/triangle/source identity tables.
4. Build/reuse one BLAS per dirty bucket. Resident inactive buckets may keep
   storage and BLAS state, but must not be put in the active TLAS.
5. Derive one active-set generation from portal visibility. Use that same
   generation for TLAS instances and shader route tables; reject mixed epochs.
6. Coalesce tiny buckets deterministically if static TLAS entries exceed the
   declared budget. Never drop a bucket silently.
7. Compare old/new active static triangles, material IDs, sampled hit tuples,
   emissive inventory, and TLAS entries per area.
8. Run comm1 area 41 first. Record active/retained ranges plus the full GEO-01
   generation tuple. Then run STATIC_BUSY, portal transitions, PDA, and map
   changes.
9. Measure dirty bucket builds/reuse, active TLAS entries, upload bytes, scratch,
   retained memory, and timings with identical content.

GUARDRAILS
----------
- Do not use the old compile-time static cap as bucket admission policy.
- Do not include all resident inactive buckets just to make comm1 render.
- Do not delete the monolithic path until GEO-13.

DONE WHEN
---------
- Every static primitive has one bucket and correct shader identity.
- Only active buckets enter TLAS; generations match end-to-end.
- comm1 and all baselines render with zero silent loss.
- Old static route is a one-cvar rollback.
