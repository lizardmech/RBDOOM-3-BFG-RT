GEO-10 - Replace monolithic static traversal with portal-area buckets
====================================================================

GOAL
----
Build resident static BLAS buckets by portal area and bounded size, then place
only active buckets in the TLAS while preserving full static shading identity.

PRECONDITIONS
-------------
- Phase C gate passes.
- GEO-02 comm1 invariant is retained as a mandatory regression.
- New static route is default off and compare-capable.

ARCHITECTURE OVERRIDE - 2026-07-27
----------------------------------
Read `artifacts/GEO-10_architecture_pivot_2026-07-27.txt` before changing GEO-10
code. It supersedes the parallel t100-t105 route-record decoder, contribution
4/5, compact hit-library, and material hit-stage direction documented below.
The remainder of this ticket is retained as historical evidence unless the
pivot document explicitly preserves a contract.

The active direction keeps deterministic bucket assignment, resident BLASes,
active TLAS selection, and rollback, but binds the resident pool through the
existing static t3/t4/t5/t9/t11 slots. Bucket InstanceID encodes its global
triangle offset and uses contribution 0/1. Resident-pack caching is a
precondition for live traversal, not deferred performance cleanup.

Remix GI now mirrors the complete 512-byte clean-DI constants prefix instead

binds the six bucket streams at t100 through t105. Central hit-range,

The first attempt to import the checked decoder directly into every clean-DI
consumer compiled but caused repeatable Vulkan device removal even with the
route disabled. That integration is quarantined. Vulkan pipelines now append
separate compact bucket hit-only modules at SBT contributions 4/5 instead:
one for the core clean-DI payload, one for glass/transmission's extended
payload, and one for the clean-GI payload. Primary and spatial use the same
six-record contract. Default launch/save-load tests passed independently for
core DI, primary/spatial, material features, and GI with no device removal or
visual regression. The checked decoder is therefore available in every live
Vulkan ray-pipeline family without expanding the large raygen libraries.

Primary history and motion now classify a checked bucket InstanceID as static
world geometry. Bucket vertices are immutable world-space data, so their
previous position is the current hit position and the existing previous-camera
projection produces motion pixels and depth. This bypasses monolithic static
snapshot indexing without entering rigid/skinned object-motion arithmetic.
The legacy smoke library compiles the old contract byte-for-byte; only the
primary producer enables the bucket-motion predicate.

Current-frame bucket preparation now runs once after material-table completion
and before emissive construction, acceleration submission, binding creation,
and scene-input commit. One frame result owns the pack, resolved material
indexes, BLAS state, active publication, route upload result, and generation.
The later GEO-10 diagnostics read that result instead of rebuilding or patching
the already committed `m_sceneInputs`. The fresh local scene-input package now
receives the route count, generation, and validity before resource commit.
This closes the stale publication-order blocker while traversal remains
shadow-only.

The emissive-identity audit then rejected dense active-subset InstanceIDs:
adding or removing an earlier portal-area bucket could renumber a still-visible
bucket. Publication now assigns InstanceID from the stable resident-bucket
ordinal. The TLAS still contains only active buckets, while the checked route
table contains one record for every resident bucket. CPU validation accepts an
active TLAS count independently from the complete resident route count and
proves the route count remains complete when the active subset changes.

A shadow static-emissive builder now reads the exact current-frame packed
bucket ranges and emits only active-bucket records using resident InstanceID
plus bucket-local primitive index. Static/dynamic summaries recognize both
monolithic instance 0 and the reserved bucket namespace as static. The
one-shot GEO-10 audit reports monolithic/bucket counts plus zero-identity and
collision counts. Production emissive publication remains monolithic until the
same default-off gate switches traversal and emissive identity atomically.

STEPS
-----
1. Define a static bucket key: world generation, portal area, size split, and
   source/storage generation. Define deterministic splitting and stable order.
2. Assign each static surface/primitive to exactly one bucket. Emit duplicate,
   unassigned, invalid-area, oversized, and split counters.
3. Build bucket geometry from GEO-06-style pooled full-fidelity ranges. Preserve
   local primitive -> material/triangle/source identity tables.
4. Build/reuse one BLAS per dirty bucket. Resident inactive buckets may keep
   storage and BLAS state, but must not be put in the active TLAS.
5. Derive one active-set generation from portal visibility. Use that same
   generation for TLAS instances and shader route tables; reject mixed epochs.
6. Coalesce tiny buckets deterministically if static TLAS entries exceed the
   declared budget. Never drop a bucket silently.
7. Compare old/new active static triangles, material IDs, sampled hit tuples,
   emissive inventory, and TLAS entries per area.
8. Run comm1 area 41 first. Record active/retained ranges plus the full GEO-01
   generation tuple. Then run STATIC_BUSY, portal transitions, PDA, and map
   changes.
9. Measure dirty bucket builds/reuse, active TLAS entries, upload bytes, scratch,
   retained memory, and timings with identical content.

GUARDRAILS
----------
- Do not use the old compile-time static cap as bucket admission policy.
- Do not include all resident inactive buckets just to make comm1 render.
- Do not delete the monolithic path until GEO-13.

DONE WHEN
---------
- Every static primitive has one bucket and correct shader identity.
- Only active buckets enter TLAS; generations match end-to-end.
- comm1 and all baselines render with zero silent loss.
- Old static route is a one-cvar rollback.
