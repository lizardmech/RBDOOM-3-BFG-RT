GEO-11 - Enforce AS budgets, in-flight lifetimes, and safe compaction
====================================================================

GOAL
----
Make BLAS/TLAS work admission, scratch use, result-buffer lifetime, retirement,
and optional compaction explicit and safe under real frame overlap.

PRECONDITIONS
-------------
- GEO-10 static buckets are correct in compare mode.
- This ticket must not change geometry identity or shading semantics.

FILES TO AUDIT FIRST
--------------------
  neo/renderer/NVRHI/PathTraceAcceleration.cpp/.h
  neo/renderer/NVRHI/PathTraceAccelerationPlan.cpp/.h
  neo/renderer/NVRHI/PathTraceCpuWork.cpp/.h
  neo/renderer/NVRHI/PathTraceSmokeSceneBuild.cpp
  neo/renderer/NVRHI/PathTraceSceneInputs.h

STEPS
-----
1. Trace command-list submission, queue, frame slots, fences, TLAS instance
   buffer lifetime, AS result lifetime, scratch reuse, and deferred destruction.
2. Define build admission budgets for operation count and scratch/result bytes.
   Separate new builds, updates, periodic rebuilds, and compaction copies.
3. Prioritize correctness-critical active work; defer eligible background work
   with explicit reason/age counters. Never omit a live object silently.
4. Prove TLAS consumes only BLAS handles whose build/copy completed and whose
   buffers remain alive through the last referencing submission.
5. Prove TLAS result and instance buffers are double/triple-buffered or fenced
   against in-flight overwrite. Include frame-slot/generation diagnostics.
6. Audit NVRHI/Vulkan support for compacted-size query and AS copy. If supported,
   implement compaction as build -> query -> allocate -> copy -> completion ->
   handle publish -> old-handle retirement. If unsupported, record the result
   and leave compaction disabled; do not emulate unsafe swapping.
7. Stress spawn/despawn, portal churn, map restart, buffer growth, and forced low
   budgets. Deferred work must converge and failures must remain recoverable.
8. Re-run comm1 generation tuple, crowded skinned updates, and lifecycle removal.
9. Capture median/p90/max build/update/TLAS times, budget use, deferred ages,
   scratch high-water mark, result bytes, and compaction savings.

VALIDATION
----------
- Zero stale AS handle, in-flight overwrite, premature retirement, or silent
  omission counters under normal and forced-low-budget tests.
- Deferred active work has a visible safe fallback or preserves last valid AS.
- Compacted handle is never exposed before copy completion.

DONE WHEN
---------
AS work and memory have proved admission/lifetime contracts; compaction is
either safely implemented with measured benefit or explicitly rejected by the
current backend capability audit.

CHECKPOINT
----------
  pt geometry GEO-11: enforce AS budget and lifetime contracts

ENTRY AUDIT STATUS
------------------
Validated on 2026-07-29:

  docs/geometry_modernization/artifacts/GEO-11_entry_audit.txt

The audit narrows the first implementation to measured result-memory census
followed by exact event-query retirement of GEO-10 bucket BLASes and buffers.
NVRHI already versions Vulkan scratch and CPU TLAS-instance uploads by command
buffer. Exact scratch requirements are not exposed to the application.

Compaction is explicitly unsupported in the active build:

  NVRHI_WITH_RTXMU = OFF

The Vulkan `compactBottomLevelAccelStructs` implementation is a no-op in that
configuration. Do not set `AllowCompaction` or emulate a handle swap. Enabling
RTXMU requires a separate backend/build audit.

IMPLEMENTATION STATUS

  - one-shot NVRHI BLAS result-memory census;
  - event-query retirement for replaced/removed bucket BLASes;
  - event-query retirement for replaced/removed bucket GPU buffers;
  - event-query retirement for older and canonical rigid BLASes;
  - event-query retirement for older rigid vertex/index buffers;
  - event-query retirement for canonical pool buffer generations and the

----------------------------

view-16 device removal before the requested rigid off/on transition. Bounded
controls produced these results:

  canonical rigid BLAS disabled                 device removal
  clean DI light mode 0                         device removal
  GPU idle on every portal/scene transition     device removal
  identical camera/content in clean DI view 12  stable

that its RGB analytic-light payload is the cause. Shared scene capture,

Stage 3 survived. Source decode, secondary traversal, closest-hit payload, and

publication path found one material-generation violation:

  - resolved-surface construction already loads the current material, applies
    its dynamic record, and stores final emissive radiance in `RAB_Surface`;

    crossed the material namespace that grew 407 -> 425 at the crash trigger.

already-resolved `surface.material.emissiveRadiance`. It no longer re-enters
the dynamic-material namespace during publication. This removes duplicated
decode, preserves the authoritative resolved-surface contract, and matches the
one-record/one-decode reference shape.
