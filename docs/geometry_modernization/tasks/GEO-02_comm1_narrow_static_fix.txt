REJECTED GENERATION CANDIDATE
-----------------------------
The persistent geometry universe now publishes a topology-only
`staticGeometryGeneration`. Material-only refreshes advance the already
separate material generation but no longer claim that BLAS input geometry
changed.

The committed static BLAS records the topology generation it was built from.
With:

  r_pathTracingStaticBlasGenerationGuard 1

cache acceptance requires the committed and current topology generations to
match. A mismatch performs a normal full static upload/build once, then
returns to cache reuse. Set the cvar to 0 for the exact legacy
hash/dirty-flag-only A/B path. The every-frame force-rebuild diagnostic remains
independent and should stay 0.

A reused BLAS retains its original committed generation even while the guard
is disabled. This is required so that switching the guard back on can detect
and repair a stale legacy-path BLAS instead of laundering it as current. Each
guard invalidation prints one:

  PT static BLAS generation guard invalidated cache

The static one-shot tuple now prints:

  staticGen(cache/current/mismatch/guard)

This makes the repaired invariant directly observable.

ROOT CAUSE AND NARROW FIX
-------------------------
Runtime texture-matrix evaluation makes a per-frame copy of static vertices.
The upload selector previously chose the texture-matrix first/last vertex span
whenever any such vertices existed. That partial span took precedence even
when the static cache missed and buffer growth/recreation required complete
initialization. The index path still performed its full cache-miss upload,
which exactly explains the GEO-11 zero-vertex / correct-index split.

The fix gate is:

  r_pathTracingStaticVertexFullUploadOnCacheMiss 0  legacy partial-span path
  r_pathTracingStaticVertexFullUploadOnCacheMiss 1  corrected path

It defaults off until the runtime A/B passes. With the gate on:

  - cache hit, no texture matrices: skip unchanged static vertices;
  - cache hit, texture matrices: upload only their bounded span;
  - cache miss plus texture matrices: upload the complete static vertex buffer;
  - cache miss without texture matrices: keep the existing valid dirty-range
    optimization or full-upload fallback;
  - diagnostic mode 2: continue skipping uploads exactly as requested.

The selection is now a pure CPU plan with harness coverage for cache hit,
cache miss, dirty range, disjoint texture-matrix range, the gated legacy path,
and mode 2.

GEO-09 REJECTION
----------------
The runtime result rejected the generation guard as a fix. It rebuilt at every
observed static-generation transition, yet the later generation-matched BLAS
still missed retained brush geometry and enabling the guard did not restore
it. The guard now defaults off and the ticket remains open.

The next diagnostic changes `r_pathTracingStaticBlasForceRebuild` from a
boolean interpretation to:

  0  reuse the cached BLAS
  1  normal static cache-miss upload policy plus BLAS rebuild
  2  BLAS rebuild from the existing GPU buffers with no static upload

This resolves the previously conflated GPU-buffer-versus-BLAS boundary before
another permanent fix is attempted.

STEPS
-----
1. Restate the failed invariant as one sentence and one tuple comparison.
2. Identify the smallest owner that can restore that invariant. Prefer fixing
   generation/identity/range propagation at its source over compensating in
   several consumers.
3. Add a default-off fix gate if the correction changes live routing or buffer
   selection. Keep the exact old path selectable for A/B.
4. Patch only the localized boundary. Do not introduce area buckets, pooled
   geometry, registry cutover, or raised caps in this ticket.
5. Retain the GEO-01 counter and make the repaired invariant assertable in a
   development build.
6. Run old/fix A/B in the same comm1 position. The old path must reproduce the
   mismatch and the new path must remove it.
7. Run `STATIC_BUSY`, `SKINNED_CROWD_CPU`, and `LIFECYCLE_MEDKIT`. Confirm no
   static, rigid, skinned, transient, material, or TLAS count regresses.
8. Confirm raster output remains functional with both gate settings.
9. For shader changes, follow the targeted SPIR-V deletion/mtime rule. Never
   build or deploy DXIL.
