GEO-07 - Make jointCache GPU skinning authoritative
==================================================

GOAL
----
For eligible true-deforming MD5 surfaces, consume renderer-authoritative joint
state on the GPU, write per-instance current/previous geometry, and skip CPU
pre-skinning while retaining an explicit CPU fallback.

PRECONDITIONS
-------------
- GEO-03 readback parity and failure funnel pass.
- GEO-06 supplies full-fidelity immutable source records.
- New live behavior is behind one default-off master gate.

--------------------
  neo/renderer/NVRHI/PathTraceSkinning.cpp/.h

STEPS
-----
1. Trace `jointCache` production, allocation, update, command-list ownership,
   lifetime, format, joint base offset, and current/previous availability. Do not
   create a parallel pose evaluator if renderer joint data is usable.
2. Decide direct joint-buffer binding versus a staged compact joint array from
   measured binding/lifetime constraints. Record the reason in the decision
   register before implementation.
3. Define a per-instance skinning job: immutable source ranges, joint range,
   vertex output range, previous output range, surface identity, and status.
4. Establish a proven immutable skinned bind-source record before allocating
   outputs. The accepted GEO-06 registry currently admits only
   RegisteredRenderModel + Rigid and deliberately treats SkinnedBindSource as
   a negative control. Then allocate mutable outputs by the full canonical
   InstanceKey, never by shared MeshKey. Two zombies sharing one MD5 source
   must have distinct output ranges.
5. Schedule skinning after authoritative joint writes and before BLAS update on
   the same queue/command-list dependency chain.
6. Route each candidate through the GEO-03 funnel. Only `dispatchedGpu` may skip
   CPU pre-skinning; every other result uses the named CPU fallback or explicit
   single-bone route.
7. Keep single-bone optimization conditional on proven rigid transform and
   identical material/motion semantics. Otherwise use normal GPU skinning.
8. Preserve current and previous positions. On first observation, teleport, or
   invalid history, mark history invalid rather than fabricating motion. Key
   previous outputs to the GEO-04 logical view/history owner; never consume the
   global last-3D-view bridge as authoritative history.
9. Re-run same-frame CPU/GPU readback for all GEO-03 probes and crowded clones.
10. Measure CPU skin time, source upload, joint upload, output bytes, and GPU
    skin dispatch time on identical geometry counts.

GUARDRAILS
----------
- No per-model pose sharing in the first cut.
- No silent fallback and no T-pose sentinel output.
- Do not promote the new outputs into live BLAS traversal here; GEO-08 owns it.
- Fatzombie texture failure is not a skinning failure if its geometry compares.

DONE WHEN
---------
- Every eligible surface has exact GPU/fallback accounting.
- GPU current/previous outputs meet GEO-03 tolerance.
- Eligible surfaces no longer execute CPU pre-skinning under the gate.
- Gate off restores the previous CPU path.
