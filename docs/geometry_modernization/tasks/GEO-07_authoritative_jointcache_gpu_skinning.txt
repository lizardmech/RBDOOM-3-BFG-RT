GEO-07 - Make jointCache GPU skinning authoritative
==================================================

GOAL
----
For eligible true-deforming MD5 surfaces, consume renderer-authoritative joint
state on the GPU and write validated per-instance current/previous geometry.
Hand the proven producer and exact failure classification to GEO-08, where live
BLAS traversal and CPU pre-skin removal must cut over together.

PRECONDITIONS
-------------
- GEO-03 readback parity and failure funnel pass.
- GEO-06 supplies full-fidelity immutable source records.
- New live behavior is behind one default-off master gate.

STEPS
-----
1. Trace `jointCache` production, allocation, update, command-list ownership,
   lifetime, format, joint base offset, and current/previous availability. Do not
   create a parallel pose evaluator if renderer joint data is usable.
2. Decide direct joint-buffer binding versus a staged compact joint array from
   measured binding/lifetime constraints. Record the reason in the decision
   register before implementation.
3. Define a per-instance skinning job: immutable source ranges, joint range,
   vertex output range, previous output range, surface identity, and status.
4. Use the accepted slice-5A immutable skinned bind-source record and the
   accepted slice-5B full-InstanceKey mutable-output allocator. The source
   producer is the MD5 load-time deformInfo bind geometry, admitted only after
   exact model-surface count/topology validation and value-copy into the source
   registry. Mutable ranges are keyed by full canonical InstanceKey, never by
   shared MeshKey; removal and storage-generation retirement are explicit.
   Two zombies sharing one MD5 source must retain distinct output ranges.
5. Use the accepted slice-5C mode-1 comparison route: pack each exact
   value-owned source once per unique MeshKey/checksum, bind distinct
   full-InstanceKey output offsets, and schedule skinning after authoritative
   joint writes on the same command-list chain. CPU pre-skinning and live BLAS
   inputs remain unchanged in GEO-07.
6. Route each candidate through the GEO-03 funnel and export the exact
   eligibility/result needed by GEO-08. `dispatchedGpu` is necessary but is not
   by itself permission to skip CPU capture: until a BLAS consumes the new
   output, the merged dynamic BLAS still depends on CPU-skinned vertices.
7. Keep single-bone optimization conditional on proven rigid transform and
   identical material/motion semantics. Otherwise use normal GPU skinning.
8. Preserve current and previous positions. On first observation, teleport, or
   invalid history, mark history invalid rather than fabricating motion. Key
   previous outputs to the GEO-04 logical view/history owner; never consume the
   global last-3D-view bridge as authoritative history.
9. Re-run same-frame CPU/GPU readback for all GEO-03 probes and crowded clones.
10. Measure source upload, joint upload, output bytes, and GPU skin dispatch
    time on identical geometry counts. Retain the measured CPU skin baseline
    for the GEO-08 cutover A/B.

GUARDRAILS
----------
- No per-model pose sharing in the first cut.
- No silent fallback and no T-pose sentinel output.
- Do not promote the new outputs into live BLAS traversal here; GEO-08 owns it.
- Do not claim CPU pre-skin removal while the merged dynamic BLAS consumes the
  CPU-produced dynamic vertex stream.
- Fatzombie texture failure is not a skinning failure if its geometry compares.

DONE WHEN
---------
- Every eligible surface has exact GPU/fallback accounting.
- GPU current/previous outputs meet GEO-03 tolerance.
- Shared sources and distinct full-InstanceKey outputs pass runtime proof.
- Gate off restores the previous comparison path.

CPU pre-skin removal remains a Phase C acceptance condition, but the live
cutover is completed in GEO-08 after per-instance BLAS/TLAS parity passes.

CHECKPOINT

Q7 SINGLE-BONE POLICY CLOSURE
-----------------------------
The proposed per-joint rigid promotion is not part of the accepted first cut.
`IsEntityFeedSingleBoneSurface` remains a conservative classifier and the
entity-feed census retains its separate `RigidSkinned` count, but production
continues to process these surfaces through authoritative GPU skinning and
per-instance skinned BLASes.

The representative 359-surface census reports 62 single-bone observations but
only 4,042 of 135,849 vertices (2.98 percent). Accepted runtime captures
explicitly dispatched single-bone chair and head surfaces with zero funnel
failures and exact sampled current/previous/motion parity. No same-content GPU
profile isolates a material cost for this subset.

A future optimization must not infer promotion from the current boolean alone.
It must export a range-validated controlling joint index from the immutable
source, prove current and previous composed object/joint transforms under the
HistoryOwner contract, and measure the isolated skin-dispatch and BLAS benefit
before changing TLAS admission. See D188 and:

  ../artifacts/GEO-07_q7_single_bone_route_audit_2026-07-30.txt
