GEO-08 - Build and update one BLAS per skinned instance
======================================================

GOAL
----
Replace the frame-merged skinned BLAS for eligible geometry with per-instance
BLAS state updated from GEO-07 outputs and periodically rebuilt under an
observable policy.

PRECONDITIONS
-------------
- GEO-07 GPU current/previous output is numerically correct and every candidate
  has exact source, output, joint, dispatch, and failure accounting.
- CPU fallback surfaces remain on the legacy route.

STEPS
-----
1. Freeze the cutover contract before implementation:
   - the accepted output buffer stores world-space PathTraceSmokeVertex records,
     so the first TLAS transform is identity;
   - BLAS vertexOffset is the full-InstanceKey output byte offset;
   - BLAS indexOffset/count comes from the exact canonical source GPU-pool
     record, whose indexes remain local to that source surface;
   - compute dispatch, UAV-to-AS barrier, BLAS build/update, and TLAS build are
     ordered on the same command-list chain;
   - output storage generation, source checksum/generation, and BLAS generation
     must agree before submission.
2. Define a pure per-instance AS state machine and harness: absent,
   build-pending, ready, update-pending, rebuild-pending, failed, and retiring.
   Give every transition and rejection a counter. Never key AS state by shared
   MeshKey.
3. ACCEPTED FOR SHADOW USE, EXPLICIT COMPLETION, AND PHYSICAL GROWTH. Make physical output-buffer generations follow the accepted allocator.
   Growth creates a new buffer and retires the old buffer plus every BLAS that
   references it. Initial generation identity and physical AS-input capability
   pass in geometry_geo64_auto. Retired packages require exact
   gpu-event-query completion. geometry_geo71_auto proves generation-1
   replacement ownership and release during a real growth event.
4. ACCEPTED FOR INITIAL COMPARISON BUILDS. Create one updateable BLAS per eligible SkinnedSurface InstanceKey using
   AllowUpdate + PreferFastBuild. Keep source mesh identity, mutable output
   identity, and AS identity separate.
5. ACCEPTED. Schedule initial build or update only after that instance's skin dispatch.
   Use PerformUpdate only when topology, source record, output buffer and range,
   and AS generation are unchanged. Otherwise rebuild. Start with a fixed,
   observable full-rebuild cadence. Stable PerformUpdate and cadence rebuild
   pass in geometry_geo68_auto; exact removal and completion-owned replacement
   pass in geometry_geo69_auto and geometry_geo71_auto.
6. ACCEPTED THROUGH GPU TRANSPORT, ALL CONSUMERS, COMPACT CLEAN-DI/CLEAN-GI
   HIT LIBRARIES, AND BOUNDED RUNTIME PIPELINE CREATION. Define the
   shader hit-routing contract before adding TLAS instances.
   Prove canonical instance ID, primitive-to-source-triangle lookup, material
   table lookup, current/previous position lookup, and emissive identity for a
   per-surface skinned BLAS. Do not reuse the merged-dynamic instance-ID meaning
   accidentally. PathTraceSkinnedHitRoute and geometry_geo72_auto accept the
   source-local CPU plan. Step 6B1 adds the exact 80-byte route / 36-byte
   triangle ABI, persistent t18/t19 bindings, empty sentinels, scene-package
   lifetime ownership, and byte-exact GPU readback. geometry_geo73_auto and
   geometry_geo74_auto pass 12-route / 15,962-triangle transport with all
   comparison BLASes excluded from the TLAS. Step 6B2 now binds canonical
   source indexes at t28, current world-space output vertices at t29, and
   previous world-space positions at t32. Primary/shadow, transmission,
   spatial, ReGIR/NEE debug, material, class, UV/color, and motion consumers
   compile with explicit disjoint rigid/skinned handling. The clean-DI
   sentinel and clean-GI libraries remain lightweight because their unchanged
   baseline SPIR-V is already 5,929,604 and 9,385,432 bytes respectively;
   adding full skinned reconstruction makes DXC fail with SPIR-V ID overflow.
   Both oversized libraries receive the bindings but compile out skinned hit
   reconstruction. Step 6B3 adds a 17,196-byte clean-DI skinned-hit library
   with four exports and appends its primary/shadow groups at SBT slots 2/3.
   `spirv-val`, disassembly, and the release build pass; the existing sentinel
   blob remains byte-identical. Step 6B4 adds the equivalent clean-GI module:
   172,820 bytes, four exports, exact GI payload/alpha/translucency/liquid-pool
   candidate handling, and verified b2 offsets 144/464/516/672/684/688.
   Debug and production GI pipelines append its primary/shadow groups at SBT
   slots 2/3; both monolithic GI blobs remain byte-identical. No skinned
   comparison BLAS may enter a TLAS. The exact SBT contribution planner and
   harness now pass, but the first eager mixed-library user run failed by
   starving Windows input during GI pipeline construction. The replacement
   partitions all sixteen GI raygens at source level, validates 32/32 Vulkan
   blobs with exact seven-entry inventories, warms one pipeline at a time with
   a fifteen-frame gap, and uses one yielding deferred-host-operation joiner.
   This mitigation is offline-only until a bounded user run reaches 16/16
   initialization without system input loss.
7. ACCEPTED. Add comparison TLAS routing while the merged dynamic BLAS remains live.
   Record instance/primitive totals, sampled hit identities, bounds,
   material/triangle IDs, and motion inputs. A compare failure must select only
   the legacy route.
8. ACCEPTED. Split capture only after comparison passes. GPU-eligible skinned surfaces
   stop appending CPU-skinned vertices/indexes to the merged dynamic BLAS, while
   particles, callbacks, unsupported layouts, and other named failures remain
   there. Source topology, not bind-pose positions, supplies index validity;
   posed zero-area filtering must not silently change primitive identity.
9. ACCEPTED. Make failure timing explicit:
   - structural ineligibility is decided before the CPU capture split and uses
     same-frame CPU fallback;
   - a late command-recording/resource failure after CPU work was skipped uses
     a validated prior-pose hold or suppresses that instance for the frame;
   - never leave bind-pose or zero sentinel vertices traversable;
   - do not describe a late failure as CPU fallback unless CPU vertices were
     actually produced.
10. ACCEPTED. Handle spawn, despawn, offscreen/return, PDA, map teardown, and
    buffer growth. Retire AS resources only after their last in-flight TLAS
    use. geometry_geo113_auto, geometry_geo115_auto, and the rebuilt
    geometry_geo116_auto close these cases with exact event-query retirement,
    forced cache eviction, and cold map-reload admission.
11. ACCEPTED. Validate 13 Fatzombie/clone instances: one source mesh record per
    unique surface, distinct mutable output/BLAS per live instance.
    geometry_geo122_auto crosses the old 196,608-index merged cap and remains
    at 23 omitted routes / 43,439 vertices / 216,054 indexes for 173 logged
    frames. geometry_geo123_auto records 11 immutable sources shared by 23
    surfaces, 78/78 shared-source pairs with non-aliased mutable ranges, zero
    overlaps, 23 exact dispatch/output/BLAS owners, and TLAS IDs 113..135 with
    every admission failure bucket zero.
12. Measure CPU skin time, BLAS build/update/reuse time and counts with
    identical animated geometry. Report merged legacy rebuild cost separately.

VALIDATION
----------
- Per-instance update count equals eligible live skinned BLAS count.
- No duplicate/missing TLAS instance IDs and no stale buffer generation.
- Periodic rebuild is bounded and visible.
- Eligible routed surfaces perform no full CPU vertex skin/copy.
- Every remaining CPU-skinned surface has a named ineligibility/failure reason.
- Late-failure policy cannot expose bind pose, zero sentinels, or stale storage.
- Gate off returns to the merged BLAS with identical visible geometry.

DONE WHEN
---------
Eligible skinned instances traverse their own updateable BLASes with exact state
accounting, safe retirement, and legacy comparison proof. Their full CPU
pre-skin/copy is absent under the gate; ineligible surfaces retain explicit CPU
fallback and gate-off restores the original merged route.
