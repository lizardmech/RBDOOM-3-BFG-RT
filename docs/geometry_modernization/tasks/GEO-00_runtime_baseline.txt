tickets can compare without requesting another broad manual dump.

STEPS

1. Inventory the existing geometry diagnostic commands, labels, cvars, and log
   records. Map each required evidence field to an existing producer.
2. Define four durable scenario IDs:

     STATIC_BUSY
     SKINNED_CROWD_CPU
     COMM1_AREA41_BROKEN_PT

3. Add a small repository artifact manifest or bounded capture helper only if

4. Record the accepted 2026-07-23 baseline values in a machine-diffable text or

5. Add a one-command or short console checklist for capturing each scenario.
   If a savegame/position is required, name it and record the portal area check.

7. Confirm the GPU mode captures are coverage-only. Do not record them as a

   should be touched by this ticket.
9. Capture one bounded rerun when possible. If the original scene cannot be
   rerun without user input, validate the schema against the existing log and
   explicitly mark the runtime refresh pending; do not invent values.

For every scenario: map, area, label, frame, visible/static/retained counts,
rigid mesh/instance counts, skinned surfaces/vertices/indices/triangles,
transient counts, cap/overflow/invalid/fallback counts, TLAS instances, upload
bytes, and total/capture/CPU-skin timing sample count.

- Do not copy the multi-megabyte external log into git without a stated reason.
- No screenshot-only baseline and no unlabeled performance number.
